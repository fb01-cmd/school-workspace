2026-08-19 Claude(Fable) 작성. 로드맵 Phase 8 단계별 계획(2026-08-09 확정)의 3단계 본체. 변수 4개 최종 확정(2026-08-19: 복직 2027-03·활동 지속·현장 협력자 有·쿨메신저 계약 2026-12월 말)으로 착수 관문 해제. **목표 상태 = 12월 말 쿨메신저 갱신 판단 전, "시연 가능한 업무 지시"**.

상위·인접 문서: [`memo_spec.md`](./memo_spec.md)(발송·수신자 확장·푸시), [`memo_attachment_spec.md`](./memo_attachment_spec.md)(첨부 검증 전례), [`notification_center_spec.md`](./notification_center_spec.md)(수락 창구 — 업무 수락은 설계 예약된 첫 용례).

## §0 배경·확정 전제 (전부 기존 결정 — 재론 금지 목록)

1. **문제**: 쿨메신저는 메시지와 업무 상태가 분리돼 "놓친 업무 없나" 메신저를 뒤적이는 구조. 대체 가치의 승부처는 보드가 아니라 **발신자 화면의 사람별 수락/완료 실시간 현황**(재촉 대상 즉시 파악)과 **제출물 취합 고통 제거**(파일명 난장판·미제출 파악)다.
2. **상태 단일 원본 = 플랫폼.** 캘린더는 4단계의 단방향 출력 채널(이 스펙 범위 밖), 구글 Tasks 동기화는 제외 확정.
3. **파일 흐름 = "사본 수수"**: 수신자는 Drive를 보지 않는다 — 플랫폼에서 양식 내려받기 → 로컬 한글 작성 → 플랫폼에 제출 업로드(쿨메신저 감각).
4. **저장소 = 업무 전용 공유드라이브 신설**(조직 소유). 명단 시트용 공유드라이브 재사용 금지(권한 규칙 혼합 = 제출물 개인정보 유출 구멍). 폴더는 플랫폼 자동 생성 창고 `업무/{연도}/{업무ID}/양식|제출함/` — **접근 권한 = 서비스 계정만**, 예외 1: 담당자(발신자)에게 그 업무 제출함 열람 자동 부여(통째 내려받기 취합).
5. 파일 수 = 양식 수 + 제출 인원수(다운로드는 로컬로만, Drive 사본 없음). **재제출 = 최신본 교체**, 이전 본은 Drive 버전 이력(30일)뿐 — 재제출 UI에 "이전 제출본은 교체되며 30일 후 복구할 수 없습니다" 경고(2026-08-09 사용자 확정).
6. **자동 독촉 금지**(「시스템은 정보 전달까지만」 — 알림 센터 결정 ⓓ에서 못박음). 기한 임박을 **본인에게** 알리는 것과 발신자가 **직접 누르는** 재촉은 허용(당사자 행위).
7. 인간 생성 데이터 — 용량 판정 '하' 유지(capacity review). 쓰기 수백/일, 좁은 구독.

## §1 범위

**포함**: 업무 생성·발송(확인형/제출형) · 수신자별 상태 머신 · 내 할 일 목록 · 발신자 현황판 · 제출함(공유드라이브·파일명 정규화) · 알림(발송·수락 창구·기한 임박·수동 재촉) · 보존·파기.
**명시적 제외**: 캘린더 출력(4단계) · 자동 반복 독촉(§0-6) · 대리 지정/재배정 위임(조율은 사람 일 — 발신자가 대상을 추가·제거하는 것으로 갈음) · 학생 대상 업무(교직원 전용) · HWP 뷰어(후속 연계 — 제출함 검토용 1차 자리라는 로드맵 예약만 유지) · 반복 업무 템플릿(실수요 후).

## §2 데이터 모델 — `tasks/{domain}/items/{taskId}` (신설 컬렉션)

쪽지 문서 재사용이 아니라 별도 컬렉션이다 — 수신자별 상태 머신·제출물 참조가 쪽지 모델과 구조적으로 다르고, 쪽지의 회수·별표·스레드 의미론을 상속하면 오히려 얽힌다. 단 **발송 파이프라인(수신자 확장·검증·푸시)은 memo 인프라를 재사용**한다.

| 필드 | 타입 | 설명 |
|---|---|---|
| senderEmail·senderName | string | 발신자(담당자) — memo와 동일 규약 |
| title | string | 업무명 ≤200자 |
| body | string | 지시 내용 ≤10,000자. `contentFormat?: "md1"` 서식 승계(richtext 재사용) |
| kind | `"confirm"` \| `"submit"` | 확인형(완료 체크만) / 제출형(파일 제출 = 완료) |
| dueAt | number | 기한(ms, KST 날짜+시각). 필수 |
| recipientEmails·recipientCount·recipientSummary | — | memo §1 규약 그대로(서버 확장·검증) |
| statuses | map<email, {state, at, note?}> | **수신자별 상태의 단일 원본** (§3). 키에 점 — FieldPath 필수(memo reads 전례) |
| formFiles | {driveFileId, name, mimeType, size}[] | 양식 파일 참조 ≤5 (실체는 공유드라이브 `양식/`) |
| submissions | map<email, {driveFileId, name, size, at, version}> | 제출형 전용 — 사람당 1개(재제출 = 교체, version 증가) |
| submitFolderId | string? | 제출형 전용 — 이 업무의 제출함 폴더 id |
| createdAt·expireAt | number | 보존·파기 기준(§8) |
| canceledAt? | number | 발신자 철회(§3) — 쪽지 회수 대응물 |

- 읽기 = 클라이언트 직독 + firestore.rules(발신자·수신자만 — memo §3 규칙 패턴 승계, 쓰기는 API 전용). 색인: 수신자별 "내 할 일" 쿼리와 발신자 "내가 낸 업무" 쿼리에 필요한 최소 2개(구현 시 memo 색인 전례 따름).

## §3 상태 머신 (수신자별 — 미뤄둔 결정 ①의 확정)

```
PENDING(도달) → ACCEPTED(수락) → DONE(완료)
      ↘ DECLINED(거절, 사유 필수)     [제출형은 제출 성공이 곧 DONE]
```

- **거절에는 사유가 필수다** — 발신자에게 알림. 거절 후 처리는 사람 일(발신자가 대상에서 제거하거나, 대화로 해결 후 발신자가 되돌림 요청 → 수신자가 다시 수락). 시스템은 상태와 사유를 전달할 뿐 중재하지 않는다.
- DONE 취소(완료 체크 해제)는 본인만, 기한 후에도 가능(실수 정정) — 이력은 statuses.at 갱신으로 남는다.
- **발신자 철회(cancel)**: 업무 전체를 닫는다 — 수신자 할 일 목록에서 사라지고 현황판에 "철회됨" 표기. 제출물은 보존(§8 파기까지) — 이미 낸 노동을 지우지 않는다.
- 상태 전이 판정은 순수 함수 `applyTaskTransition(task, email, action)` 단일 소재지 — 셀프테스트 대상(§10).

## §4 발신 자격 (미뤄둔 결정 ②의 확정)

**조직도 등록 교직원 전원 발신 가능** — 쪽지와 동일 자격(부장 이상 제한 안 함). 근거: ⓐ 쿨메신저도 발신 제한이 없고 실무 남용은 조직 규율이 다룬다 ⓑ 직책 기반 제한은 조직도에 직책 체계 데이터를 요구해 범위가 커진다 ⓒ 기관 채택 모델 — 제한이 필요해지면 실무협의회 요구로 좁히는 편이 순서다. 수신 대상 선택은 쪽지 v1.1 조직도 동선 재사용.

## §5 제출형 업무 — 제출함·파일명 정규화 (킬러 기능)

1. **공유드라이브 프로비저닝**: 최초 1회 "업무 제출함" 공유드라이브 생성(서비스 계정 관리) + `platform_config`에 id 저장. 업무 생성 시 `업무/{연도}/{업무ID}/양식/`·`제출함/` 폴더 자동 생성. 담당자에게 제출함 폴더 열람 권한 자동 부여(§0-4 예외), 업무 철회·파기 시 회수.
2. **양식 배포**: 발신자가 양식 업로드(HWP 등 일반 파일 — 이미지 화이트리스트가 아니라 **업무 양식 화이트리스트**: hwp·hwpx·doc·docx·xls·xlsx·pdf·zip + 이미지. 실행 파일류 차단, 바이트 서명은 판별 가능한 형식만·나머지는 확장자+크기). 수신자는 플랫폼에서 내려받는다(프록시 GET — 인라인 이미지 프록시 전례 §13 패턴, 자격 = 그 업무의 발신·수신자).
3. **제출**: 수신자가 파일 업로드 → 서버가 검증 후 제출함에 저장하며 **파일명 자동 정규화**: `{소속}_{이름}_{업무명}.{원본 확장자}` — 소속 = 담임이면 "N학년M반", 아니면 조직도 첫 부서, 그것도 없으면 생략. (로드맵 예시 "2학년3반_홍길동_양식명.hwp"의 일반화. 정규화는 순수 함수 — 셀프테스트.) 제출 성공 = DONE 전이 원자 처리.
4. **크기 한도 = 10MB/파일**: Vercel 본문 4.5MB 한도 때문에 4MB 초과분은 **Drive 재개 업로드 세션(resumable session URL)을 서버가 발급하고 브라우저가 Drive로 직접 업로드**하는 2경로제 — ≤4MB는 서버 경유(간단·검증 용이), 초과는 세션 경로(업로드 후 서버가 메타 검증·이동). 세션 경로는 코어 구현 시 실측 1회 선행(2026-08-09 재검토 ②의 해소 지점). HWP 실무 대부분이 수 MB라 10MB로 충분, 초과는 눈높이 안내.
5. **취합**: 담당자는 현황판에서 제출물 개별 내려받기 + "제출함 폴더 열기"(권한 부여된 Drive 폴더 — 통째 다운로드는 Drive가 제공). 플랫폼이 zip을 만들지 않는다(비용·복잡도 대비 Drive 기능으로 충분).

## §6 알림 (미뤄둔 결정 ③·④의 확정 — 피로 설계)

| 사건 | 수신자 | 채널 |
|---|---|---|
| 업무 발송 | 대상 전원 | 웹 푸시(제목만 — memo 전례) + 알림 센터 원장 |
| 수락/거절/완료/제출 | 발신자 | 알림 센터 원장만 (푸시 없음 — N명 업무에서 푸시 N건은 피로. 현황판이 실시간 원본) |
| 기한 임박 (D-1 아침) | **미완료 수신자 본인** | 웹 푸시 + 알림 센터 — daily-sync 크론에 통합(Hobby 2개 한도 준수). 본인 리마인드라 §0-6 정합. 1회만(반복 없음) |
| 수동 재촉 | 발신자가 지정한 미완료자 | 웹 푸시 — **업무당 24시간에 1회** 서버 제한(연타 방지). 당사자 행위라 허용 |
| 철회 | 대상 전원 | 알림 센터 원장만 |

- **수락은 알림 센터 [수락] 버튼에서 바로** — notification_center_spec §설계 예약("업무 배분 수락"이 첫 용례)의 이행. 양해 수락 창구와 같은 패턴(원장 항목에 액션 버튼 → 서버 전이 → 배지 갱신).

## §7 화면 IA (Antigravity 인계 — 구현은 코어 뒤)

- **업무 보내기**: 쪽지 쓰기와 한 자리(쪽지 화면에 "업무로 보내기" 전환 또는 별도 버튼 — IA 상세는 코어 후 지시서에서). 업무명·기한(날짜+시각)·확인형/제출형·양식 첨부·지시 내용(서식 재사용)·수신자(조직도 동선).
- **내 할 일**: 받은 업무 목록 — 기한순, 상태 칩(할 일/완료/거절), 확인형은 [완료] 체크, 제출형은 [양식 내려받기]·[제출하기]. `/m`은 열람+완료 체크·제출까지(폰에서 파일 제출은 사진 제출 실수요 — 허용).
- **보낸 업무 현황판** (승부처): 업무별 — 수신자 표(이름·상태·시각·제출물), 집계 칩(수락 n/전체 · 완료 n/전체), [재촉] 버튼(미완료자 일괄, 24h 제한 표시), [제출함 폴더 열기], [철회].
- 대시보드 건수 카드에 "내 할 일 N건" 추가(기존 건수 카드 패턴 — 5분 캐시 1회 집계 재사용).
- UI 문구 눈높이: "업무", "할 일", "제출" — 상태 머신·전이 같은 용어 금지.

## §8 보존·개인정보·파기

- 보존 기본 365일(`settings.taskRetentionDays`, 쪽지 전례) — expireAt 스탬프, **daily-sync 파기 크론이 문서와 공유드라이브 폴더(양식·제출물)를 함께 삭제**(첨부 크론 전례). 연도 폴더가 비면 정리.
- **개인정보 인벤토리 등재 필수(코어 커밋에 동반)**: `tasks` 행(업무 지시·상태·거절 사유 — 인사 관련 민감 소지) + 업무 공유드라이브 행(제출물 — 학생 명단·성적이 실릴 수 있어 텍스트보다 민감). 처리방침 문안 갱신 여부는 코어 시점에 판단.
- 감사 로그: 생성·철회·재촉·제출함 권한 부여/회수.

## §9 비용 계수

- 쓰기: 업무 1건 = 문서 1 + 상태 전이당 1 (수백/일 상한). 읽기: 내 할 일 = 본인 쿼리, 현황판 = 문서 1개 구독(수신자별 상태가 한 문서 안 — 좁은 구독). Drive: 양식+제출 인원수(§0-5). 크론 추가 없음(daily-sync 통합 2건).
- 무료 원칙: 실서비스 경로 전부 기존 무료 자원 내. 공유드라이브는 Workspace 계약 내 0원.

## §10 검증

- 순수 셀프테스트: ① 상태 전이 전 조합(불법 전이 거부 포함) ② 파일명 정규화(담임/부서/생략 3갈래·특수문자·확장자 보존) ③ 기한 임박 판정(KST 경계) ④ 재촉 24h 제한 판정.
- 실계정 사이클(memo_attachment 2부 전례): 공유드라이브 폴더 생성→양식 업로드→제출→정규화 확인→권한 실측→파기, 흔적 삭제.
- 실기기 시나리오: 확인형 왕복(발송→알림 수락→완료→현황판) + 제출형 왕복(양식 내려받기→제출→파일명 확인→재제출 경고) — 협력자(변수 ③ 有) 계정 활용 가능.
