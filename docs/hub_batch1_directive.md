## 3. 피드백 5 — 부분 선택과 완전 선택이 구분되지 않는다

**파일**: `src/components/admin/hub/HubOrgTree.tsx` — `IndeterminateCheckbox`(:20-47), 부서 헤더(:320-327)

원인은 **네이티브 `indeterminate` 렌더링**이다. 브라우저는 `indeterminate`를 `checked`와 **같은 강조색으로 채운 박스**에 가로줄만 넣어 그린다. 그래서 부분 선택(`−`)과 완전 선택(`✓`)이 둘 다 파란 채움 박스로 보인다.

**지시**: 부서 헤더 체크박스를 **세 상태가 한눈에 다른 모양**이 되게 바꾼다.

| 상태 | 요구 |
|---|---|
| 선택 없음 | 빈 박스, 회색 테두리 |
| **부분 선택** | **채우지 않는다.** 흰 배경 유지 + 연한 인디고 테두리 + 가운데에 **작고 연한 회색 가로 막대**. "파란 덩어리"로 보이면 실패다 |
| 전체 선택 | 지금처럼 인디고 채움 + 흰 체크 |

- 네이티브 체크박스의 그리기를 그대로 쓰지 말고, 부서 헤더에 한해 커스텀 박스로 그린다(사람 행 체크박스는 두 상태뿐이므로 지금 그대로 둔다).
- **접근성**: 커스텀으로 그리더라도 실제 `<input type="checkbox">`를 없애지 마라(포커스·키보드·`indeterminate` 속성 유지). 시각만 덮는다.
- **선택 로직은 절대 건드리지 마라.** 한 사람이 여러 부서에 속해 1학년 전체 선택 시 교과부들이 부분 선택이 되는 것은 **정상 동작**이다. 이걸 "고치면" 스펙 §3(이메일 기준 중복 제거)이 깨진다.

**확인 방법**: 1학년 전체를 담은 뒤 국어·수학·사회·과학 부서 헤더를 본다. **선택하지 않은 사람까지 담긴 것처럼 보이지 않아야 한다.** 아래 4번(선택 인원 배지)과 함께 보면 판단이 확실해진다.

**근거**: 스펙 **§2-1-2**(이번에 신설). memo_spec §11-2가 *"전 교직원 발송은 조직도 전체 선택으로 대체된다"* 로 못 박았으므로, **이게 없으면 전 교직원 발송 수단 자체가 없다.**

## 6. 피드백 4-1 — 검색은 트리를 필터하지 않는다. 평면 목록이다

**근거**: 스펙 **§2-1-1**(이번에 신설) — **읽고 그대로 구현해라.** 아래는 요약이다.

사용자 요지: *"조직도는 그 사람의 위치를 알 때 쓰는 거고, 검색은 위치를 모를 때 쓴다."* 지금처럼 트리를 필터하면 일치자가 부서 아래 흩어져 있어 여전히 부서를 훑어야 한다.

**지시**: 검색어가 1자 이상이면 **트리 자리를 평면 결과 목록이 대체**한다.

- 후보 = 소속이 등록된 교직원 전원(부서를 가로질러 평평하게), **사람 1명 = 줄 1개**(3개 부서 소속이어도 3줄이 되지 않는다)
- 한 줄 = **이름 + 부서 부제**(부서가 여럿이면 전부). 검색 결과에서는 부제를 **항상** 붙인다
- 매칭 = **이름**. 여기에 더해 **내선번호 숫자 매칭도 넣는다** — 기존 쪽지 쓰기에 있던 기능이다(`MemoSection:151-157`). **이메일·아이디 매칭은 금지**(memo_spec §11-2)
- 선택 = 줄 왼쪽 체크박스(트리와 같은 제스처). 이름 클릭은 정보 카드
- 0건이면 `"이름과 일치하는 선생님이 없습니다."` 한 줄. **부서 헤더를 남기지 마라** — 이게 원래 신고된 증상이다
- 정렬은 이름 가나다순. `sortMembersForDept`(부서장·담임 우선)는 **쓰지 마라** — 부서 안에서만 뜻이 있는 정렬이다
- 검색어를 지우면 트리로 돌아오고 **담긴 사람은 그대로 유지**된다
- 서버 호출 0. 이미 불러온 명단만 필터링한다

**함께 지울 것 (중요)**: 검색 시 부서를 자동으로 펼치는 `useEffect`(`HubOrgTree:206-217`)를 **삭제한다.** 트리를 더 이상 필터하지 않으므로 불필요하고, 지금은 **검색을 한 번 하면 "내 소속 부서만 펼침" 초기 상태가 영구히 파괴되는** 부작용이 있다(검색어를 지워도 복원되지 않는다).

**이 개정으로 함께 사라지는 결함**: 검색 중 부서 헤더를 체크하면 **화면에 보이지 않는 사람까지 담기던 것**(`:324`가 필터 전 `allDeptEmails`로 토글). 평면 목록에는 부서 헤더가 없으므로 자연히 없어진다 — **트리 필터 코드를 남겨 두지 마라.**

**확인 방법**: 이름 두 글자를 친다. 부서 헤더가 하나도 보이지 않고, 일치자만 `이름 · 부서` 형태로 뜬다. 체크해서 담고 검색어를 지우면 트리로 돌아오며 그 사람이 담긴 채로 남아 있다.

## 7. 피드백 9 — 다른 부서의 부서장이 이 부서 부서장으로 표시된다

**파일**: `src/components/admin/hub/HubOrgTree.tsx:356-357`

```
teacher.isDeptHead || teacher.deptHeadMap?.[deptName]     // 지금 (틀림)
```

`isDeptHead`는 *"전체 중 하나라도 부서장인지 여부"* 다(`AuthContext.tsx:23`). 전역 플래그를 먼저 OR 하므로 **어느 부서든 부서장인 사람은 자기가 속한 모든 부서에서 부서장으로 표시된다.** 사용자 화면의 1학년에 부서장 배지가 3개 뜬 이유다.

**지시**: 기존 조직도(`OrgChartTree.tsx:258`)·정렬 유틸(`src/lib/org/sort.ts:37-39`)과 **똑같은 조건으로 교체**한다.

```
!!teacher.deptHeadMap?.[deptName] || (teacher.departments?.length === 1 && teacher.isDeptHead)
```

단일 부서 폴백은 `deptHeadMap`이 비어 있는 프로필 때문에 필요하니 **빼지 마라.** 지금은 배지와 정렬이 서로 다른 기준으로 돌고 있고, 이 수정으로 둘이 같아진다.

## 9. 피드백 12 — 조직도 로드 실패가 정상 빈 상태와 구분되지 않는다

- 문구에 기술 용어를 쓰지 마라(예: `"명단을 불러오지 못했습니다. 잠시 후 다시 시도해 주세요."`).

**확인 방법**: DevTools에서 해당 요청을 차단하고 새로 고쳐, 스피너가 영원히 돌거나 "정보가 없습니다"로 끝나지 않는지 본다.

## 10. 피드백 13 — 부서로 담아도 수신 요약이 개인 나열로 저장된다

**파일**: `src/components/admin/hub/HubMemoComposer.tsx:93` · `HubTaskComposer.tsx:108` · `src/components/admin/MessagingHub.tsx`

두 작성기가 칩을 만들 때 `source: "person"` 을 **상수로 박아서**, `buildRecipientSummary`(`src/lib/org/recipients.ts:29-36`)의 부서 분기가 절대 실행되지 않는다. 1학년 전원에게 보내도 요약이 `1학년 11명`이 아니라 `홍길동 외 10명`으로 굳는다.

**이건 화면이 아니라 저장되는 데이터에 남는다.** 부서로 골랐다는 정보는 발송 순간에만 존재하므로 나중에 복원할 수 없다.

**지시**: 부서 헤더 체크로 담긴 사람에게 `source: "dept"` + `deptLabel`(그 부서명)을 부여한다.

- 기존 쪽지의 방식이 참고 기준이다(`MemoSection:1336-1350` — 부서 전원이 담겨 있으면 그 부서 칩으로 표시).
- 개인 체크로 담은 사람은 `"person"` 그대로.

**확인 방법**: 1학년 헤더를 체크해 발송한 뒤 보낸쪽지함·보낸 업무 현황판의 수신 요약이 `1학년 11명` 형태로 뜬다. 두 부서를 담으면 `1학년 외 1개 부서 N명`.

## 12. 피드백 8 — 「교직원 조직도」를 관리자 전용으로 내린다
