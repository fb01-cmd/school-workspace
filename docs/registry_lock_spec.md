- **확정 근거**: development_roadmap.md §2 「활성 학기에서는 편성 등록부를 열람 전용으로」 — 2026-08-15 사용자 발상 → 2026-08-16 사용자 5쟁점 전부 확정(ⓐ~ⓔ). 이 문서는 그 확정의 구현 스펙이다(새 결정 없음).
- **분업**: 스펙+서버 가드 = Claude(§1-2 직접 구현 영역 — 보안·권한 가드) / 잠금 표시·해제 다이얼로그 UI = Antigravity (§5가 인계 경계)
- **작성**: 2026-08-18

## §0. 왜 잠그는가 — 소급 효력

이동수업(SimulGroup)·특별실(VenueGroup) 등록부는 "편성 때 쓰고 끝"이 아니라 **살아 있는 판정 원본**이다: 그리드를 로드할 때마다 서버가 이 등록부로 `lesson.simul`·`lesson.room`을 다시 스탬프하고, 그 스탬프가 교체 하드 제외·특별실 겹침·통 이동 판정의 근거다. 학기 중에 등록부를 고치면 **이미 승인된 교체·통 이동의 판정 근거가 소급으로 바뀐다.** 위험한 것은 읽기가 아니라 편집이다.

한편 전면 차단은 배제한다 — 2026-08-15 통 이동 작업에서 **등록 누락을 학기 중에 정정할 실수요**가 실증됐다(등록부와 그리드가 어긋나면 통 이동 자체가 거부되므로, 누락은 학기 중에라도 고쳐야 한다). 그래서 "기본 잠금 + 명시적 해제"다.

## §1. 잠금 매트릭스 (확정 ⓓ)

| 학기 상태 | 판정 기준 | 편성 등록부 편집 |
|---|---|---|
| 초안 | 운영 학기 아님 + `status ≠ "archived"` | **자유 편집** (지금과 동일) |
| 운영 | `settings.activeTermId === termId` (운영 판정의 기존 단일 기준) | **기본 잠금** — 해제 사유를 실어 보낸 요청만 통과, 전건 감사 기록 |
| 보관 | `term.status === "archived"` | **완전 열람 전용** — 해제 불가 |

- 대상 액션 10종 (편성 등록부 5종의 저장·삭제): `simul_save`·`simul_delete`·`venue_save`·`venue_delete`·`slot_ban_save`·`slot_ban_delete`·`consecutive_rule_save`·`consecutive_rule_delete`·`co_teaching_rule_save`·`co_teaching_rule_delete`.
- ㉯ 계열(배정금지·연속수업·공동수업 — 활성 학기에 안 쓰이는 편성 전용 규칙)도 **같은 매트릭스를 적용**한다(ⓓ 균일). 숨기지 않는다 — 열람은 항상 가능(ⓒ).
- 대상 아님: `registry_inherit`(이미 초안 대상 전용 가드 실재), `simul_move_commit`(통 이동 — 편집이 아니라 운영 기능), 조회 계열 전부, 교육과정 코호트(학기 무관 축).
- 잠금 판정에 쓰는 termId: 저장 = 기존 파생 규약 그대로(`body.X?.termId || body.termId || settings.activeTermId`), 삭제 = **기존 문서의 termId** (전 삭제 핸들러가 이미 문서를 먼저 읽는다).

## §2. 잠금의 단일 소재지 = 서버 가드 (확정 ⓔ)

UI 잠금은 표현일 뿐이다 — API 직접 호출로 우회되면 잠금이 아니다(공강 조회 축소 교훈). `server.ts`에 단일 판정 함수를 둔다:

```ts
export class RegistryLockError extends Error { statusCode = 423; termState: "operating" | "archived"; }

/** 등록부 편집 잠금 판정 — 통과 시 해제 여부 반환, 잠기면 RegistryLockError를 던진다.
 *  운영 학기 + 유효한 unlockReason이면 감사 로그(registry_lock_unlock_edit)를 남기고 통과. */
export async function assertRegistryEditable(
  domain: string,
  termId: string,
  operatorEmail: string,
  unlockReason: string | undefined,
  editSummary: string
): Promise<void>;
```

- 해제 사유: 공백 제거 후 **2~200자**. 미달·부재 시 423 거부.
- 감사 기록: 해제 편집 전건에 `registry_lock_unlock_edit` 항목(사유 + 편집 요약 + 학기) — 각 액션의 기존 감사 로그와 별개로, "잠금을 뚫은 편집"만 모아 검색할 수 있게.
- 423 응답 형태(항상 이 모양 — UI가 다이얼로그 분기에 쓴다):

```json
{ "error": "<눈높이 문구>", "code": "registry-locked", "termState": "operating" | "archived" }
```

## §3. 요청 계약

- 10종 편집 요청에 선택 필드 `unlockReason?: string` 추가 (`ManageTimetableRequest`).
- 초안 학기: 필드 무시(있어도 감사 기록 안 함 — 잠금이 없으니 해제도 없다).
- 운영 학기: 필드 없으면 423 `termState:"operating"` / 있으면 통과+감사 기록.
- 보관 학기: 무조건 423 `termState:"archived"`.

## §4. 화면 문구 (확정 ⓑ·ⓒ — ui-copy-rules 준수)

- 잠김 안내(운영): *"운영 중인 학기의 편성 등록 내용은 잠겨 있습니다. 이미 승인된 교체·이동의 판정 근거가 되기 때문입니다. 꼭 고쳐야 하면 사유를 입력하고 잠금을 해제해 주세요."*
- 해제 경고(ⓑ, 해제 다이얼로그에 표시): *"이 변경은 이미 확정된 교체의 판정 근거를 바꿉니다. 변경 내용과 사유는 작업 기록에 남습니다."*
- 보관 안내: *"지난 학기의 편성 등록 내용은 열람만 가능합니다."*
- ㉯ 계열 탭 상단 안내(ⓒ, 운영 학기일 때): *"이 등록 내용은 시간표를 새로 짤 때 쓰입니다. 운영 중인 시간표에는 영향을 주지 않습니다."*

## §5. Antigravity UI 인계 경계

- 등록부 4탭(이동수업·특별실·특별교사 금지·연속수업)과 복수교사 편집 화면: 운영 학기일 때 편집 컨트롤에 잠금 표시(자물쇠 배지) + 저장/삭제 시 423 `registry-locked` 응답을 받으면 **사유 입력 다이얼로그**(§4 경고 문구 포함) → 사유와 함께 재요청. 사유는 편집 세션 동안 기억하되 다이얼로그 창은 매번 표시하여 확인 후 진행하도록 한다(요청마다 실어 보내는 것은 유지).
- 보관 학기: 편집 컨트롤 비활성 + §4 보관 안내. 다이얼로그 없음.
- ㉯ 계열 탭에는 §4의 안내 문구를 상단에 상시 표시(운영 학기일 때).
- 서버 판정이 원본이므로 UI는 termState를 스스로 계산하지 말고 **423 응답으로 분기**하는 것을 기본으로 한다(선제 배지는 표시용으로만 `activeTermId === 작업 학기` 비교 사용 가능).

## §6. 검증

- `scripts/verify_registry_lock.ts` (읽기 전용): 가드 함수를 실데이터로 직접 호출 — 운영 학기(사유 없음→423, 사유 있음→통과+감사 기록), 초안 학기(자유), 보관 학기(무조건 423), 사유 길이 경계(1자 거부·2자 통과·200자 초과 거부).
- 기존 셀프테스트 회귀 무관(등록부 읽기 경로는 불변).
