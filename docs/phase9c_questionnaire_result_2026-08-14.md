## 1. 금요일 1교시 실무회의 — 13명

장원재 · 전원선 · 전성호 · 이윤정 · 허영실 · 최은정 · 이시내 · 이경호 · 김천도 · 정성희 · 이창재 · 한창훈 · 박윤흡

**성격**: 개인 사정이 아니라 **학교 전체의 고정 회의**다. 13명이 한 슬롯에 동시에 묶이므로 솔버에는 국소 제약이 아니라 **구조적 제약**이다 — 금 1교시는 나머지 교사만으로 30학급을 채워야 한다.

**반영**: 하드 제약. 13명 각각에게 `금 1교시` 배정 금지.

> **1-1(아예 금지 vs 이동만 금지) 미기재** → 질의지에 적어 둔 대로 **전부 "아예 넣으면 안 됨"으로 처리**한다.
>
> ⚠️ **선행 작업**: 위는 **성명**이고 시스템은 **이메일**로 동작한다. 등록 전에 13명의 계정을 대조해야 하며, **동명이인·표기 차이**를 사람이 확인해야 한다. 자동 매칭에 맡기지 않는다.

## 2. 창체·SLAT — 답과 실데이터가 일치한다

**답(2-2)**: 맞다 — 먼저 고정하고 나머지를 짠다.
**부연(선생님이 직접 적으심)**: *"창체, SLAT는 요일과 시간을 고정하고, **시간표 작성 후에** 해당 요일·교시에 창체·SLAT를 임의로 입력함"*

**실데이터 확인 (2026-2 학기, 30개 반 전수)**:
```
SLAT : 수 6교시 30개반 · 수 7교시 30개반
창체 : 금 5교시 30개반 · 금 6교시 30개반
```
**한 반의 예외도 없다.** 답과 데이터가 완전히 일치한다.

### 이 부연이 스펙을 바꾼다

"먼저 고정한다"를 문자 그대로 읽으면 *솔버가 창체·SLAT를 먼저 배치한다*가 되는데, **부연은 반대**다 — 그 자리를 **비워 두고** 나머지를 짠 뒤, **사람이 나중에 이름을 채운다.**

**따라서 솔버의 역할은 이렇게 확정한다:**

1. 수 6·7, 금 5·6 (전 학급)은 **일반 수업 배정 금지 구역**이다.
2. 솔버는 창체·SLAT를 **배치 대상으로 삼지 않는다.** 이름을 넣는 것은 사람의 사후 작업이다.
3. 즉 이 슬롯은 "고정 수업"이 아니라 **점유 불가 슬롯**으로 다루는 편이 실무와 맞다.

> 부연이 없었으면 "창체를 배치하는 솔버"를 만들 뻔했다. **선택지에 적어 주신 한 줄이 설계를 바꿨다.**

## 3. 소프트 제약 가중치 — §11 미결정 2번 종결

두 항목 모두 **최상위(중요하게 지킨다)가 아니다.** 실무에서 "지키면 좋지만 포기 가능한" 축이다.

| 제약 | 답 | 판정 |
|---|---|---|
| **S6** 교사 하루 수업의 오전/오후 쏠림 | 웬만하면 피하지만 어쩔 수 없으면 둔다 | **중간 가중치** |
| **S7** 같은 과목의 반별 교시 순배 | 가능하면 좋지만 필수는 아니다 | **낮은 가중치** |

**서열이 확정된다: S6 > S7, 둘 다 하드 아님.**

**구체 수치는 지금 정하지 않는다.** 절대값은 다른 소프트 제약과의 상대비로만 의미가 있고, 실제 편성을 돌려 봐야 균형이 보인다. **11월 리허설에서 조정**하되 **S6가 S7보다 크다는 서열은 고정**한다.

> 이 답이 중요한 이유: 둘 중 하나라도 "중요하게 지킨다"였다면 하드에 준하게 다뤄야 했고, 그러면 해가 급격히 좁아진다. **둘 다 양보 가능**이라는 답은 솔버에 숨 쉴 공간을 준다.

## 4. 나이스 파일 실물 분석 (5-1 회수)

받은 파일 = **1학년 1반**(우리 그리드와 대조해 확정). 저장소에 커밋하지 않는다(교사 성명 포함, `.gitignore`).

### 4-1. 우리 데이터와 35칸 전수 대조 — **완전 일치**

1~7교시 × 월~금 전부 과목·교사가 같다. **딱 한 곳만 다르다**:

| | 우리 그리드 | 나이스 파일 |
|---|---|---|
| 금 5·6교시 | 창체 | **빈 칸(`""`)** |
| 수 6·7교시 | SLAT | **빈 칸(`""`)** |

**→ 5-2의 답이 데이터로 교차 검증된다.** 선생님 답변("파일에서 아예 빠진다")과 실물이 일치한다. 정확히는 **칸 자리는 남고 내용이 빈 문자열**이다.

### 4-2. 파일 형식 (내보내기 구현 사양)

- **UTF-8 + BOM**(`EF BB BF`). BOM이 없으면 나이스/엑셀에서 한글이 깨진다 — **반드시 붙인다.**
- 헤더: `,월,화,수,목,금,토,일` — 첫 칸 비고 **8열**
- 데이터 행: `교시,"과목명(교사명)",…`
- **행마다 열 수가 다르다** — 1~7교시 행은 **7열**, 8·9교시 행은 8열. 후행 빈 칸이 잘려 있다. 재현할 때 이 들쭉날쭉함까지 따라갈지는 **나이스가 받아 주는지 실물로 확인**해야 한다(권장: 8열로 채워 보내고 거부되면 그때 맞춘다).
- 9교시까지 행이 있다(8·9교시는 전부 빈 칸).
- 토·일 열 존재, 값 없음.

### 4-3. 과목명 매핑 — `neisName` 실측 11종

우리 약칭과 나이스 정식명이 다르다. [`phase9c_f_spec.md`](./phase9c_f_spec.md)의 `neisName` 필드에 **이 값을 그대로 넣는다.**

| 우리 표기 | 나이스 정식명 |
|---|---|
| 철학 | 인간과철학 |
| 통과 | 통합과학2 |
| 영어 | 공통영어2 |
| 통사 | 통합사회2 |
| 한국 | 한국사2 |
| 수학 | 공통수학2 |
| 국어 | 공통국어2 |
| 과탐 | 과학탐구실험2 |
| 체Ⅰ | 체육2 |
| 미술 | 미술 |
| 진로 | 진로 |

> **주의**: 이건 **1학년 과목만**이다. 2·3학년 과목명은 아직 모른다 — 파일을 한 반만 받았기 때문이다. `phase9c_f_spec`의 **B1 차단 규칙**(NEIS명 미확정이면 내보내기 차단)이 그대로 유효하다.
