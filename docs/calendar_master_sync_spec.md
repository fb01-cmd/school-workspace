# 학사일정 마스터 동기화 스펙 (calendar_master_sync)

2026-08-10 사용자 확정 방향: **학사일정이 마스터다.** 주는 학사일정에서 자동 파생되고(기구현, pre_opening_3features_spec §B), 학사일정이 변경되면 **이미 파생된 주에도 반영**되어야 하며, 학사일정으로 표현되지 않는 조정·돌발 변수만 주 운영의 휴업·시수 수정으로 처리한다. 이에 따라 "새 주 등록" 수동 UI는 제거한다.

관련 확정 이력: development_roadmap.md §2 "주간 목록 완전 자동화"(과거 주 숨김·노출 캡·파생 게이트 — 배포 완료 eaa0b56), project_notes.md [2026-08-10] 체크포인트들.

## §1 계층 모델

| 계층 | 원본 | 반영 시점 | 수단 |
|---|---|---|---|
| 마스터 | 학사일정(휴업일·재량휴업·단축수업·고사) + 공휴일표 | 주 생성 시 + **학사일정 변경 시(신규)** | `deriveWeekInput` |
| 오버라이드 | 주별 수동 조정(학사일정에 없는 돌발 변수) | 일과계가 휴업·시수 수정 저장 시 | `week_update` |

병합 규칙: **요일(day) 단위**. 주의 각 요일은 "파생값 추종" 또는 "수동 오버라이드" 중 하나이며, 동기화는 파생 추종 요일만 다시 쓴다. 수동 오버라이드 요일은 항상 보존한다(마스터에 나중에 같은 날짜 이벤트가 생겨도 오버라이드 우선 — 단순·예측 가능성을 위해 예외 없음. 일과계는 §5의 배지로 오버라이드 요일을 식별해 스스로 판단).

## §2 데이터 모델 (types.ts)

`TimetableWeek`에 필드 추가:

```ts
dayOverrides?: number[]; // 수동 오버라이드된 요일(1~5). 없으면 레거시 주(§4 자가 이행 대상), 빈 배열이면 전 요일 파생 추종.
```

## §3 서버 로직 (server.ts)

### §3-1 오버라이드 판정 — week_update 확장
`updateWeek`에서 days 수정 저장 시:
1. `loadCalendarEvents` + `deriveWeekInput(termId, startDate, events)`로 **현재 마스터 기준 파생 days**를 계산한다 (수동 수정은 드문 작업이므로 이 추가 읽기는 허용).
2. 제출된 각 요일 값을 파생값과 비교해 **다른 요일만 `dayOverrides`에 기록**, 같은 요일은 제거한다.
   - 자가 치유 성질: 일과계가 요일을 파생값과 같게 되돌리면 오버라이드가 자동 해제되어 다시 마스터를 추종한다.
3. 요일 비교 기준: `holiday` 불리언과 `periodsByGrade`(키·값 전체) 동치.

### §3-2 동기화 — calendar_save·calendar_delete 쓰기 경로
학사일정 쓰기 성공 직후 `syncDerivedWeeksWithCalendar(domain, termId)` 실행:
1. `listWeeks(domain, termId)`에서 **과거 주 제외**(종료일 < todayKSTISO() — 지난 주는 기록이므로 불변).
2. 각 대상 주에 대해 `deriveWeekInput` 재계산 후, `dayOverrides`에 없는 요일만 파생값으로 치환. 값이 하나도 안 바뀌면 쓰기 생략(무변경 주 write 0).
3. note 처리: 주 note가 없거나 `"학사일정 자동:"`으로 시작하면 파생 note로 재생성, 그 외(수동 note)는 보존.
4. 완료 후 `bumpTimetableCacheVersion` 1회 + 감사 로그 1건(변경된 주 ID 목록 요약, action: `sync_calendar_weeks`).
5. 이벤트 날짜 범위로 대상 주를 좁히지 **않는다** — 수정·삭제 시 옛 날짜 범위 주도 원복해야 하므로 전 비과거 주 재계산이 단순하고 안전하다(대상 최대 = 노출 창 + 잔여 등록 주, 실측 규모 수 개).

### §3-3 자동 파생 주 생성 시 (registerWeek 경유 ensureDerivedWeeks)
신규 파생 주는 `dayOverrides: []`로 생성한다("전 요일 마스터 추종" 명시).

## §4 레거시 주 자가 이행
`dayOverrides`가 **없는(undefined)** 기존 주(개학 준비 때 수동 등록된 8/10~8/31 등)는 첫 동기화 때:
- 현재 days와 파생 days를 요일별 비교해 **다른 요일 = 오버라이드로 초기화**(수동으로 만든 값 보호), 같은 요일 = 추종으로 편입.
- 별도 마이그레이션 스크립트 불요 — sync 헬퍼 안에서 1회 수행되고 이후 `dayOverrides`가 항상 존재.

## §5 UI (WeekManageTab.tsx)

1. **"새 주 등록" 버튼·모달 제거** (2026-08-10 사용자 확정: 자동 파생 전담으로 잉여). `week_register` API·`registerWeek` 함수는 예외 상황용으로 존치(스크립트 경로).
2. 헤더 카드 문구 교체(눈높이 표현, 개발 용어 금지): 주는 학사일정에서 자동으로 만들어지며, 학사일정에 없는 돌발 조정만 이 화면의 휴업·시수 수정으로 처리한다는 안내.
3. 주 목록 행에 **수동 조정 요일 배지**: `dayOverrides`가 비어 있지 않으면 해당 요일 칩에 "직접 조정" 표시 — 일과계가 마스터 추종/수동 구분을 눈으로 확인.
4. 휴업·시수 수정 모달 동작은 불변(서버가 §3-1로 오버라이드를 자동 판정).

## §6 검증

- `npx tsc --noEmit`·`npm run build`(힙 4GB 옵션) 통과.
- 실측 시나리오(admin SDK 스크립트, 읽기 위주 — Claude 검수 시 수행):
  1. 학사일정에 미래 주 단축수업 추가 → 해당 주 요일 periodsByGrade 반영 확인.
  2. 그 요일을 휴업·시수 수정으로 다르게 조정 → dayOverrides 기록 확인.
  3. 학사일정 이벤트 삭제 → 오버라이드 요일 보존 + 추종 요일 원복 확인.
  4. 레거시 주(8/17 광복절 휴업 등) 첫 동기화에서 기존 값 불변(오버라이드 편입 or 파생 일치) 확인.
- 테스트용 학사일정 이벤트는 검증 후 반드시 삭제(프로덕션 실데이터).
