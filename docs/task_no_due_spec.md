# 기한 없는 「내 할 일」 스펙 (task_no_due)

> **작성**: 2026-08-20 Claude (Opus 5) · **근거**: 로드맵 §2 아이디어 38번 (2026-08-19 사용자 발제, **정렬 A안 확정**)
> **상위 스펙**: [`phase8_tasks_spec.md`](./phase8_tasks_spec.md) — 이 문서는 그 위의 부분 개정이다
> **성격**: 무엇을 어떻게 저장하고 어디에 놓는가만 정한다. 마크업·문구 다듬기는 구현자 몫이다

## §0 확정 전제

| # | 확정 사항 | 출처 |
|---|---|---|
| 1 | **기한 없는 항목은 「내 할 일 추가」(셀프 등록)에만 허용한다.** 남에게 보내는 업무에는 허용하지 않는다 | Claude 제안 → 2026-08-19 사용자 확정 |
| 2 | **정렬 = 구역 분리(A안).** 기한 있는 것은 지금처럼 임박순, 기한 없는 것은 그 아래 별도 구역 | 2026-08-19 사용자 확정 |
| 3 | 리마인드·지남 판정에서 제외 · 홈 카드 미표시 · 미완료 건수에는 포함 | 같은 결정의 딸린 규약 |

**전제 1의 근거(재론 금지)**: 기한 없는 업무를 남에게 보내는 것은 *"이거 좀 해주세요"* 하고 말로 시키는 것의 재현이다. 이 화면의 취지(`messaging_hub_ia_spec` §2-5 — 메신저 기반 업무의 개선)와 정면으로 충돌한다. 반면 **자기가 자기한테 적는 메모는 그 유도의 대상이 아니다** — "언제까지"가 아니라 "잊지 않으려고" 적는 것이라 성격이 다르다.

## §1 저장 방식 — 센티널 + `noDue` 불리언 (**이 절이 이 스펙의 핵심 판단이다**)

### §1-1 왜 `dueAt: null`이 아닌가

「내 할 일」·모바일·홈 카드 **세 곳이 전부 `dueAt`을 범위 조건으로 걸어서** 문서를 가져온다.

```
where("recipientEmails", "array-contains", myEmail)
where("dueAt", ">=", windowStart)      ← 90일 창
orderBy("dueAt", "asc")
limit(100)
```
(`TasksSection:182-188` · `MobileTasksSection:123-129` · `DashboardTaskCard:71~`)

**`dueAt`이 없으면 이 조건에 걸리지 않아 세 목록 모두에서 통째로 빠진다.** 별도 쿼리를 하나 더 두면 해결되지만, 그러려면 ⓐ 새 복합 색인 ⓑ 화면마다 읽기 1회 추가가 따라온다. 이 저장소는 읽기 예산 규율이 있는 곳이다.

### §1-2 채택 — 먼 미래 센티널 + `noDue`

| 필드 | 값 |
|---|---|
| `noDue?: boolean` | 기한 없는 항목에 `true`. **이것이 계약이다** |
| `dueAt` | `TASK_NO_DUE_AT` 센티널 (`Date.UTC(2100, 0, 1)` = `4102444800000`) |

**이 방식이 공짜로 얻는 것 4가지** — 코드를 안 고쳐도 저절로 맞는다.

1. **세 쿼리가 그대로 집어 온다** (센티널 > windowStart)
2. **`orderBy asc`에서 자동으로 맨 뒤에 온다** — A안의 "기한 있는 것 먼저, 없는 것 나중"이 정렬로 이미 성립
3. **D-1 리마인드에서 자동 제외** — 스윕이 `dueAt > now && dueAt < now+48h`로 조회한다(`src/lib/tasks/cron.ts:31-32`). 센티널은 영원히 안 걸린다
4. **「지난 업무」 탭에도 안 뜬다** — 그 쿼리는 `dueAt < windowStart`다(`TasksSection:108`)

**새 색인 0건 · 추가 읽기 0건 · 서버 스윕 변경 0건.**

### §1-3 센티널의 대가 — 반드시 지킬 규약

> **⚠️ 센티널은 구현 세부이고, 계약은 `noDue`다. 화면은 `dueAt`을 보기 전에 항상 `noDue`부터 본다.**
> 이 규약을 어기면 화면에 **「2100.01.01까지」** 나 **「D-27000」** 이 샌다.

**고쳐야 하는 표시 경로 4곳** (빠뜨리면 그대로 샌다):

| 위치 | 지금 | 해야 할 것 |
|---|---|---|
| `TasksSection.tsx:40` `formatRemainingTime` 호출부 | `dueAt`으로 남은 시간 계산 | `noDue`면 계산하지 말고 **「기한 없음」** |
| `MobileTasksSection.tsx:32` 같은 함수 호출부 | 동일 | 동일 |
| `DashboardTaskCard.tsx:37` `formatDue` | `if (!dueAt)` 분기가 있으나 **센티널은 truthy라 안 걸린다** | `noDue` 분기를 **앞에** 추가 |
| `TaskStatusBoard.tsx:250` `dueInfo` | 셀프 업무도 이 보드의 「셀프 구역」(`:248`)에 뜬다 | 동일 |

**함수 자체를 고쳐도 되고 호출부에서 갈라도 된다.** 다만 **네 곳 전부**여야 한다.

### §1-4 알려진 한계 (지금은 수용, 문서화만)

`limit(100)`에서 **센티널 항목이 뒤에 있어 먼저 잘린다.** 기한 있는 업무를 100건 넘게 가진 사람은 기한 없는 항목을 못 볼 수 있다. 1인당 보유량이 수십 건 규모인 현재로선 문제가 없고, **잘리는 순서가 "급한 것이 살아남는" 쪽이라 방향도 옳다.** 규모가 커지면 그때 별도 쿼리로 분리한다.

## §2 서버 — 셀프 등록에만 연다

**파일**: `src/lib/tasks/logic.ts` · `src/app/api/tasks/route.ts`

1. **`validateTaskContent`** — 입력에 `noDue === true`가 있으면 **`dueAt` 검증을 건너뛰고** 결과의 `dueAt`을 센티널로, `noDue: true`를 함께 돌려준다. `noDue`가 없으면 지금 동작 그대로(기한 필수).
2. **`buildSelfTaskDoc`** — `noDue`를 받아 문서에 `noDue: true`로 싣는다. 나머지(확인형 강제·즉시 수락·`selfAssigned`)는 그대로.
3. **⭐ `prepare`(남에게 보내는 업무)는 `noDue`를 거부한다** — 전제 1. 클라이언트가 보내와도 서버가 400으로 막는다. *"기한 없는 업무는 본인 할 일에만 등록할 수 있습니다."*
   - **화면에서 막는 것만으로는 부족하다.** 전제 1은 이 화면의 취지에 관한 결정이라 서버가 지키는 것이 맞다.
4. `TASK_NO_DUE_AT` 상수를 `logic.ts`에 둔다 — 이 파일은 네트워크 무의존이라 클라이언트도 임포트한다(기존 `validateTaskFileName` 전례).

## §3 화면 — 「기한 없음」 구역

### §3-1 입력

「내 할 일 추가」 미니 입력에 **[기한 없음] 체크박스**를 둔다.

- 체크하면 **날짜·시각 입력이 비활성**된다(사라지지 않고 흐려진다 — 되돌릴 수 있다는 게 보여야 한다)
- **PC(`TasksSection`)와 모바일(`MobileTasksSection`) 둘 다** 넣는다
- 기본값은 **체크 해제**(기한 있는 쪽이 기본) — §2-5 유도 방향과 같다

### §3-2 목록 배치 (A안)

```
내 할 일
────────────────────────
  교육과정 반성 제출        내일까지
  만족도 조사               08.22까지
  ...                       (기한 임박순 — 지금 그대로)
────────────────────────
기한 없음  3
  교실 열쇠 반납 건
  2학기 교재 확인
  ...                       (최근 추가순)
```

- **구역 머리에 건수**를 단다
- 구역 안 정렬 = **최근 추가순(`createdAt` 내림차순)**. 전부 센티널이라 `dueAt`으로는 순서가 안 정해진다 — **클라이언트에서 정렬한다**
- **기한 없는 항목이 0건이면 구역 자체를 감춘다** (빈 구역이 자리를 먹지 않게)
- 각 줄에서 기한 자리는 **비우거나 「기한 없음」** — 날짜 비슷한 것을 절대 쓰지 않는다

### §3-3 다른 화면의 처리

| 화면 | 처리 | 이유 |
|---|---|---|
| **홈 카드**(`DashboardTaskCard`) | **기한 없는 항목 제외** | 그 카드는 「기한 임박순 5건」이 취지다. 기한 없는 것이 섞이면 카드의 뜻이 없어진다 |
| **미완료 건수 배지** | **포함** | 할 일은 할 일이다 |
| **보낸 업무 현황판** 셀프 구역 | 표시하되 기한 자리는 「기한 없음」 | §1-3 |
| **완료 처리** | 지금과 동일 | 확인형이므로 완료 체크로 끝난다 |

## §4 명시적 비범위

- 남에게 보내는 업무의 기한 없음 (전제 1 — **서버가 막는다**)
- 기한을 나중에 붙이기(기한 없음 → 기한 있음 전환) — 있으면 좋으나 이번 범위 아님. **필요해지면 별건으로 판단**
- 수동 드래그 정렬 (B·C안 폐기 근거는 로드맵 38번)
- 반복 업무·템플릿

## §5 검증

| # | 항목 | 확인 방법 |
|---|---|---|
| 1 | **센티널 누출 0** | 기한 없는 항목을 하나 만들고 **네 화면 전부** 확인 — 「내 할 일」·모바일·홈 카드·현황판 셀프 구역. **「2100」이나 「D-」로 시작하는 큰 수가 한 곳도 없어야 한다** |
| 2 | 배치 | 기한 있는 것 아래에 「기한 없음 N」 구역. 0건이면 구역이 안 보인다 |
| 3 | 구역 내 정렬 | 새로 추가한 것이 그 구역 **맨 위** |
| 4 | 홈 카드 | 기한 없는 항목이 **안 뜬다.** 미완료 건수에는 **들어간다** |
| 5 | **서버 게이트** | 남에게 보내는 업무 발송에 `noDue`를 실어 보내면 **400**. (개발자 도구나 스크립트로 직접 호출해 확인) |
| 6 | 리마인드 제외 | `npx tsx --env-file=.env.local scripts/...` 스윕 dry-run에서 기한 없는 항목이 리마인드 대상에 **없다** |
| 7 | 지난 업무 탭 | 기한 없는 항목이 **안 뜬다** |
| 8 | 기존 회귀 0 | 기한 있는 업무의 표시·정렬·리마인드가 **하나도 안 바뀐다** |
| 9 | 기계 | `tsc` 0건 · `build` 통과 · `bash scripts/check_ui_removals.sh <시작커밋>` 0건 |
