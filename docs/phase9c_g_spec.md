# Phase 9c-G — 미배정 처리: ejection 한계와 실패 사유 진단 (2026-08-14, Claude Opus 5)

> `phase9c_spec.md` §11 미결정 1번 *"솔버 실패(미배정 다수) 시 UX — 컴시간은 「걸림돌 삭제 후 재배정」 수동 순환. 자동 ejection 한계 설정"* 을 확정한다.
> 관련: `phase9c_d_spec.md` §5(미배정 목록 → 수동 배정 UI), 로드맵 §2 「징검다리 체인 탐색 실패 사유 표시」(같은 계열 문제).

## 0. 결론 먼저

1. **ejection을 더 깊게 파지 않는다.** 깊이 2·걸림돌 2개 유지. 깊이를 늘리면 비용은 지수로 늘고 얻는 배치는 얼마 안 되며, **실패한 시도가 판을 흔드는 부작용**(§3)이 같이 커진다.
2. **대신 「왜 못 넣었는지」를 돌려준다.** 지금은 미배정 목록이 *"이 수업 3시간이 안 들어갔습니다"* 로 끝나 사람이 원인을 처음부터 찾아야 한다. **원인을 한 줄로 주면 수동 조정이 한 번에 끝난다.**
3. **실패 시도가 남기는 잔여 이동을 막는다** — 읽다가 발견한 결함(§3). 지금은 실패한 ejection이 판을 조금씩 바꿔 놓고 물러난다.

---

## 1. 현재 구현 (실물 확인 — `src/lib/timetable/solver.ts`)

```
⑤ greedy 배치 → 막힌 것(stuck) 수집
⑥ ejection chain: for (p of stuck) tryPlaceWithEjection(p, 2)
   실패분 → unplacedFinal → 결과의 unplaced[]
```

`tryPlaceWithEjection(p, depth)`(`:624~`)의 한계값:

| 항목 | 현재 값 | 위치 |
|---|---|---|
| 재귀 깊이 | **2** | `:626` 호출부 |
| 슬롯당 허용 걸림돌 수 | **≤ 2** | `:659` `blockerKeys.size > 2 → continue` |
| 고정 수업(`kind === "fixed"`) | **걸림돌로 삼지 않음** | `:661` |
| 금지·허용 슬롯 | **절대 조건** (넘지 않음) | `:642` |
| 실패 시 | 대상 배치 + 걸림돌 **롤백** | `:688~` |

**이 설계는 맞다.** 고정 수업을 안 건드리는 것, 금지 슬롯을 절대 조건으로 두는 것, 실패 시 롤백하는 것 모두 옳다. 바꿀 이유가 없다.

---

## 2. 한계값을 올리지 않는 이유

깊이 3, 걸림돌 3개로 올리자는 유혹이 있다. **하지 않는다.**

- **비용이 지수다.** 슬롯 후보(요일 5 × 교시 ~7) × 걸림돌 조합 × 재귀. 깊이 2에서 3으로 가면 탐색이 한 자릿수 배로 늘어난다. 브라우저 워커에서 도는 솔버다(`solver.worker.ts`).
- **얻는 것이 적다.** 깊이 2로도 안 들어가는 수업은 대개 **국소적 충돌이 아니라 구조적 과포화**다 — 그 교사의 주당 가용 슬롯이 애초에 부족하거나, 특별실이 모자라거나, 금지 슬롯이 과하다. 걸림돌을 한 겹 더 밀어도 안 풀린다.
- **판이 흔들린다.** §3의 결함이 깊이에 비례해 커진다.
- **사람이 더 잘 푼다.** 구조적 과포화는 "이 제약을 풀 것인가"라는 **판단**이고, 그건 일과계 선생님의 몫이다. 솔버가 억지로 밀어 넣으면 오히려 실무가 못 받아들이는 시간표가 나온다.

> **판정: 깊이 2·걸림돌 2 고정. 대신 실패를 잘 설명한다.**

---

## 3. 🔴 발견한 결함 — 실패한 ejection이 판을 바꿔 놓는다

`tryPlaceWithEjection`은 실패 시 **자기가 뺀 걸림돌(`removedOccs`)만** 되돌린다(`:688~`).

그런데 재귀 호출이 성공하면 그 안쪽에서 **또 다른 걸림돌들을 옮겼을 수 있다.** 그것들은 `removedOccs`에 없으므로 **롤백 대상이 아니다.** 바깥 시도가 뒤늦게 실패해도 안쪽이 옮겨 놓은 것은 그대로 남는다.

**결과가 틀리지는 않는다** — 모든 `apply`가 점유 표를 정확히 유지하므로 판은 항상 유효하다. 문제는 다른 데 있다:

- **실패한 시도가 해를 조금씩 흔든다.** 아무 성과 없이 소프트 점수만 나빠질 수 있다.
- **시드 재현성이 약해진다.** 같은 시드로 돌려도 실패 경로의 부작용이 누적 순서에 따라 달라진다. 포트폴리오(`DEFAULT_SEED_PORTFOLIO`)로 여러 시드를 비교하는 설계인데, 비교의 전제가 흔들린다.

### 처방 — 스냅샷 롤백

`tryPlaceWithEjection` 진입 시 그 시도가 건드릴 범위의 배치 상태를 저장하고, 실패하면 **통째로 되돌린다.**

```ts
// 깊이 2 · 걸림돌 2라 스냅샷 크기는 작다(최대 수 개 occurrence).
// 전체 판을 복사하지 말고 "이번 시도에서 apply된 것"만 기록해 역순으로 되돌린다.
const journal: Array<{ occ: Occurrence; dir: 1 | -1 }> = [];
// apply를 감싸 journal에 남기고, 실패 시 journal을 역순으로 반대 방향 apply
```

**전체 판 복사는 하지 않는다** — 30학급 × 34슬롯을 매 시도마다 복사하면 그게 더 비싸다. 되돌릴 것은 이번 시도가 실제로 건드린 몇 개뿐이다.

## 4. 미배정 사유 진단 — 이 스펙의 본체

### 4-1. 왜 필요한가

현재 `unplaced[]`는 `{ sectionId, label, remaining }` 뿐이다(`solver.ts:84`). 화면에는 *"1학년 3반 수학 2시간 미배정"* 만 뜬다.

일과계 선생님이 이걸 받으면 **왜 안 들어갔는지를 처음부터 찾아야 한다.** 어느 교사가 꽉 찼는지, 특별실이 모자란지, 금지 슬롯이 과한지를 사람이 그리드를 뒤져 알아내야 한다. 컴시간이 "걸림돌 삭제 후 재배정"이라는 **수동 순환**을 시키는 이유가 그것이고, 우리가 그걸 그대로 물려받을 이유는 없다.

> 같은 문제를 결보강 쪽에서 이미 만났다 — 로드맵 §2 「징검다리 체인 탐색 실패 사유 표시」("이동 불가 지배 사유(특별실/구장 충돌) 반환"). **같은 처방을 여기에도 쓴다.**

### 4-2. 진단 방법 — 이미 있는 것을 세기만 하면 된다

배치 실패는 슬롯마다 이유가 있다. `tryPlaceWithEjection`이 이미 슬롯을 훑으며 그 이유를 계산하고 있다(`:642~657`) — **버리지 말고 집계한다.**

각 미배정 occurrence에 대해 **모든 후보 슬롯을 한 번 더 훑되, 배치하지 않고 사유만 센다**:

| 사유 코드 | 뜻 | 판정 근거 |
|---|---|---|
| `BANNED` | 금지·허용 슬롯 제한에 걸림 | `s.bannedSlots` / `s.allowedSlots` |
| `CLASS_BUSY` | 그 학급이 이미 다른 수업 | `classOcc` |
| `TEACHER_BUSY` | 담당 교사가 이미 다른 수업 | `teacherOcc` |
| `ROOM_BUSY` | 특별실 점유 | `roomOcc` |
| `FIXED_BLOCK` | 걸림돌이 고정 수업이라 못 밀어냄 | `sections[bi].kind === "fixed"` |
| `TOO_MANY_BLOCKERS` | 걸림돌이 3개 이상이라 ejection 대상 밖 | `blockerKeys.size > 2` |

**지배 사유(dominant reason)** = 전체 후보 슬롯 중 가장 많이 나온 코드. 이것 하나만 화면에 보인다.

```ts
unplaced: Array<{
  sectionId: string;
  label: string;
  remaining: number;
  reason: {
    code: "BANNED" | "CLASS_BUSY" | "TEACHER_BUSY" | "ROOM_BUSY" | "FIXED_BLOCK" | "TOO_MANY_BLOCKERS";
    ratio: number;              // 이 사유가 막은 슬롯 비율 (0~1)
    detail?: string;            // 교사명·특별실명 등 지목 대상 1개
    freeSlots: number;          // 사유 무관하게 비어 있던 슬롯 수 (0이면 구조적 과포화)
  };
}>
```

**비용**: 미배정 occurrence당 후보 슬롯 5×7 = 35회 검사. 미배정이 수십 건이어도 수천 회 — 이미 도는 솔버 안에서 무시할 수준이다. **미배정이 있을 때만** 돌린다(정상 해에는 비용 0).

### 4-3. 화면 문구 — 원인과 다음 행동을 같이 준다

**개발 용어를 쓰지 않는다**(`AGENTS.md` ui-copy-rules). 코드가 아니라 사람의 말로 바꿔서 보인다.

| 코드 | 화면 문구 (예) |
|---|---|
| `TEACHER_BUSY` | **김○○ 선생님 시간이 꽉 찼습니다.** 다른 수업을 옮기거나, 이 수업을 다른 선생님께 배정해 주세요. |
| `ROOM_BUSY` | **과학실이 그 시간에 모두 차 있습니다.** 다른 교실을 쓰거나 다른 요일로 옮겨 주세요. |
| `BANNED` | **넣을 수 있는 시간이 거의 없습니다.** 이 수업에 걸린 「수업 불가 시간」 설정을 확인해 주세요. |
| `FIXED_BLOCK` | **창체·SLAT처럼 고정된 시간에 막혀 있습니다.** 고정 시간을 옮기지 않으면 이 수업은 자동으로 못 넣습니다. |
| `TOO_MANY_BLOCKERS` | **한 칸을 비우려면 수업 세 개 이상을 밀어야 합니다.** 자동으로는 여기까지고, 직접 배정해 주세요. |
| `CLASS_BUSY` | **그 학급 시간표가 이미 꽉 찼습니다.** 주당 시수 설정을 확인해 주세요. |

`freeSlots === 0`이면 문구 앞에 한 줄 덧붙인다:
> **이 수업이 들어갈 수 있는 빈 시간이 아예 없습니다.** 시수나 제약 설정을 손대야 합니다.

### 4-4. 수동 조정 UI와의 연결

`phase9c_d_spec.md` §5의 미배정 목록에서 **[배정하기]** 를 누르면 배정 가능 슬롯이 하이라이트된다. 여기에 **사유 한 줄을 항목마다 붙인다.** 하이라이트가 0개일 때 지금은 아무 설명이 없는데, 그때가 바로 사유가 가장 필요한 순간이다.

## 5. 하지 않는 것

- **ejection 깊이·걸림돌 수 상향** — §2.
- **제약 자동 완화** — 솔버가 금지 슬롯이나 고정 수업을 스스로 풀지 않는다. 그건 실무 판단이고, 자동으로 풀면 **왜 이렇게 짜였는지 아무도 모르는 시간표**가 나온다.
- **사유의 다중 표시** — 지배 사유 1개만. 여러 개를 늘어놓으면 읽지 않는다.
- **완전 탐색(백트래킹 전면 도입)** — 브라우저 워커에서 30학급 규모를 완전 탐색하는 것은 현실적이지 않고, §2의 이유로 이득도 작다.
