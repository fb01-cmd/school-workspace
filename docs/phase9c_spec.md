# Phase 9c — 기초시간표 자동 작성 스펙 v1 (2026-08-11)

> **시한**: 검증 완료 11월 말 (컴시간 재계약 결판 2026-12 — 킬 스위치).
> **완전 대체 조건**: 생성만으로는 부족 — ①자동 생성 ②검증 ③수동 미세조정 ④NEIS 일괄 내보내기 네 축이 모두 있어야 컴시간을 끊을 수 있다 ([`9c_research_notes.md`](./9c_research_notes.md) §2).
> **원천**: `archive/주간시간표설명서.pdf` §6(특별작업)·§7(배정검색)·§8(배정교시 이동)·§9(엑셀 인쇄)·§10(NEIS 업로드) 정독 완료(2026-08-11). 이하 "매뉴얼 §n"으로 인용.

## 0. 설계 원칙

1. **탐색은 로직, 판단은 AI** (2026-08-11 사용자 발상 + Claude 경계 설계, 로드맵 §2): 배치·탐색은 결정론 솔버, LLM은 선호 정식화·불능 진단·결과 설명·정성 비평 4역할. **AI 출력은 결정론 검사기를 통과해야만 시간표에 반영**.
2. **검사기 먼저, 솔버 나중**: 컴시간의 실무 순서(자동 작성 → 배정검색으로 문제 확인·조정)와 동일. 검사기는 현행 2026-2 실시간표(컴시간 산출물)로 즉시 검증 가능 — 솔버 없이도 단독 가치(수동 편성 검증 도구).
3. **무료·로컬**: 솔버는 브라우저(Web Worker)에서 실행 — 서버리스 시간 제한·비용 회피, 외부 유료 솔버 금지.
4. **기존 자산 재사용**: 시수표=가져오기 파서 구조, 동시수업=SimulGroup, 특별실=VenueGroup(slots 포함), 요일별 교시수=computeDayPeriodCounts, 소프트 감점=teacherDayPenalties 계열, 연쇄이동 UI=chain_search 개념.

## 1. 컴시간 워크플로 요약 (매뉴얼 실독 — 재현 대상)

기초자료(시수표·요일별 시수·일과시간) → 시간표 작성하기(정합성 검사+초기화) → **특별작업 6종 입력** → 부분 자동배정(연속→동시→특별실 각각 자동배정 버튼) → 자동 시간표작성 → **배정검색**([자동 조정하여라] 반복 → 수동 조정 반복) → 배정교시 이동(수동 미세조정) → 엑셀 인쇄·NEIS 일괄파일.

## 2. 입력 데이터 모델

### 2-1. 시수표 (teacher × subject × class → 주당 시수)

- 구조는 우리 가져오기 파서가 소화하는 교사별 시수표 엑셀과 동형 (매뉴얼 §5 시수표 등록부).
- **획득 경로 2개**: ⓐ 현행 2026-2 기초시간표에서 **역산**(그리드 → 시수 카운트) — 검증 단계의 기본 경로 ⓑ 신학기용 신규 입력 UI(엑셀 업로드 재사용).
- 정합성 검사(매뉴얼 §5-사): 학년별 "요일별 시수 합 = 시수표 합" 일치 / 복수교사([*] 과목)는 동일 학급 2교사·시수 동일.

### 2-2. 기본사항

- **요일별 교시수**: 학년×요일 (기존 주 운영 periodsByGrade 개념 + 기초시간표 실측 computeDayPeriodCounts). 수집 20에서 확립한 "week.days가 비면 기초시간표가 진실" 원칙 유지.
- **일과시간·점심**: settings.lunchAfterPeriod 재사용 (매뉴얼의 학년별 "N교시 후 점심"과 동형 — 학년별 차등은 필요 시 확장).
- 가상학급수(동시수업 확장 학급) 개념은 그룹 모델로 흡수 — 별도 입력 불요.

### 2-3. 제약 등록부 6종 (매뉴얼 §6 = 제약 모델 원형)

| 컴시간 특별작업 | 플랫폼 대응 | 상태 |
|---|---|---|
| ① 이동금지/배정금지(특별교사) | **신규** `teacherSlotBans`: 교사별 (요일,교시) 금지 집합 + 요일 전체/교시 전체 토글. 이동금지(솔버가 옮기지 못함)와 배정금지(아예 배정 불가) 2속성 구분 | 신규 UI·모델 |
| ② 일괄 배정 | **신규** `fixedBlocks`: (요일,교시)에 여러 학급 고정 배치(창체·SLAT·재량). 배정된 교사는 자동 이동금지(매뉴얼 규칙). §4-1b의 SLAT·창체 로테이션 = 이 등록부의 실데이터 | 신규(개념은 기구현 블록 교사) |
| ③ 연속수업 | **신규** `consecutiveRules`: (학년,과목,교사,시수) → 연속 패턴 `"2"`, `"2,2"`, `"3"`, `"4,4"` 등 콤마 표기(매뉴얼 §6-라 계승) | 신규 |
| ④ 동시수업 | **SimulGroup 재사용+확장**: 그룹 = 같은 교시에 묶이는 (반,교사,과목) 집합. 시수 다르면 작은 쪽 기준 등록·잔여는 별도 그룹(매뉴얼 규칙). 연속+동시는 그룹에 연속시수 필드 | 기구현(확장) |
| ⑤ 특별실 | **VenueGroup 재사용**: roomName 단위 용량 1, slots 특정(과탐 실험) 포함. 특별실+연속은 여기에 연속 필드(매뉴얼 §6-바: 등록부에 연속 셀) | 기구현(연속 필드만 확장) |
| ⑥ 복수교사 | **신규** `coTeaching`: 동일 학급·동일 슬롯 2교사, 시수 동일 강제 | 신규 |

**제약 소유 우선순위(매뉴얼 명시 규칙 계승)**: 연속수업이 동시수업이면 동시 등록부가, 특별실이면 특별실 등록부가 연속 속성을 소유한다. 솔버·검사기의 속성 해석은 단일 소유자 기준(이중 등재 금지 — 컴시간도 "비고란에 연속·동시·특별 등록 원본이 있으면 등록 불가"로 막음).

## 3. Phase A — 검사기 (배정검색의 재현, 매뉴얼 §7)

순수 함수 `validateTimetable(grids, model) → { hard: Violation[], soft: PenaltyReport }`. **솔버·AI·수동 편집 모두 이 관문을 통과해야 한다** (§0-1 철칙).

### 3-1. 하드 위반 (컴시간 "중대한 문제 = 이동 실행 비활성" 대응)

H1 미배정 시수 (시수표 대비 부족) / H2 교사 동시 2곳 배정 / H3 학급 슬롯 중복(같은 요일 같은 학급 이중 배정) / H4 시수 초과 배정 / H5 배정금지·이동금지 교시 위반 / H6 일괄 배정 고정 위반 / H7 동시수업 그룹 동시성 위반(그룹 전원이 같은 슬롯 아님) / H8 특별실 초과 점유(용량 1) / H9 연속수업 패턴 위반 / H10 복수교사 동시성·시수 불일치 / H11 미편성 교시(요일별 교시수 밖) 배정.

### 3-2. 소프트 감점 (컴시간 검색조건 + 기존 감점 엔진의 합류)

기존 `teacherDayPenalties`(요일 쏠림 5h+·연속 3h+·점심 전후 — 이미 가중치제·실전 검증됨)를 학기 전체로 일반화하고, 매뉴얼 §7·§8 문제점 항목에서 다음을 추가:

S1 요일 시수 쏠림(기존) / S2 연속 3·4·5시간(기존, 길이 비례) / S3 점심 전후 연속(기존) / S4 같은 요일 동일 과목 중복(같은 학급에 같은 과목 2회 — 분산 선호, 기존 classDuplicatePenalty) / S5 교사 기준 같은 요일 3과목 이상(매뉴얼 "학년" 항목) / S6 오전/오후 균형(매뉴얼 "오후") / S7 순배 — 1~4반 등 반 순회 배정 회전(매뉴얼 "순배", 우선순위 낮음 — 실효 검증 후).

각 감점은 (scope, text, points) 구조 유지 — 수집 18(점수 병기)·21(3인칭 라벨) 규약 그대로.

### 3-3. 검증 전략 (이 단계의 핵심 실험)

**현행 2026-2 실시간표를 검사기에 통과시킨다.**
- 하드 위반 = 0이어야 정상. 위반이 나오면 **우리 제약 모델이 틀렸거나 등록부 데이터가 불완전한 것** — 컴시간 산출물이 그라운드 트루스.
- 소프트 총점 = **컴시간 품질 기준선**. 이후 솔버 산출물이 이길 목표치가 된다 (정량 비교 근거).
- 부산물: 등록부 미비(특별교사 금지·연속수업 등 아직 없는 데이터)가 하드 위반으로 드러나면 그것이 곧 9월 질문지의 문항이 된다.

### 3-4. 문제점만 검색 (매뉴얼 §7-(7) 계승 — 눈높이 원칙)

"어쩔 수 없는 것까지 다 보여주면 작성자 머리가 아프다" — 검사기 리포트는 기본 **실행 가능한 문제만** 노출하고 전체는 접힘. AI 불능 진단(Phase E)의 입력이 이 리포트.

## 4. Phase B — 역산·기준선

1. 2026-2 그리드 → 시수표 역산기 (2-1ⓐ).
2. 검사기로 하드 0 확인(3-3) → 소프트 기준선 기록.
3. 이 시점에 **검사기 단독 출시 가능**: 일과계의 수동 편성·기초 개정(§E revision) 검증 도구로 즉시 실용 — 솔버 실패 시에도 건지는 가치(리스크 헷지).

## 5. Phase C — 솔버 코어

- **실행**: 브라우저 Web Worker (UI 비블로킹, 진행률 스트림). 30학급×주 34교시 규모 — 로컬 CPU로 충분.
- **배치 순서 (컴시간 부분 자동배정 순서 계승)**: ① 일괄 배정·배정금지 선반영(고정) ② 동시수업 그룹(가장 경직 — 매뉴얼 "모의실행" 대응으로 그룹 경우수 사전 카운트, 임계 미달 시 배치 전 경고) ③ 특별실 ④ 연속수업 블록 ⑤ 일반 시수 — 백트래킹 + MRV(잔여 후보 최소 슬롯 우선) ⑥ 미배정 잔여 — ejection chain(매뉴얼 §8-라 "걸림돌 배정을 삭제해 다른 곳으로 옮기고 재배정"의 자동화 = 기존 chain_search 사고방식) ⑦ 국소 탐색으로 소프트 점수 개선(컴시간 [자동 조정하여라] 반복 대응) — 시간 예산제(예: 60초)·개선 없으면 조기 종료.
- **결정론**: 시드 고정 — 같은 입력 = 같은 출력(재현성·디버깅·검사기와 함께 신뢰의 근거).
- **산출**: 완성 그리드 + 검사기 리포트 + 미배정 잔여 목록(있다면). 미배정은 실패가 아니라 수동 조정 대상(컴시간도 동일).

## 6. Phase D — 수동 조정 UI (배정교시 이동의 재현, 매뉴얼 §8 — Antigravity)

- 교사 시간표 + 학급 시간표 + 미배정 목록 3면 구성(컴시간 6패널의 현대화 — 기존 직권 배정 UI 문법 재사용).
- 셀 이동 시 **연쇄 영향 미리보기**: 영향 교사별 하드/소프트 문제 목록(매뉴얼 §8-다 "연쇄 이동시 문제점" 다이얼로그) — 하드 문제면 실행 차단, 소프트면 감점 표시 후 진행 허용. 판정은 전부 Phase A 검사기 호출.
- 색 의미론은 기존 색 일람표(U8)에 통합 — 배정가능/이동전/이동후/중복/속성 (컴시간 색 문법 계승하되 경고 red 전용 원칙 유지).
- **작업기록**: 조정마다 스냅샷 자동 저장 + 복원(매뉴얼 [작업기록 열람]) — 시간표 draft 문서의 버전 배열로.

## 7. Phase E — AI 보조층 (로드맵 §2 확정 경계)
