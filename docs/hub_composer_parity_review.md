## 🔴 결함 1 (데이터 유실) — A-9는 뒷문만 잠갔다

**주 전환 수단인 상단 띠 버튼이 확인창을 통째로 우회한다.**

`MessagingHub.tsx:285`·`:297`
```
onClick={() => setActiveComposer("task")}    // 확인창 없음
onClick={() => setActiveComposer("memo")}    // 제목·본문 인계 없음
```

이 두 버튼은 `handleSwitchToMemo`/`handleSwitchToTask`(`:175-187`)를 **거치지 않는다.** 결과가 작성기 안 버튼보다 더 나쁘다:

- 새로 붙인 `window.confirm`이 **한 번도 뜨지 않는다**
- `setSharedTitle`/`setSharedBody`를 안 부르므로 **제목·본문까지 통째로 증발**한다 (작성기 안 버튼은 최소한 인계는 한다)

**상단 띠는 사람을 담으면 항상 보이는 자리**다. 작성기 안의 「쪽지로 바꾸기」보다 여기를 먼저 누른다. 즉 **고친 경로가 덜 쓰이는 쪽이다.**

> 이 구멍 자체는 이번 배치가 만든 게 아니다(전부터 그랬다). 하지만 A-2·A-6로 **첨부가 이제 실물**이 됐기 때문에 잃는 것이 커졌고, A-9가 지목한 문제가 바로 이것이다.

**지시**: 상단 띠 버튼 2개도 **같은 경로를 타게** 한다.

- 작성기가 `hasDraftRef`를 동기화하듯, **현재 제목·본문을 담은 ref를 부모와 공유**한다(같은 패턴이라 새 개념이 없다)
- 상단 띠 버튼은 그 값을 읽어 `handleSwitchToMemo`/`handleSwitchToTask`를 부른다 → 확인창과 인계가 자동으로 따라온다
- **확인창을 두 번 띄우지 마라.** 작성기 안 버튼과 상단 띠 버튼이 같은 함수를 타면 확인은 한 곳에서만 일어난다

**확인 방법**: 쪽지를 쓰다가(제목+본문+첨부 1개) **상단 띠의 [업무 등록]** 을 누른다 → 확인창이 뜨고, 계속하면 제목·본문이 업무 폼에 그대로 넘어간다.

## 🔴 결함 2 (데이터 유실) — 첨부만 있으면 경고가 안 뜬다

`HubMemoComposer.tsx:60-61`
```
hasDraftRef.current = !!(title.trim() || body.trim());   // 첨부를 안 센다
```

**경로 ⓐ**: 파일만 5개 올려 둔 상태(제목·본문 비어 있음)에서 [비우기] → `MessagingHub.tsx:148`의 확인창이 **건너뛰어지고** 작성기가 사라지면서 **이미 Drive에 올라간 첨부가 날아간다.**

**경로 ⓑ (더 나쁘다)**: 상단 칩의 ✕로 **마지막 수신자를 지우면** — `handleRemoveEmail`(`:166-172`)에는 **가드가 아예 없다.** 담긴 사람이 0이 되면 보내는 화면에서 빠지고 작성기가 사라진다. **제목·본문·첨부 전부, 확인창 하나 없이.**

**지시**:
1. `hasDraftRef` 판정에 **첨부(그리고 업무 쪽 양식 파일)를 포함**한다
2. `handleRemoveEmail`에도 같은 가드를 건다 — **단, 마지막 한 명을 지워 0이 될 때만.** 여러 명 중 하나를 빼는 것은 흔한 조작이라 매번 확인창이 뜨면 안 된다
3. 확인 문구는 상황에 맞게 — 첨부만 있을 때 *"작성 중인 내용"* 은 어색하다

## 🟠 결함 3 — 전환하면 본문이 없는 파일을 가리킨다 (새 결함)

인라인 이미지는 본문에 `![…](att:<파일id>)` 형태로 직렬화된다(`richtext_dom.ts:96`). 그런데 전환 시 **첨부는 버리면서 본문은 그대로 넘긴다**(`HubMemoComposer.tsx:458-459`).

결과: 업무 본문이 **그 업무에 붙어 있지도 않은 파일을 가리킨다.** 받는 사람 화면에서 깨진 이미지가 되거나, 권한이 없어 안 보인다.

**지시**: 전환 시 본문에서 `att:` 참조를 **제거하거나**, 확인 문구에 *"본문에 넣은 이미지는 함께 넘어가지 않습니다"* 를 명시한다. 어느 쪽이든 **깨진 참조가 발송되지 않게** 한다.

## 🟠 결함 4 — 전환 후 편집기에 `**굵게**` 같은 기호가 그대로 보인다

`HubMemoComposer.tsx:75-79`·`HubTaskComposer.tsx:86-90`이 `editorRef.current.innerText = initialBody`로 넣는데, `initialBody`는 **저장 형식(md1) 문자열**이다.

전부터 있던 문제지만 A-4 전에는 대개 평문이라 티가 안 났다. 이제 전환하면 `![붙여넣은 이미지.png](att:1a2b…)`·`**굵게**`가 **글자 그대로** 보인다.

**지시**: md1을 편집기 DOM으로 되돌리는 경로를 쓴다(플랫폼에 이미 렌더 경로가 있다). 없으면 최소한 **서식 기호를 벗긴 평문**으로 넣는다.
