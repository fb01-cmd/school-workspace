# Phase 9c-D — 수동 조정 UI 스펙 v1 (2026-08-11)

> 상위: [`phase9c_spec.md`](./phase9c_spec.md) §6 (배정교시 이동의 재현, 매뉴얼 §8).
> 전제 자산: Phase A 검사기(`validateTimetable` — 순수·클라 실행 가능) / Phase C 솔버(`solverClient.solveTimetableInWorker` — 워커 안에서 관문까지 완료) / 기초 개정 op 모델(`BaseRevisionOp` + `applyRevisionOps` 순수 함수, server.ts:2115) / 직권 배정 UI 문법 / U8 색 일람표.
> **철칙(§0-1)**: 솔버·AI·수동 편집 전부 검사기 관문 통과로만 시간표에 반영. 이 화면의 모든 판정은 `validateTimetable` 하나로 한다 — 별도 판정 로직 신설 금지.

## 1. 목표·범위

- 솔버 산출물(또는 현행 복제본)을 **작성본(draft)** 으로 저장하고, 셀 이동·맞교환·미배정 배정을 반복해 하드 0 완성본을 만드는 화면.
- 컴시간 §8의 재현: 연쇄 영향 미리보기(§8-다 다이얼로그) · **중대 문제 시 이동 실행 비활성**(하드 차단) · 작업기록 스냅샷 undo(§8 [작업기록 열람]) · 미배정 수동 순환(§8-라).
- 범위 밖: NEIS 내보내기(Phase F), AI 보조(Phase E), 신학기 시수표 직접 입력(C-2).

## 2. 작성본 저장 모델 (9c 스펙 §11 미결 → 여기서 확정)

**별도 컬렉션 채택** (draft 학기 방식 기각 — 학기 목록 오염·시드 비교용 다중 초안 불가·활성화 사고 위험).

```
timetable_drafts/{domain}/drafts/{draftId}            ← 메타 문서
  label, sourceTermId,                                 // "2026-2" — 제약 모델(등록부)은 이 학기 것을 로드
  origin: { kind: "solver"|"copy", seed?, ranking? },  // 출처 기록 (솔버면 시드·포트폴리오 순위)
  ops: BaseRevisionOp[],                               // 작업기록 = 조정 연산 로그 (기존 타입 재사용)
  opCursor: number,                                    // undo/redo 위치 — 현재 그리드 = base + ops[0..opCursor)
  unplaced: [...],                                     // 솔버 미배정 잔여 (배정 시 목록에서 제거)
  lastReport: { hardCount, actionableHard, softTotal } // 마지막 검증 요약 (목록 카드 표시용)
  createdBy/At, updatedBy/At
timetable_drafts/{domain}/drafts/{draftId}/classGrids/{grade}-{classNum}   ← base 그리드 (학기 classGrids와 문서 동형 — 로더 재사용)
```

- **현재 그리드는 저장하지 않는다** — base + `applyRevisionOps(base, ops.slice(0, opCursor))` 재생으로 항상 재구성(결정론·저장량 최소). 스냅샷 열람 = ops 슬라이스 재생.
- undo = opCursor−1, redo = opCursor+1. cursor 뒤가 있는 상태에서 새 op 추가 시 뒤를 truncate(분기 금지).
- ops 500건 도달 시 경고 + base로 압착(flatten) 버튼 제공(압착 = 현재 그리드를 새 base로 저장, ops 비움 — 작업기록 소실 경고 표시).
- 문서 크기: 메타(ops)·classGrids 각각 1MB 한도와 무관한 수준(op 1건 ≈ 100B).

## 3. IA — 배치 명시 (Phase 5.8 교훈)

- **관리자 대시보드 → 시간표 섹션(TimetableSection) → 새 탭 "🧩 자동 작성"** (기존 탭 열 끝에 추가). 권한: 기존 manage 게이트 그대로(일과계 관리자·super_admin — authz 기본 거부라 신규 액션 추가만으로 자동 적용).
- 탭 안 2단계: ① **초안 목록** 화면(카드: label·출처(시드)·하드/소프트 요약·수정 시각·[열기]/[삭제]) + [🤖 자동 작성 실행]/[현행 복제로 시작] 버튼 ② **초안 편집** 화면(아래 3면).
- 다른 화면(기초 개정 탭 등)과 교차 진입 없음 — v1은 이 탭 안에서 완결.

## 4. 초안 편집 3면 (컴시간 6패널의 현대화)

```
┌─ 상단 바: 초안명 · 하드 N(빨강)/소프트 M점(호박) 실시간 배지 · [↩ 실행취소][↪ 다시실행] · [작업기록] ─┐
│ ┌── 좌: 학급 그리드 ──────────────┐  ┌── 우: 교사 그리드 ──────────────┐ │
│ │ 학년·반 선택 → 주 34슬롯 표     │  │ 교사 선택(자동완성) → 주 시간표  │ │
│ │ (셀: 과목·교사 약칭)            │  │ (draft 그리드에서 클라 파생)     │ │
│ └────────────────────────────────┘  └────────────────────────────────┘ │
│ ┌─ 하단: 미배정 목록 (섹션 라벨 · 잔여 시간 · [배정하기]) ────────────────┐ │
└──────────────────────────────────────────────────────────────────────┘
```

- 교사 그리드는 draft 그리드에서 **클라이언트 파생**(synthesize 로직 계승) — 추가 읽기 0. 좌우는 같은 상태의 두 뷰: 좌측 셀 선택 시 우측이 그 교사로 전환.
- 미배정 목록: draft.unplaced 표시. [배정하기] → 좌측 그리드에 배정 가능 슬롯 하이라이트 → 슬롯 클릭 = edit_cell op + unplaced 차감.

## 5. 이동·교환 UX (매뉴얼 §8-다 연쇄 미리보기)

1. 셀 A 클릭(선택) → 같은 학급 전 슬롯을 **후보 채색**: what-if로 `validateTimetable`을 돌려 ⓐ 이동/교환해도 하드 무변 = 배정가능색 ⓑ 하드 발생 = 불가(채색 없음·클릭 시 사유 토스트) ⓒ 빈 슬롯 vs 점유 슬롯(맞교환)은 아이콘으로 구분.
2. 후보 슬롯 B 클릭 → **연쇄 영향 다이얼로그**: 관련 교사별 하드 문제(있으면 [실행] 비활성 — 컴시간 "중대 문제" 계승) / 소프트 delta 목록((scope,text,points) 규약·점수 병기) / [적용].
3. 적용 = op 생성(빈 슬롯 = swap(a,b) — 기존 타입이 빈 슬롯 허용 = 이동 / 점유 = swap 맞교환 / 미배정 배정·셀 편집 = edit_cell) → 서버 `draft_op`.
4. **판정 이중화**: 미리보기는 클라에서 순수 검사기 실행(1020수업 전체 재검 수 ms — 충분히 빠름, 실측 후 느리면 학급·교사 표적 재검으로 최적화), 서버 `draft_op`가 **같은 검사기로 최종 재검증** — 하드 신규 발생 시 409 거부(UI 신뢰 금지 규칙). 소프트는 서버가 차단하지 않는다.
- what-if 제약 모델: 편집 진입 시 등록부(동시·특별실·금지·연속·복수) 1회 로드 → 클라 보관. 등록부 판정(simul 하드 제외 등)도 검사기가 이미 품고 있으므로 별도 분기 불요.

## 7. API (manage 라우트 확장 — authz 기본 거부로 관리자 전용 자동)

`draft_list` / `draft_create`(body: origin, label, grids?(솔버 산출 — 페이로드 수백 KB, 4.5MB 한도 내), 현행 복제면 서버가 로드) / `draft_get`(메타+base+재생 그리드+검증 리포트) / `draft_op`(op 1건 적용: 재생→검사→하드 신규 발생 시 409→저장+lastReport 갱신) / `draft_undo` · `draft_redo` / `draft_rename` / `draft_delete`. 감사 로그·캐시 규약은 등록부 CRUD와 동일.

- **재사용 강제**: op 적용은 `applyRevisionOps`, 판정은 `validateTimetable` — 서버에 별도 구현 금지. **단일 소재지는 utils.ts**(클라·서버 공용, 2026-08-11 이관) — server.ts는 utils에서 import만 하고 자체 사본을 두지 않는다.
- 제약 모델 로드는 기존 로더 5종(`load*`) + `deriveGradeDayPeriods`.
- **시수 기준 = 초안 메타의 `hoursSnapshot`** (v1.1 정정, 2026-08-11 D-2 리뷰): base 그리드 역산은 미배정 있는 솔버 초안에서 "미배정 배정"을 H4 초과로 오판해 409로 차단하는 결함이 있다. `draft_create` 시 서버가 **sourceTermId 현행 학기 기초 그리드에서 역산한 시수표를 `hoursSnapshot`으로 저장**(클라 전송 신뢰 금지 — 관문 기준이므로 서버 산출만)하고, draft_op·undo·redo·draft_get의 모델은 `hoursSnapshot ?? deriveHoursFromGrids(base)`(구초안 폴백)를 쓴다. draft_get 응답에 hours를 동봉해 클라 미리보기도 같은 기준을 쓴다.
- 승격(promote)은 v1 범위 밖(Phase F에서 NEIS 내보내기와 함께 — 하드 0 필수 조건만 여기 명시).
