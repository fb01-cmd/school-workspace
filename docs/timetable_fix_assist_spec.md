# 시간표 초안 — 위반 상세 조회 · 해결안 제시 스펙 v1 (2026-08-12)

> 상위: [`phase9c_spec.md`](./phase9c_spec.md) §3 검사기 · [`phase9c_e_spec.md`](./phase9c_e_spec.md) AI 보조층
> 계기: 2026-08-12 AI 3종 실기기 확인 중 사용자 신고 3건.

## 0. 배경 — 사용자가 지적한 3가지

1. **"하드 위반 0건 · 소프트 39점"이 숫자뿐이라 내용을 볼 수 없다.** 뭐가 문제인지 알아야 조치를 한다.
2. **AI가 분석까지만 한다.** "김한별 화2와 김동연 수3을 교환하면 해결됩니다" 수준의 **구체적 대안**과 **변경 전/후 확인**이 있어야 의미가 있다.
3. **SLAT 수업이 맞교환 대상이 됐다.** (2학년 5반 목1교시 체Ⅱ ↔ 수6교시 SL 이 "중대 문제 없음"으로 통과)

→ 3번은 개선이 아니라 결함이므로 **당일 수정 완료(§3)**. 1·2번을 F-1·F-2로 정의한다.

## 1. F-1 — 위반·감점 상세 조회

### 1-1. 전제: 데이터는 이미 다 있다

`openDraft.report`(`TimetableAuditReport`)가 **이미 브라우저 메모리에 통째로 있다** — `DraftAutoTab.tsx`가 `validateTimetable(currentGrids, fullModel)`을 직접 실행해 만든다. 서버 왕복도, 새 API도 필요 없다.

- `report.hard[]` → `code` `text`(완성 문장) `hint` `grade` `classNum` `day` `period` `teacherName` `subjectName` `registryGap`
- `report.soft.details[]` → `code` `scope` `key` `label` `day` `text` `points` (점수 내림차순 정렬됨)
- `report.soft.byCode` / `report.summary.hardByCode` / `summary.actionableHard`

**현재 이 셋을 렌더링하는 컴포넌트가 저장소에 하나도 없다.** 배지 숫자·셀 빨간칠·AI 버튼 노출 조건으로만 소비된다. F-1은 순수 UI 작업이다.

### 1-2. 화면

배지 "하드 위반 N건"·"소프트 N점"을 **클릭 가능**하게 하고, AI 카드와 같은 자리·같은 접이식 패턴으로 상세 패널을 연다(카드 스타일은 기존 `이 시간표 설명` 카드 재사용).

**하드 위반 패널**
- 코드별 그룹(H1~H11), 그룹 헤더에 `hardByCode` 소계
- 항목 = `text` 한 줄 + `hint` 있으면 회색 보조 줄
- `grade`·`classNum`·`day`·`period`가 있으면 `2-5반 목 1교시` 칩 → **클릭 시 해당 학년·반 그리드로 이동 + 셀 강조**(기존 `viewGrade`/`viewClass` 상태 전환)
- `registryGap: true` 항목은 **"등록부 미비로 추정 (N건)"** 접힌 섹션으로 분리 — 스펙 §3-4의 "어쩔 수 없는 것까지 다 보여주면 머리가 아프다" 원칙

**소프트 감점 패널**
- 코드별 그룹(S1~S6), 헤더 = 눈높이 라벨 + `byCode` 소계 점수
- 항목 = `label` · 요일 · `text` · `−N점`, 점수 내림차순
- 각 항목 우측에 **[해결안 찾기]** 버튼 → F-2 진입점

### 1-3. 같이 고칠 결함

- **셀 빨간 강조의 사각지대**: 강조 조건이 `grade·classNum·day·period` 4개 일치라, 좌표가 비는 위반은 화면 어디에도 안 뜬다 — H8(특별실 초과: `day`·`period`만), H9(연속수업: `grade`·`classNum`만). 상세 목록이 생기면 최소한 목록에는 보인다. 강조 조건도 **있는 좌표만 대조**하도록 완화할 것.
- **라벨 테이블 위치**: `SOFT_CODE_LABELS`가 `ai.ts`에 있다. 화면에서 쓰려고 `ai.ts`를 import하면 Gemini 호출 코드가 클라이언트 번들에 딸려 들어온다. → **`types.ts` 또는 새 `labels.ts`로 옮기고 `ai.ts`가 그것을 import**하도록 뒤집을 것. 하드 코드(H1~H11) 라벨 테이블도 같은 곳에 신설(현재 존재하지 않고 주석만 있음).

## 2. F-2 — 해결안 후보 탐색

### 2-1. 판단: AI에게 교환안을 만들게 하지 않는다

**AI 제안 방식은 채택하지 않는다.** 근거 3가지:

1. **AI는 그리드 전문을 못 본다.** 현재 AI에 가는 것은 요약(감점 상세 40건·교사 부하 80명)뿐이고, 앞으로도 전문을 보낼 계획이 없다(PII·토큰). 실재하지 않는 교환을 지어낸다 — `8d7f963`의 "SLAT 선생님 주 60시간" 오진과 같은 실패 계열이다.
2. **AI는 자기 제안을 검증할 수 없다.** 어떤 교환이 새 하드 위반을 만드는지 모른다. 검사기만 안다.
3. **무료 등급 하루 20회.** 제안 하나 얻자고 한도를 태울 이유가 없다.

대신 **결정론적 후보 탐색기**를 만든다. 검사기가 진실의 원본이므로, 후보를 만들고 검사기로 채점하면 결과가 **검증된 사실**이 된다. AI 호출 0회.

### 2-2. 이미 있는 것 — 절반은 완성돼 있다

`analyzeOpImpact`(`DraftAutoTab.tsx`)가 이미 op 하나에 대해:
`baseGrids 복제 → 기존 ops 재생 → op 추가 → validateTimetable → 신규 하드 추출 → 소프트 총점 델타`
를 클라이언트에서 동기 수행하고, 연쇄 영향 모달이 **전/후 점수와 신규 하드를 보여주며 하드 발생 시 적용 버튼을 잠근다**. 즉 요구 2번의 "변경 전/후 확인"은 이미 있다.

**없는 것은 후보 탐색뿐이다.** 지금은 사람이 두 셀을 찍어야만 평가가 돌아간다.

### 2-3. 엔진 계약

새 순수 모듈 `src/lib/timetable/fixFinder.ts` (Firestore 무의존, 검사기와 동일 규약):

```ts
export interface FixCandidate {
  op: BaseRevisionOp;          // 항상 type:"swap" (v1)
  desc: string;                // "2학년 5반 화요일 2교시(수학Ⅰ·김○○) ↔ 수요일 3교시(영어·이○○)"
  oldSoftTotal: number;
  newSoftTotal: number;
  deltaScore: number;          // 음수 = 개선
  resolvesTarget: boolean;     // 지목한 감점 항목이 사라졌는가
  sideEffects: string[];       // 새로 생기거나 커진 다른 감점 문장 (최대 3건)
}

export function findFixCandidates(params: {
  baseGrids: ClassGrid[];
  ops: BaseRevisionOp[];       // meta.ops.slice(0, opCursor)
  currentGrids: ClassGrid[];
  model: TimetableConstraintModel;
  target: TermPenaltyDetail;   // F-1 목록에서 사용자가 지목한 감점 한 건
  maxCandidates?: number;      // 기본 300 — 평가 상한
  maxResults?: number;         // 기본 5
}): FixCandidate[];
```

**후보 생성 규칙** (감점 코드별 — 원인 셀만 후보로 좁힌다. 전역 탐색은 비용상 금지)

| 코드 | 원인 셀(source) | 목적지(target) |
|---|---|---|
| S1 요일 쏠림 | `target.key` 교사의 `target.day` 수업 셀 전부 | 같은 학급의 **다른 요일** 모든 슬롯 |
| S2 연속 3교시 | 그 교사·그 요일 연속 블록의 **양 끝** 셀 | 같은 학급의 다른 슬롯 |
| S3 점심 전후 | 그 교사·그 요일의 `lunchAfterPeriod`·`+1` 셀 | 같은 학급의 다른 슬롯 |
| S5 하루 3과목 | 그 교사·그 요일 수업 셀 전부 | 같은 학급의 다른 요일 슬롯 |
| S4 같은 반 동일 과목 중복 | `target.key` 학급의 그 요일 중복 과목 셀(첫 건 제외) | 같은 학급의 다른 요일 슬롯 |

**공통 제외** — source·target 양쪽 모두에 적용:
- `checkPlaceholderOp`으로 걸리는 셀(창체·SLAT 자리표시) — §3에서 만든 함수 **그대로 재사용**
- 동시수업(simul) 셀 — `buildSimulMatcher` 판정, 기존 `handleCellClick`과 같은 기준
- source와 target이 같은 슬롯

**채점·정렬**
1. op 적용 후 `validateTimetable` 재실행
2. **신규 하드가 하나라도 있으면 버린다** (판정 키는 `applyDraftOp`과 동일한 문자열 조립을 쓸 것 — 중복 구현 말고 헬퍼로 뽑아 공유)
3. `deltaScore >= 0`이면 버린다 (개선 없는 안은 보여주지 않는다)
4. `deltaScore` 오름차순(개선 큰 순) → 동점이면 `resolvesTarget` 우선
5. 상위 `maxResults`건 반환

**미편성 교시로 옮기는 안은 자동으로 걸러진다** — H11이 발생해 2번에서 탈락한다. 별도 처리 불필요.

### 2-4. 비용 — 반드시 실측할 것

평가 1회 = `cloneClassGrids`(30개 학급) + ops 재생 + `validateTimetable` 전체. 300회면 UI 스레드가 수 초 멈출 수 있다.

**착수 순서**: ① 먼저 평가 1회의 실제 소요를 측정한다(`performance.now()`, 실제 30학급 초안). ② 300회 예상이 **1초 미만**이면 동기 실행. ③ 넘으면 청크 분할(`requestIdleCallback`/50건마다 yield) + 진행률 표시. ④ 그래도 넘치면 `maxCandidates`를 낮춘다 — **서버로 옮기지 말 것**(서버는 같은 계산을 하고 왕복만 늘어난다).

측정값은 `project_notes.md`에 기록한다.

## 3. F-3 — 자리표시(창체·SLAT) 셀 보호 ✅ 완료 (2026-08-12, Claude)

**원인**: 이 저장소의 "이메일 없음 = 가상 교사" 규약이 검사기·솔버·(8d7f963 이후) AI 층에는 적용됐는데 **편집 경로에는 없었다.** 편집 가드는 동시수업(simul) 판정 하나뿐이라, 등록부에 동시수업으로 올라 있지 않은 SL·창체는 자유롭게 이동·맞교환됐다. 검사기도 못 잡는다 — 가상 교사는 H2(교사 중복) 대상이 아니고, 등록부에 없으면 H6·H7도 안 걸린다.

**수정**: `validate.ts`에 규약 단일 소재지 신설 — `isAllVirtual` export화, `findPlaceholderLesson`, `checkPlaceholderOp`. 이를 세 관문에 연결:
- `DraftAutoTab.handleCellClick` Case 3 — 소스 셀 선택 시점에 알림(목적지 클릭까지 기다리지 않음)
- `DraftAutoTab.analyzeOpImpact` — **모든 편집이 거치는 클라이언트 단일 관문**(이동·맞교환·미배정 배정 전부)
- `server.applyDraftOp` — 최종 관문(클라 우회 방지), `DraftOpConflictError`

**과거 연산 재생(`applyRevisionOps`)에는 걸지 않았다** — 이미 저장된 초안이 재생 불가가 되면 안 된다. 가드는 연산이 새로 만들어지거나 접수되는 지점에만 있다.

**남은 구멍(후속)**: 기초시간표 개정 탭(`BaseRevisionTab` → `saveRevisionDraft`)은 아직 이 가드를 타지 않는다. 해당 경로는 `latestBase` 그리드를 이미 들고 있으므로 `checkPlaceholderOp` 한 줄 추가로 막힌다. **F-1·F-2 착수 시 같이 처리할 것.**

**실기기 확인**: 초안에서 SL·창체 셀을 클릭 → 🔒 안내가 뜨고 선택이 안 되면 정상. 다른 수업을 SL 자리로 맞교환 시도 → 같은 안내로 차단되면 정상.

## 4. AI 층의 역할 재정의

F-2가 들어오면 E-4(개선 제안)의 현재 출력("분산하세요", "이동하세요")은 **탐색기가 더 정확하게 대체한다.** E-4를 없애지는 않되 성격을 바꾼다:

- **E-4 = 해설**: "왜 이 감점들이 남았는가"의 구조적 설명. 후보 탐색이 0건인 감점이 왜 안 풀리는지가 주 용도.
- **E-3 = 설명**: 현행 유지.
- 두 카드의 "AI가 작성한 참고 의견입니다" 경고는 유지한다(추정이므로).

## 7. v2 이월

- **학급 간 교환**: `BaseRevisionOp.swap`이 단일 `grade`/`classNum`이라 **같은 학급 안에서만** 맞바꿀 수 있다. "김한별 화2 ↔ 김동연 수3"이 서로 다른 학급이면 현재 op 타입으로 표현 불가 — op 타입 확장이 필요하다. v1은 같은 학급 내 이동만으로 S1·S2·S3·S5를 대부분 해소할 수 있다(교사 쏠림은 결국 그 교사 수업이 어느 교시에 있느냐의 문제이므로).
- **변경 전/후 시트 내보내기**: 화면 내 전/후 비교로 v1을 충족한다고 보고 이월. 필요해지면 기존 나이스 일괄 내보내기 경로에 얹는다.
- **다단계 해결안**: 2회 이상 교환으로 푸는 안. 탐색 공간이 제곱으로 늘어 v1 제외.
- S7(순배) 규칙: 타입에만 있고 미구현.
