# 9c 사전 조사 노트 — 컴시간 시간표 작성 실무·나이스 등록 절차 (2026-08-10)

9c(기초시간표 자동 작성) 스펙의 원천 조사. 1차 원천 = **`archive/주간시간표설명서.pdf`(컴시간 작성 프로그램 공식 매뉴얼, 저장소 보유 — 9b 때 확보만 하고 미정독)**. 보조 = 컴시간 공식 자료실·질의응답, 나이스 절차 웹 자료.

## §1 컴시간 작성 워크플로 (매뉴얼 목차·도입부 실독)

1. **기초자료 입력**: ① 교사별 시수표 엑셀(정식과목명·단축과목명·교사명·학년/반별 시수 — 우리 가져오기 파서가 이미 소화하는 그 구조) ② 기본사항(교사수·최대수업교시·실제학급수·**가상학급수** = 동시수업으로 늘어나는 학급수 개념) ③ 성명/학급/과목 등록부 ④ **요일별 시수**(학년×요일 교시수 — 우리 주 운영 periodsByGrade와 동형) ⑤ 일과시간.
2. **특별작업 = 제약 입력 6종** (9c 제약 모델의 원형):
   - **특별교사 배정** — 교사별 이동금지·배정금지 교시 (교사 시간 제약의 공식 입력처 — "인터뷰로 캘 소프트 제약"이 컴시간에선 이 메뉴)
   - **일괄 배정** — 재량·학급활동을 특정 교시에 여러 학급 동시 고정 (창체 고정 배치)
   - **연속수업 배정** — 2시간+ 블록 수업
   - **동시수업 배정** — 수준별/선택 이동수업 (우리 동시수업 등록부와 1:1)
   - **특별실 배정** — 공용 실 점유 (우리 §F 특별실 등록부와 1:1)
   - **복수교사** — 한 과목 2명 이상 공동 수업
3. **자동 시간표작성 / 배정검색**: 자동 배정 후 **배정검색으로 문제 조건을 확인·해결** — 우리가 계획한 "제약 위반 검사기"가 곧 배정검색의 재현.
4. **배정교시 이동(수동 조정)**: 색깔로 배정 가능/중복 표시, 미배정 시수 처리, 우클릭 도구 — "자동 초안 + 수동 미세조정" UI의 원형.
5. **NEIS 일괄 업로드**: "NEIS에 기초시간표 일괄파일 올리기" 절차 + **대상 부분이 빈칸으로 나오는 문제**(과목명 매칭 실패 — FAQ의 "전문교과 과목명 어떻게 기입" 질문과 동일 계열).

## §2 나이스 쪽 절차 (웹 조사)

- 경로: [교육과정]-[시간표관리]-[기초시간표관리] 등록 → [시간표검증및반영]에서 반영. 기초시간표가 있어야 보결 처리·출결이 돌아감(법정 기록의 전제).
- 담임 단위 수동 입력 경로도 존재(4세대: 학급시간표관리→기초시간표→과목 드래그→저장→반영) — 소규모용이고, 학교 단위는 컴시간의 "교무업무시스템용 일괄파일"이 표준.
- 시사점: **9c는 시간표 생성만으로 끝나지 않고 "나이스 일괄파일 내보내기"까지 있어야 컴시간 완전 대체가 성립** — 과목명 매칭(빈칸 문제)이 알려진 함정.

## §3 실무 고충 신호 (컴시간 질의응답 게시판 제목 실측)

특별실 중복 배정 / 동시수업(선택교과) 중 한 개 반만 복수교사 / 자율 일괄배정 학반 오류 / 배정교시 이동 화면 오류 / **수기 시간표를 거꾸로 프로그램에 업로드** — 실무 질문의 무게중심이 정확히 동시수업·특별실·수동 조정에 있음(우리 §A·§F 데이터가 급소를 이미 커버).

## §4 9c 스펙 시사점 종합

1. **제약 모델 = 컴시간 특별작업 6종의 재현이 출발선** — 이 중 4종(동시수업·특별실·연속·일괄)은 플랫폼 데이터·개념이 이미 있고, 교사별 배정금지 교시(특별교사)와 복수교사만 신규 입력 UI가 필요.
2. **검증 도구(배정검색 대응물)를 솔버보다 먼저** — 현행 2026-2 실시간표로 제약 모델을 검증하는 순서가 컴시간의 실무 순서와도 일치.
3. **범위에 나이스 일괄파일 내보내기 포함** (완전 대체 조건). 과목명 매칭 표 필요.
4. 소프트 제약(교사 희망)은 컴시간의 이동금지/배정금지 입력 항목을 질문지의 뼈대로 쓰면 됨 — 인터뷰 부담 최소화.
5. 다음 단계: `archive/주간시간표설명서.pdf` 전체 정독(특히 §6 특별작업 14~24p, §8 배정교시 이동 25~30p, §10 NEIS 업로드 33~36p) 후 9c 스펙 v1 작성.
