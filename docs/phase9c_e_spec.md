# Phase 9c-E — AI 보조층 스펙 v1 (2026-08-11)

> 상위: [`phase9c_spec.md`](./phase9c_spec.md) §7 + 로드맵 §2 "탐색은 로직, 판단은 AI" (2026-08-11 사용자 발상 + Claude 경계 설계).
> **철칙 재확인**: 배치·탐색은 결정론 솔버만. AI 출력이 시간표·등록부에 닿는 경로는 **사람 확인 → 기존 정규 저장 API** 하나뿐이며, 그 결과는 반드시 검사기(validateTimetable)를 통과해야 한다. AI 오류가 시간표를 깨뜨릴 수 있는 구조를 만들지 않는다.

## 0. 범위 — 4역할 한정 (9c §7 표 계승)

| # | 역할 | 입력 | 출력 | 반영 경로 |
|---|---|---|---|---|
| E1 | **불능 진단** | 검사기 하드 리포트 + 등록부 요약 | 충돌 원인 진단 + 완화 후보 문장 | **표시 전용** |
| E2 | **선호 정식화** | 자연어 요구("김OO은 월1 회피") | teacherSlotBans 후보(구조화) | 사람 확인 다이얼로그 → **기존 slot_ban_save** |
| E3 | **결과 설명** | 완성 그리드 요약 + 감점 상세 | "왜 이 배치인가" 눈높이 문단 | 표시 전용 |
| E4 | **정성 비평** | 완성 그리드 요약 | 개선 제안 목록(텍스트) | 표시 전용 (v1은 셀 연동 없음) |

구현 우선순위: **E1 → E2 → E3·E4**. 근거 — E1은 8월 실측 흐름(등록부 미비가 하드 위반으로 드러나 9월 질문지 문항이 되는 구조)과 직결돼 실무 가치가 즉시 발생. E3·E4는 11월 리허설 전 완성이면 충분.

## 1. 엔진·키 — Gemini API 무료 등급 정식 1키

- **선정 근거**: 무료 원칙(0원 경로 우선 — 유료 API는 기본 제안 제외) + 로드맵 §2에서 이미 확정된 전제("정식 무료 1키로 충분", 다중 키 파밍 기각). 호출은 시간표 작성 기간에만 집중되는 저빈도라 무료 한도 내.
- **키 발급 = 사용자**: Google AI Studio(https://aistudio.google.com/apikey)에서 발급 — 1분 작업. `.env.local`과 Vercel 환경변수에 `GEMINI_API_KEY`로 추가. (DWD·GCP 콘솔 작업 아님 — Workspace API가 아니라 별도 스코프·enable 불요.)
- **모델명**: 스펙에 박지 않는다 — 무료 등급 제공 모델은 자주 바뀌므로 **구현 시점에 확인해 `ai.ts` 상수 1곳**에만 기록 (모델명 추측 금지 규칙의 정신).
- **호출 방식**: 서버 라우트에서 REST 직접 호출(fetch) — 신규 SDK 의존성 0. 키는 서버 전용(클라이언트 노출 금지).
- **키 미설정 시 자연 비활성**: `ai_*` 액션이 `enabled: false` 응답 → UI는 진입점 자체를 숨김. 킬 스위치 = 환경변수 제거.

## 2. 개인정보 — 가명화 필수 (Claude 결정 사항)

**무료 등급 입력은 Google의 모델 개선에 활용될 수 있다.** 따라서:

1. **교사 실명·이메일을 외부로 보내지 않는다.** 서버가 전송 직전 실명→`T01`·`T02`… 가명으로 치환하고, 응답의 가명을 역치환해 클라이언트에 내려준다. 치환표는 요청 생명주기 안에서만 존재(저장 안 함).
2. 학급 번호·과목명·요일/교시는 개인정보가 아니므로 그대로 전송. 학생 데이터는 이 기능에 아예 등장하지 않는다.
3. 결과: **PII 외부 전송 0건** → 개인정보 처리방침·인벤토리 갱신 불요. (가명화를 뺀 설계 변경은 반드시 Claude 재검토를 거칠 것.)
4. 역치환 누락 방어: 응답에 미치환 가명이 남아도 표시상 무해(가명일 뿐) — fail-safe.

## 3. 역할별 입출력 계약

공통: 서버가 draftId(또는 termId)로 **그리드·모델·리포트를 재산출**해 프롬프트를 조립한다 — 클라이언트가 보낸 리포트를 신뢰하지 않는다(draft_op 관문과 동일 계열). 응답은 JSON 강제(responseMimeType), 파싱 실패 시 1회 재시도 후 실패를 그대로 표시(fail-visible — 조용한 무시 금지).

### E1 불능 진단 (`ai_diagnose`)
- 입력: draftId. 서버가 검사기 하드 리포트(actionable/registryGap 구분 포함)+제약 등록부 통계를 가명화 요약.
- 출력: `{ diagnosis: string, suggestions: string[] }` — 충돌 제약 조합을 사람 말로, 완화 후보(예: "T03의 화요일 전일 금지를 오전만으로 줄이면 3건이 풀립니다").
- 표시 전용. 제안을 클릭해도 자동 반영 없음.

### E2 선호 정식화 (`ai_formalize`)
- 입력: 자연어 문장 1건 + 서버가 채우는 컨텍스트(가명 교사 목록, 요일·교시 범위).
- 출력: `{ interpretation: string, entries: Array<{ teacherKey, day?, period?, wholeDay?, kind: "ban"|"move_ban" }> }` — **v1 범위는 teacherSlotBans만** (소프트 가중치 조정은 질문지 회수 후 v2).
- 반영: UI가 해석 결과를 사람 말로 보여주고("김OO 선생님 월요일 1교시 배정 금지로 등록할까요?") 확인 시 **기존 `slot_ban_save`로만 저장** — AI 전용 쓰기 경로 신설 금지, 정규 sanitize·감사 로그 그대로.
- 역치환 실패(모르는 이름) 시 유사 후보 제시 + 미등록 안내.

### E3 결과 설명 (`ai_explain`) / E4 정성 비평 (`ai_critique`)
- 입력: draftId. 서버가 요약 통계(반·교사별 분포, 감점 상세 상위 N)를 가명화.
- 출력: E3 `{ explanation: string }`, E4 `{ suggestions: string[] }`. 둘 다 표시 전용.
- 그리드 전문 전송 금지 — 요약만(토큰·한도 절약, 프롬프트는 `ai.ts`에서 Claude가 설계).

## 4. API·아키텍처

- manage 라우트 action 4종: `ai_diagnose`·`ai_formalize`·`ai_explain`·`ai_critique`. 권한 = authz 기본 거부 폴스루(일과계+super_admin, authz.ts 무변경 — F-1 판단 재사용).
- 프롬프트 템플릿·가명화·응답 파싱 = **`src/lib/timetable/ai.ts` (Claude 소유 파일)**. 라우트는 얇게.
- 타임아웃 30초·응답 크기 상한. 429(무료 한도) 시 눈높이 안내("사용량이 많아 잠시 후 다시 시도해 주세요").
- 감사 로그: 등록부에 닿는 E2 확정 저장만(기존 slot_ban_save 로그로 충분 — AI 호출 자체는 로그 불요, 읽기성 행위).

## 5. UI (Antigravity — IA 명시)

- **E1**: DraftAutoTab 초안 리포트 영역에 [원인 진단 (AI 도움)] 버튼 — 하드 위반 > 0일 때 노출 (v1.1 정정: actionable 한정 → 전체 하드. 등록부미비(registryGap) 전용 위반도 "데이터 보완 먼저" 진단 가치가 있고 프롬프트가 명시 처리함). 결과는 리포트 아래 접이식 카드. 초안 전환 시 진단 상태 초기화(오귀속 방지), 같은 초안 내 조정에는 유지.
- **E3·E4**: 초안 편집기 헤더에 [이 시간표 설명]·[개선 제안] — 초안 열림 시.
- **E2**: TeacherSlotBanTab 상단에 "말로 입력하기" 접힌 입력창 → 해석 확인 다이얼로그 → 기존 저장 플로우.
- **AI 표식 필수**: 모든 출력에 "AI가 작성한 참고 의견입니다 — 반영 전 직접 확인하세요" 라벨. 확인 없이 반영되는 경로가 없음을 UI에서도 드러낸다.
- 키 미설정이면 진입점 전부 숨김(회색 비활성 아님 — 존재 자체 숨김). UI 문구 개발 용어 금지("AI 도움" 수준).

## 6. 검증 계획

1. `scripts/ai_selftest.ts` — 가명화 왕복(치환→역치환 무손실)·프롬프트 조립·파싱을 네트워크 무의존으로.
2. `scripts/verify_ai_smoke.ts` — 키 있을 때만 실호출 1회: 전송 본문에 실명·이메일 0건임을 스크립트가 기계 검증(가명화 실측), E1 응답 파싱 확인.
3. E2 출력 → 기존 slot_ban_save sanitize 통과 실측.
