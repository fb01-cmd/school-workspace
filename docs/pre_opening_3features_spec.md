## 0. 우선순위와 관계 (사용자 확정 + Claude 판단)

| 순번 | 기능 | 시점 | 이유 |
|---|---|---|---|
| A | 동시수업(분반) 교체 불가 | **개학 전 필수 (D-4~D-1)** | 없으면 후보 엔진이 분반 수업을 교체 추천 — 실사고 경로 |
| B | 학사일정 등록 → 주차 자동 파생 | best-effort (개학 후 완성 허용) | 첫 주는 현행 수동 주 등록으로 개학 가능 |
| C | 징검다리(목표 지향 체인) | 개학 후 | A의 제약을 전제로 그 위에 얹는 기능 |

셋의 관계: **A는 모든 교체 경로의 공통 하드 제약**(C의 체인 탐색도 A를 지켜야 함), **B는 주(week) 데이터의 생산 방식 개선**(C의 탐색 범위인 "등록된 주"를 자동으로 넓혀줌). 그래서 A → B → C 순.

## A. 동시수업(분반 이동수업) 교체 불가

### A-1. 배경 (2026-08-06 일과계 실무 확인)

- 제2외국어(중국어·일본어)와 일부 과학 수업은 **여러 반을 묶어 같은 교시에 동시에 진행하는 분반 이동수업**. 한 반만 교체하는 것이 불가능 — 부득이하면 묶인 반 전체를 통째로 옮기는 대작업(컴시간도 연쇄이동 시 동시수업 그룹을 통째로 함께 이동시킴 — 일과진행설명서).
- 컴시간 정식 명칭 **"동시수업"**, 원 도구는 **동시수업 등록부**(행 단위로 학급+과목을 묶어 그룹 등록 — 일과진행설명서 p27). 한셀 원본에는 셀 색으로 구분돼 있었으나 xlsx 변환에서 유실.
- **기존 엔진의 동시수업 하드 제외(9b §4-3: 한 셀에 lessons 2개↑·teachers 2명↑)는 이 데이터를 잡지 못한다** — 변환된 그리드에서 분반 수업은 반마다 평범한 단일 lesson 셀로 보이기 때문. 그래서 별도 등록부가 유일한 해법.

### A-2. 데이터 모델

```
timetable_simul_groups/{domain}/groups/{groupId}
  ├ termId: "2026-2"
  ├ label: string                    ← 사람용 이름 (예: "1학년 제2외국어")
  ├ grade: number
  ├ classNums: number[]              ← 묶인 반 (예: [1,2,3])
  ├ subjectNames: string[]           ← 대상 과목명 (예: ["중국어Ⅰ","일본어Ⅰ"] — 기초 그리드 표기와 정확히 일치)
  ├ slots?: { day: 1~5, period: number }[]   ← 선택. 지정 시 이 교시들만 대상 (과목명만으로 모호할 때 —
  │                                             예: 일부 반만 분반인 과학). 미지정 시 과목명 일치 셀 전부.
  ├ active: boolean
  └ createdBy, createdAt, updatedBy?, updatedAt?
```

- **판정 함수 (단일 원본)**: `isSimulCell(grade, classNum, day, period, subjectName, groups) : { hit: boolean, groupLabel?: string }` — `src/lib/timetable/simul.ts` 순수 함수. 조건: active 그룹 중 `grade` 일치 ∧ `classNum ∈ classNums` ∧ `subjectName ∈ subjectNames` ∧ (slots 있으면 `(day,period) ∈ slots`).
- 판정은 **기초 그리드의 과목명 기준** — 주간 합성으로 셀이 이동해도 lesson의 subjectName이 따라가므로 그대로 성립. 반대로 동시수업 셀은 애초에 교체가 차단되므로 이동 자체가 없다.

### A-3. 적용 지점 (이중 방어 — AGENTS.md §5)

1. **후보 엔진 (swap.ts 하드 제외에 추가)**: 9b §4-3 하드 제외 목록에 "동시수업 그룹 판정 셀" 1줄 추가 — s(원본)든 t(목표)든 걸리면 제외. 적용 범위 = 엔진을 쓰는 전 경로 자동 커버: 맞교환·특별보강·교차 주(각 주 기준 각각)·직권(candidates_all)·체인(C, 향후). 특별보강은 **대상 슬롯이 동시수업이면 보강 자체를 차단**(분반 수업은 대체 교사 1명으로 성립하지 않음 — 묶음 전체의 문제).
2. **커밋 검증 (서버)**: 신청 생성·승인·directCommit·direct_commit_batch에서 관련 슬롯 중 하나라도 동시수업 판정이면 400 거부 — 엔진 우회(후보 위조) 대비. 메시지: "이동수업(분반) 수업은 교체할 수 없습니다. 일과계에 문의해 주세요."
3. **그리드 표시**: 동시수업 셀에 구분 표시(연보라 배경 + "이동수업" 소형 배지 — 정확한 문구·색은 구현 시 확정, 개발 용어 금지 원칙 준수). 교사 포털·직권 탭·학생 카드 전부. 셀 클릭 시 교체 시작이 아예 비활성 + 사유 문구.

### A-4. 등록부 UI (일과계 직접 지정 — 컴시간 등록부 계승)

- 위치: 시간표 관리(일과계) 안 "이동수업 관리" 탭. manage 라우트 신규 액션 `simul_list` / `simul_save` / `simul_delete` (일과계·super_admin 게이트 — 기존 판정 재사용).
- 화면: 그룹 목록(라벨·학년·반·과목·교시 제한·활성) + 추가/수정 폼(학년 선택 → 반 다중 선택 → 과목명 입력(기초 그리드에서 과목명 자동완성) → 교시 제한 선택 사항). **저장 전 미리보기**: 판정에 걸리는 셀들을 주간 그리드에 하이라이트해 "이 수업들이 교체 불가로 지정됩니다" 확인 후 저장.
- 감사 로그: simul_save/delete 시 writeAuditLog (그룹 라벨·범위 요약).

### A-5. 1차 데이터 등재 (8/7, 목록 수령 즉시)

- 일과계 목록(사진/표) → Claude가 `scripts/register_simul_groups.ts`(admin SDK, 드라이런 기본)로 등재. 등재 후 **검증 스크립트로 판정 셀 전수 출력** → 사용자·일과계가 눈으로 대조(빠진 수업·과잉 지정 확인). 원본 과목명 표기가 그리드와 다르면(예: "중국어" vs "중국어Ⅰ") 그리드 표기 기준으로 정규화해 등재.

### A-6. 분업·순서 (D-4~D-1)

1. **Claude (서버·엔진 — 위험 지점 직접)**: simul.ts 판정 함수 + swap.ts 하드 제외 + 커밋 검증 + manage 액션 3종 + 등재·검증 스크립트. **8/7 목록 수령 전이라도 구현 가능** (데이터와 코드는 독립).
2. **Antigravity (화면)**: 등록부 탭 + 그리드 구분 표시(교사 포털·직권 탭·학생 카드). Claude 표적 리뷰.
3. 8/7 데이터 등재 → 8/8~9 실기기 확인(분반 셀에 배지·후보에서 사라짐·직권에서도 차단) → 개학.

## B. 학사일정 등록 → 주차 자동 파생

### B-1. 원리

현행: 일과계가 주마다 week 문서를 수동 등록(휴업일·단축 포함) — 컴시간 답습. 개선: **학기 초 학사일정을 1회 등록하면 week 문서가 자동 파생**. 일과계 설정은 "몇 주 앞까지 교사 공개"뿐.

### B-2. 데이터 모델

```
timetable_calendar/{domain}/events/{eventId}
  ├ termId: "2026-2"
  ├ type: "휴업일" | "재량휴업" | "단축수업" | "고사"
  ├ startDate, endDate: "2026-09-30"          ← 단일일은 start=end
  ├ periodsByGrade?: {1:n,2:n,3:n}            ← 단축수업·고사일 때 요일별 시수
  ├ note?: string
  └ createdBy, createdAt

timetable_settings/{domain}
  └ publishWeeksAhead: number = 2             ← 오늘 기준 몇 주 앞까지 자동 생성·공개
```

- **공휴일 자동**: 학기 범위의 법정 공휴일은 코드 내장 정적 표(`src/lib/timetable/holidays.ts`, 학기당 십수 건 — 외부 API 불요, 무료 원칙·오프라인 안정성). 대체공휴일 포함해 학기 시작 때 갱신.
- **파생 규칙**: week 문서 생성 시 각 날짜에 대해 — 공휴일 표 ∪ 휴업일·재량휴업 이벤트 → `holiday: true`; 단축·고사 이벤트 → `periodsByGrade`. 겹치면 휴업일이 우선.

### B-3. 동작 방식 — "없으면 만들어 채우는" 지연 생성

- 크론이 아니라 **조회 시 파생**: view/manage가 주를 요청했을 때 그 주가 `publishWeeksAhead` 범위 안이고 week 문서가 없으면 파생 규칙으로 **자동 생성 후 반환** (admin SDK, 생성 로그 남김). 기존 수동 등록 주는 그대로 존중(자동 생성은 문서가 없을 때만 — 수동 우선).
- 일과계 화면: 학사일정 관리 탭(이벤트 목록+추가/수정, 달력 뷰는 후속) + 자동 생성된 주의 확인·수정은 기존 주 관리 화면 그대로(파생 결과도 일반 week 문서이므로).
- **주 등록 실수 방지 보너스**: 자동 파생 주는 휴업일 누락이 구조적으로 없음.

### B-4. 시점·분업

- **개학 첫 주(8/10)는 현행 수동 등록** — B와 무관하게 개학 가능 (이미 확정된 운영).
- 서버 파생 로직·공휴일 표 = Claude. 학사일정 관리 탭 = Antigravity. 구현은 A 종결 후 착수(개학 후 첫 주 내 목표) — 완성되면 이후 주부터 수동 등록 소멸.

## C. 징검다리(목표 지향 체인) 교체

### C-1. 원리 (로드맵 §2 확정안)

"후보 중에서 고르기"가 아니라 **"목적지를 찍으면 경로를 만들어주기"**: 일과계가 A 교사의 수업 s를 옮기고 싶은 빈칸 t를 직접 클릭 → s가 t에 도달하는 중간 교환 체인(A↔B, B↔C…)을 시스템이 역방향 탐색해 담기 목록으로 제안. 기반은 기구현 — direct_projected 가상 합성 + direct_commit_batch 순차 승인("먼저 비운 자리를 뒤 항목이 쓰는" 성질).

### C-2. 서버 — `chain_search` (manage 신규 액션, Claude 구현)

- 입력: `{ teacherEmail, source: {weekId, grade, classNum, day, period}, target: {weekId, day, period}, maxDepth?: 2 }`.
- 탐색: 상태 = 가상 적용된 합성본(§14-1 whatIf 재사용). 1수 = 기존 맞교환 규칙과 동일한 유효 이동(하드 제외 전부 적용 — **동시수업(A) 포함**, 특별실·가상 교사·복수교사). 목적지 t에 도달하는 이동 수열을 깊이 우선 탐색, **maxDepth 기본 2**(중간 교사 최대 2명 — 컴시간 연쇄이동도 실무상 2~3인, 깊이 3은 폭발 위험이 있어 opt-in).
- 출력: 체인 목록(최대 5개, 총 감점 오름차순) — 각 체인은 `pendingItems[]` 형식 그대로(담기 호환), 단계별 사람용 요약("① 김OO 수(3)→금(2) ② 이OO 금(2)→…")과 단계별 penalties.
- 성능 가드: 후보 분기 상한(단계당 상위 8 후보만 확장), 탐색 시간 상한 3초 — 초과 시 부분 결과 반환+"조건을 좁혀 주세요".
- 교차 주 목적지 허용(등록된 주 한정 — B가 완성되면 범위 자동 확장).

### C-3. UX (직권 탭 확장, Antigravity 구현)

- 대상 교사 그리드에서 **빈칸(공강 셀) 클릭 → "이 자리로 옮겨오기"** 선택 → 원본 수업 선택(또는 역순: 수업 먼저·빈칸 나중) → 체인 목록 표시(단계 수·감점·거치는 교사).
- 체인 선택 → **담기 목록에 단계들이 순서대로 적재**(기존 cart·direct_projected·상대별 양해 카드·일괄 반영 흐름 그대로 재사용 — 신규 UI는 진입점과 체인 목록뿐).
- 실패(경로 없음) 시: "2단계 안에서는 길이 없습니다" + maxDepth 3 재시도 버튼.

### C-4. 시점

개학 후, B 다음. §14-3의 "빈도 관찰" 조건은 폐기됐으나(사용자 결정) 구현 순서상 A·B에 밀린다 — 2학기 1~2주차 착수 목표.

## B-보강. 학사일정 구현 확정 세부 (2026-08-06 밤 — 서버부 선구현)

- **공휴일 정적 표** `src/lib/timetable/holidays.ts` — 2026-2 범위(2026-08~2027-02): 광복절 8/15(토)+**대체공휴일 8/17(월) — 개학 2주차 월요일**, 추석 연휴 9/24(목)~9/26(토, 대체 없음 — 설·추석은 일요일 겹침만 대체), 개천절 10/3(토)+대체 10/5(월), 한글날 10/9(금), 성탄절 12/25(금), 신정 1/1(금), 설 연휴 2027-02-05(금)~02-07(일)+대체 02-08(월). 학기 갱신 시 이 파일만 교체.
- **모델**: `timetable_calendar/{domain}/events/{eventId}` — termId, type(휴업일|재량휴업|단축수업|고사), startDate~endDate, periodsByGrade?(단축·고사), note, createdBy/At. 검증: 날짜 형식·역전 금지·단축은 periodsByGrade 필수.
- **파생 규칙**: 주(월요일 시작) 생성 시 각 평일에 대해 — 공휴일 표 ∪ (휴업일·재량휴업 이벤트) → holiday:true / (단축·고사) → periodsByGrade. 겹치면 휴업일 우선.
- **지연 생성 지점**: manage `week_list` 처리 시 `ensureDerivedWeeks` — 오늘이 속한 주부터 `publishWeeksAhead`(설정, 기본 2)주 앞까지 없는 주를 자동 생성(createdBy "학사일정 자동", 감사 로그 생략 — 파생은 결정론적). **수동 등록 주가 있으면 절대 덮지 않음**(수동 우선). 일과계 화면·교사 신청 화면 모두 week_list를 지나므로 단일 지점으로 충분.
- **manage 액션**: `calendar_list` / `calendar_save`(생성·수정, 감사 로그) / `calendar_delete`(감사 로그). 일과계 게이트(기존 규칙 4). 이벤트 수정·삭제는 **이미 생성된 주 문서를 소급 변경하지 않음** — 미래 주 재생성은 해당 주 문서를 일과계가 수동 수정(week_update)하거나 삭제 후 재파생(후속 여지).

## E. 기초시간표 개정 — 개학 첫 주 수정분을 다음 주부터 적용 (2026-08-06 사용자 요구)

### E-1. 원리

개학 첫 주에 학기 시간표 자체를 바꾸는 실무를 지원한다. 일과계가 기초시간표에 **개정판(revision)**을 편집(주간 교체와 같은 셀 이동 조작)하고, 적용 확정 시 **다음 주 월요일부터** 효력. 이번 주는 옛 기초 그대로 → 그 주의 출장 교체와 꼬이지 않음(실무 관행 그대로). 어긋나는 예약 변경은 기존 integrityWarnings가 안전망.

### E-2. 모델

```
timetable_base_revisions/{domain}/revisions/{revId}
  ├ termId
  ├ status: "draft" | "applied"
  ├ effectiveFrom?: "YYYY-MM-DD"   ← 적용 시작 주 월요일 (applied일 때 필수)
  ├ ops: [                          ← 순서 있는 편집 연산 목록
  │    { type: "swap", grade, classNum,
  │      a: {day, period}, b: {day, period} }            ← 같은 학급 두 슬롯 맞바꿈 (빈 슬롯 허용 = 이동)
  │  | { type: "edit_cell", grade, classNum, day, period,
  │      lessons: TimetableLesson[] } ]                  ← 셀 통째 교체 (교사·과목 변경 등 만능 탈출구)
  ├ note?: string
  └ createdBy, createdAt, appliedBy?, appliedAt?
```

- draft는 **학기당 동시 1개**(단순화 — 새 draft 생성 시 기존 draft 있으면 그것을 반환). applied 개정판은 불변 — 잘못 적용했으면 새 개정으로 되돌린다.
- **주차별 기초 선택**: `loadBaseGridsForWeek(domain, termId, weekStartDate)` = 기초 classGrids + `effectiveFrom ≤ weekStartDate`인 applied 개정판들을 appliedAt 순서로 적용 → **동시수업 라벨 재스탬프**(이동 후 위치 기준 재판정). 주간 합성·후보 엔진·승인 재검증·직권 전 경로가 이 로더를 쓴다.
- swap 연산 적용 검증: 적용 시점 셀 상태가 기대와 다르면(선행 개정과 충돌) 해당 op는 건너뛰고 경고 수집 — 주간 integrityWarnings와 같은 원칙.

### E-3. manage 액션 (일과계 게이트)

- `revision_list`: 학기의 개정판 목록(+draft 유무).
- `revision_save_draft` {revisionId?, ops, note?}: draft 생성/전체 교체. 서버는 ops를 기초에 가상 적용해 **오류 op 목록과 적용 결과 미리보기 요약**을 반환(저장은 항상 — 편집 중 임시 상태 허용).
- `revision_apply` {revisionId, effectiveFrom?}: draft → applied. effectiveFrom 기본값 = **다음 주 월요일**(오늘이 속한 주의 차주). 과거·이번 주 월요일은 거부(이미 운영 중인 주 소급 변경 금지). 감사 로그.
- `revision_delete` {revisionId}: draft만 삭제 가능. 감사 로그.

### E-4. 화면 (Antigravity — 개학 첫 주 내)

- 시간표 관리에 "기초시간표 개정" 탭: 학급 선택 → 기초 그리드 표시 → 셀 두 번 클릭으로 맞바꿈(주간 교체와 같은 조작감) 또는 셀 편집(교사·과목) → 변경 목록 패널(제거 가능) → [다음 주부터 적용] 확인창(적용 시작일 명시) → 적용 후 개정 이력 목록.
- 적용 전 미리보기 = revision_save_draft 응답의 요약 + 그리드에 변경 셀 하이라이트.

## §F. 특별실(장소) 점유 제약 — 교체 후보 하드 제외 (2026-08-07 추가·同日 구현)

### F-1. 배경·원칙

- 특별실(다윗관·탁구장·정보실·생명과학실)은 **한 교시에 한 수업만** 쓸 수 있는 공유 자원. 기초시간표는 충돌 없이 짜여 있으나, 교체로 수업이 다른 교시로 이동하면 교사·학급이 비어 있어도 장소가 겹칠 수 있다.
- 실무(일과계)는 특별실 수업 교체를 통째로 배제해 왔음 → 플랫폼은 **충돌하는 후보만 제외하고 안 겹치는 후보는 정상 추천** (2026-08-07 사용자 확정). 동시수업(§A)과 달리 **소스 차단 없음**.
- 데이터 원본: 컴시간 "특별실 시간표" (2026-08-07 일과계 제공 스크린샷, 4실·시수 30/30/27/16).

### F-2. 모델·판정

- `timetable_venue_groups/{domain}/groups`: VenueGroup { termId, roomName(특별실명=판정 키), label, grade, classNums(1개 허용 — 단일 반도 점유), subjectNames, slots?(과탐 실험처럼 일부 시수만 특별실일 때), active }.
- **판정 단일 통로**: 그리드 로더(loadAllClassGrids/loadClassGrid/loadBaseGridsByWeek 개정 재스탬프)가 등록부 대조 후 일치 lesson에 `lesson.room = roomName` 스탬프. 저장 데이터 무표기, 읽기 시점 계산. 미일치 lesson의 기존 room(가져오기 원본 값)은 지우지 않는다.
- **엔진은 기구현 재사용**: swap.ts의 `buildSlotIndex.roomUse` + `isRoomFree`가 room 값을 소비 — 맞교환·교차 주 target 검사 기존 코드가 그대로 발화(자기 학급 제외 = 상대 수업이 비우는 슬롯 허용). 특별보강은 수업이 제자리라 검사 불요. 커밋 검증은 스탬프된 그리드 위 엔진 재계산이라 자동 이중 방어.
- 합성(synthesizeWeeklyGrids)은 room을 lesson과 함께 운반 → 교체로 이동한 실험 수업도 특별실 요구가 따라간다.

### F-3. manage 액션 (일과계 게이트 — 기존 규칙 4)
