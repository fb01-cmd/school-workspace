# 구독형 학사일정 캘린더 스펙 (calendar_ics_feed) — 알리미 추가 캘린더

2026-08-10 사용자 착수 확정: 플랫폼 학사일정(나이스 자동 수집 + 직접 등록)을 **ics 피드**로 노출해, 효명고 구성원이 구글 캘린더(및 아이폰 기본 캘린더)에 "추가 캘린더"로 구독한다. 학사일정이 바뀌면 구독자 캘린더가 알아서 최신화되는 알리미형 채널. calendar_events_taxonomy_spec §7의 ⓐ안(앱 내 1클릭 안내, 0원·권한 불요) 채택 — DWD 자동 구독(ⓑ)은 하지 않는다.

## §1 피드 엔드포인트

- `GET /api/calendar/ics?token=<icsToken>` → `text/calendar; charset=utf-8` 응답 (파일명 `hyomyeong-calendar.ics`).
- **인증**: 구글 캘린더가 서버에서 무인 폴링하므로 로그인 불가 → **추측 불가 토큰 방식**. `timetable_settings.icsToken`(랜덤 32+자)이 없으면 관리 API(§3)가 최초 생성. 토큰 불일치·부재 시 404(존재 노출 금지). 학사일정은 전교 공지 성격이라 개인정보 아님 — 토큰은 무단 스크래핑 방지용.
- 피드 범위: 보관 아닌 전 학기의 이벤트 전부(행사 + 일과 영향, 나이스 자동 + 직접 등록 무구분).
- **공휴일은 포함하지 않음** — 나이스 수집이 스킵하므로 자연 제외되고, 구독자 구글 캘린더에는 대한민국 공휴일 캘린더가 이미 있음(중복 방지). UI 안내 문구에 명시.

## §2 ics 생성 규칙

- 종일 이벤트: `DTSTART;VALUE=DATE:YYYYMMDD`, `DTEND;VALUE=DATE:` = **종료일 + 1일**(ics 관례, exclusive).
- `SUMMARY` = title(없으면 type명) + 전 학년이 아니면 ` (N학년)` 접미(예: "체험학습 (2학년)").
- `DESCRIPTION` = note(있을 때). 시수 조정(단축수업·고사)은 periodsByGrade를 눈높이 문구로(예: "1·2·3학년 4교시 수업").
- `UID` = `<이벤트 문서 id>@portal.hmh.or.kr` (안정 — 수정 시 같은 UID로 갱신되게), `DTSTAMP`·`LAST-MODIFIED` = updatedAt/createdAt.
- `X-WR-CALNAME: 효명고 학사일정`, `X-PUBLISHED-TTL: PT12H`, `CALSCALE:GREGORIAN`, CRLF 줄바꿈·UTF-8, 텍스트 이스케이프(쉼표·세미콜론·줄바꿈).
- 라이브러리 불요 — 수제 생성으로 충분(의존성 추가 금지).

## §3 관리·발급

- manage 라우트에 `calendar_ics_info` 액션(수퍼어드민+일과계, 기본 관문): icsToken 없으면 생성·저장 후 구독 URL 반환. 토큰 재발급은 이번 범위 아님(필요 시 추후).
- 캐시: 피드 응답에 `Cache-Control: public, max-age=3600`. 읽기 비용 = 폴링당 학기 이벤트 목록 1회(구글 폴링 주기가 12~24시간이라 무시 가능 수준).

## §4 구독 안내 UI

노출 위치 2곳 (전 구성원 대상 — 관리 탭이 아니라 눈에 띄는 곳):
1. **교사 대시보드 + 학생 포털**에 "학사일정을 내 캘린더로 받기" 카드(소형): 버튼 [구글 캘린더에 추가](`https://calendar.google.com/calendar/r?cid=<URL-인코딩된 webcal URL>` 새 탭) + [주소 복사](아이폰 기본 캘린더 등 기타 앱용 webcal:// URL 클립보드) 2개.
2. 학사일정 탭(일과계)에도 같은 안내 + 구독 URL 표시.

문구 유의(개발 용어 금지, ics·피드·URL 폴링 같은 말 금지): "한 번 추가해 두면 학사일정이 바뀔 때 캘린더가 자동으로 따라 바뀝니다", "반영까지 하루 정도 걸릴 수 있습니다"(구글 폴링 주기 기대치 관리), "공휴일은 캘린더에 기본으로 있는 대한민국 휴일을 그대로 쓰세요".

## §4-2 교사용·학생용 이중 피드 (2026-08-10 사용자 확정 — 기존 수동 캘린더 이행과 함께)

배경: 사용자의 기존 수동 캘린더(568건, 공개 ics 확보)는 학교 행사와 **교직원 업무 마감류**(세특 입력 마감·학생부 대사작업 등)가 섞여 있음 — 학생·학부모 구독 캘린더에 업무 마감이 실리는 문제를 청중 분리로 해결.

- `TimetableCalendarEvent.staffOnly?: boolean` — 직접 등록 폼([행사 추가])에 체크박스 "교직원만 보기"(눈높이 문구: "학생·학부모 캘린더에는 실리지 않습니다"). 나이스 수집분은 항상 전체 공개(staffOnly 미부여). **주의: loadTimetableSettings·loadCalendarEvents 정규화 통과 확인(icsToken 누락 전례).**
- 토큰 2개: `icsToken`(학생·학부모용 — staffOnly 제외) + `icsStaffToken`(교직원용 — 전부). 피드 라우트는 토큰으로 청중 판별, 이름도 구분("효명고 학사일정" / "효명고 학사일정(교직원)").
- `calendar_ics_info` 응답: 학생 role에는 학생용 주소만, 교사·수퍼어드민·일과계에는 두 주소(카드는 자리에 맞는 것 표시 — 학생 포털=학생용, 교사 대시보드=교직원용).
- 기존 배포된 icsToken은 학생용으로 그대로 유지(주소 불변 — 기구독자 안 깨짐).

## §5 검증

- tsc·build(힙 4GB) 통과.
- 실측: ① curl로 피드 수신 → VCALENDAR/VEVENT 구조·이벤트 수 = 플랫폼 학사일정 수 일치 ② 잘못된 토큰 404 ③ 기간 이벤트(겨울방학)의 DTEND가 종료일+1일인지 ④ 학년 접미·시수 조정 DESCRIPTION 문구 확인 ⑤ (수동, 사용자) 실기기에서 구글 캘린더 추가 버튼 동작.
- ics 유효성은 구조 검사 스크립트로(필수 프로퍼티·CRLF·이스케이프) — 외부 검사기 의존 금지.
