# 기간제 교사 수업 인수인계 스펙 (substitute_handover_spec)

## §0 인터뷰로 확정된 실무 사실 (설계의 전제 — 전부 사용자 증언)

1. **계획 휴직(육아 등)은 학기 단위로 미리 정해진다** — 공백이 없고 신학기 준비 흐름에 자연히 실린다. **이 스펙의 본체는 병가형(급작) 휴직**이다: 즉시 전 수업이 보강 처리되는 공백기 → 기간제 확보(기간 천차만별) → 부임.
2. **수업은 통째로 인수한다.** 담임도 원칙은 기간제가 가져가되, 채용이 어려우면 학년부장이 대신 맡는 실사례가 있다(선택지 필요).
3. **업무분장은 승계되지 않는다** — 부서장이 흡수(휴직자가 부서장이면 인근 부서장 겸임). 사람 사이의 일이므로 **시스템 비대상**(「시스템은 정보 전달까지만」).
4. **계정**: 기간제는 부임 즉시 신규 계정 발급(기존 흐름 그대로), 휴직자 계정은 **아무 조치도 하지 않고 그대로 둔다**(실무 그대로 — 정지·삭제 설계 금지). 기간제 종료 시엔 기존 생애주기의 **전출 처리** 그대로.
5. **나이스는 나이스가 다 한다** — 기간제가 전권으로 처리(담임이면 생기부 기재 포함). 플랫폼 몫은 시수·주간이 부임일부터 기간제 이름으로 나오게 하는 것뿐.
6. **인수는 날 단위다** — "오겠다고 한 날짜부터" 바로 수업(주 단위 불가 — 수업 공백은 크리티컬). 교시 단위까지는 자르지 않는다.
7. **클래스룸은 이어받는다 — 공동교사 초대가 가장 깔끔**(사용자 확정). 종료 시엔 내보내기(공동교사 제거).
8. 복직은 원칙 원복. 예외 실사례: 건강 사유 업무 대체, 담임 배제 — 역이관에도 선택지가 필요.

## §0-1 컴시간 대조 (2026-08-18 설명서 2종 전문 검색 — 사용자 요청)

컴시간에는 기간제·휴직 인수인계 **전용 기능이 없다**(설명서 전문에서 기간제·휴직·복직 0건). 실무 경로는:
- 교사 교체 = **[성명 등록부]의 이름 칸을 수정**("교사명이 맞지 않는 경우에는 성명 등록부에서 수정") — 등록부 참조 구조라 이력 장치 없이 이름이 통째로 바뀐다. 언제부터 누가 맡았는지의 경계는 시스템에 남지 않는다.
- 알리미 계정 = 전출자 수동 삭제 + 신규 수동 등록 / 나이스 반영 = [수업교환 목록] 출력 후 수동 입력.

→ **본 스펙의 차별점이자 채택 논리**: 걸치는 주 변경 + effectiveFrom 개정판의 2단 구조는 부임일 전후를 정확히 갈라 "그 주까지는 A, 그날부터 B"가 주간·시수·나이스 목록에 그대로 남는다. 계정·담임·클래스룸까지 한 마법사로 묶이는 것도 컴시간에 없는 범위.

## §1 범위

**신규 기능은 「담당 일괄 이관 마법사」 하나로 수렴한다** (+ 클래스룸 공동교사 초대/제거 서버부). 명시적 범위 제외: ⓐ 업무분장(§0-3) ⓑ 계정 생성·전출(기존 기능 링크만) ⓒ 나이스 권한(나이스 소관) ⓓ 공백기 부재자 등록(§9 아이디어 보관 — 현행 결보강으로 충분하다는 사용자 판단) ⓔ 휴직자 계정 조치(무조치가 실무).

## §2 국면 모델

- **공백기** (병가 시작 ~ 부임 전): 현행 결보강 워크플로 그대로 — **플랫폼 무변경**. 일과계가 주간 단위로 보강 처리(실무 확립).
- **인수일 D**: 마법사 1회 실행 (§3).
- **복직일 R**: 같은 마법사 역방향 (§4) + 기간제 전출 처리(기존).

## §3 담당 일괄 이관 마법사 (핵심 신규)

입력: 이관 원 교사 A · 이관 대상 교사 B · 인수일 D. 실행 전 **미리보기**(바뀔 수업 n건·담임·클래스룸 목록)를 보여주고 일괄 커밋한다. 전 단계 감사 로그.

선행 검증(마법사 첫 화면에서 자동 확인·안내): B의 계정 실재(GWS Directory) + 승인 프로필 + **조직도 부서 배치**(없으면 이 자리에서 배치 — 부서가 있어야 쪽지·조직도에 실린다. 기본 제안 = A의 부서).

날 단위 인수(§0-6)를 기존 장치 2개의 이어붙이기로 구현한다 — **새 합성 개념 0**:

1. **걸치는 주 (D ~ 그 주 금요일)**: 해당 주의 D 이후 요일에 있는 A의 모든 수업에 대해 **B로의 직권 배정 주간 변경을 자동 산출**해 목록으로 제시 → 일괄 커밋(direct_commit_batch 패턴 재사용). 주간 합성·알림·되돌리기 전부 기존 경로.
2. **다음 주부터**: **기초시간표 개정판 자동 생성** — A 담당 셀 전부를 B로 치환(그 외 완전 동일), `effectiveFrom` = 다음 주 월요일. 기존 주차별 개정 합성이 이후의 주간시간표·결보강 후보·나이스 목록·시수 집계를 전부 B 이름으로 처리한다(개정 메커니즘의 설계된 용법).
3. **담임 승계(선택 단계)**: A가 담임이면 — 승계자를 B(기본) 또는 제3자(학년부장 실사례)로 선택 → 승인 프로필 담임 필드 갱신(담임 단일 원본 — 생활지도·명렬 권한 자동 추종).
4. **클래스룸**: A가 교사인 활성 클래스룸 목록 제시 → 선택분에 B를 **공동교사로 초대**(소유 이전 아님 — §0-7).

- 산출 로직(1의 잔여 요일 수업 추출, 2의 치환 개정판 생성)은 순수 함수로 분리해 셀프테스트 대상으로 한다.
- A 계정·문서에는 손대지 않는다(§0-4). 보호 계정 가드와 무관(교사 계정 간 이동 없음).

## §4 복직 역이관

- 같은 마법사에 방향만 반대(B→A, 복직일 R) — 걸치는 주 + 개정판 치환 동일.
- **담임 복귀는 선택**(기본 = A 복귀, 예외 = 현 담임 유지 — 담임 배제 실사례 §0-8).
- 클래스룸: B를 공동교사에서 **제거**(사용자 확정 — "끝나고 나가실 땐 내보내는 게 좋겠어"). 제거 전 목록·확인 단계 필수(비가역 아님 — 재초대 가능하므로 확인 1회면 충분).
- 기간제 계정은 마법사 밖 — 기존 전출 처리 화면으로 링크만 안내.

## §5 안전장치

- 마법사는 **실행 전 미리보기 + 실행 후 요약**(생성된 주간 변경 n건·개정판 id·담임·클래스룸 결과)을 남긴다.
- 모든 산출물이 기존 모델(주간 변경·개정판·프로필·클래스룸 로스터)이므로 **되돌리기도 기존 경로 그대로** — 마법사 전용 롤백 개념을 만들지 않는다(이관 실수 시: 개정판 삭제 + 변경 취소 + 담임 재변경).
- 실행 권한 = 수퍼어드민 + 일과계(시간표 부분) 조합이 아니라 **수퍼어드민 단독**(계정·담임·클래스룸이 얽힌 행정 행위 — 연 몇 회의 저빈도라 좁게 시작).

## §6 비용

사람 이벤트(연 수 회) × 산출물 수십 건 — Firestore·API 비용 무시 가능. 클래스룸 초대는 Classroom API 기존 스코프 범위 확인 후(추가 스코프 필요 시 DWD 절차 — 선배포 금지 원칙, URL 안내만).

## §7 검증

- 셀프테스트(순수): ① 잔여 요일 수업 추출(D=수요일 → 수~금 수업만, 주말·이전 요일 제외) ② 치환 개정판 생성(A 셀만 B로, 나머지 바이트 동일·simul/venue 등록부 불변) ③ 담임 승계 대상 판정 ④ 역방향 대칭성(이관 후 역이관 = 원상).
- 실기기 시나리오: 시험 계정 2개로 이관 실행 → 주간시간표·내 시간표·나이스 목록에서 B 이름 확인 → 역이관 → 원상 확인.
