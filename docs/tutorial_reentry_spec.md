## 1. 문제 (실측 확인 2026-08-08)

- `pwa_guide` 화면(앱으로 설치하기 안내, `PWAInstallGuideTab`)으로 들어가는 진입점은 **헤더의 `PWAInstallPrompt` 버튼 하나뿐**이다 (`src/app/admin/page.tsx` 헤더, 사이드바에 메뉴 항목 없음).
- 그런데 `PWAInstallPrompt`는 앱 창(standalone)으로 실행 중이면 **클릭 불가 배지 "✓ 앱으로 실행 중"** 으로 바뀐다 (`src/components/pwa/PWAInstallPrompt.tsx`의 `isStandalone` 분기).
- 결과: 설치(또는 크롬 "앱으로 실행")를 마친 교사는 작업표시줄 고정·컴퓨터 켤 때 자동 실행·알림 켜기 등 **후속 단계를 따라갈 진입로가 없다.**

## 2. 배치 결정 (IA — 임의 변경 금지)

### ① 헤더 배지를 진입 버튼으로 승격 (핵심 수정)

`PWAInstallPrompt.tsx`의 standalone 분기를 **클릭 가능한 버튼**으로 바꾼다.

- 동작: 클릭 시 기존 미설치 버튼과 동일하게 `onOpenGuide()` 호출 → `pwa_guide` 화면 이동.
- 문구: **"✓ 앱으로 실행 중 · 사용 설정 안내"** (✓ 상태 표시 기능은 유지하되 안내 진입임을 문구로 드러냄).
- `title` 속성: "작업표시줄 고정 · 컴퓨터 켤 때 자동 실행 · 알림 켜기 따라하기".
- 스타일: 현재 에메랄드 배지 톤 유지 + hover 배경 변화 등 클릭 가능함이 보이게. 현재 버튼과 동일한 컴포넌트 구조(`<button>`) 사용.
- 헤더는 모든 메뉴에서 상시 노출되므로 "설치 여부와 무관하게 항상 보이는 위치" 요구를 이것으로 충족한다.

### ② 가이드 화면의 standalone 관점 분기 (문구만)

`PWAInstallGuideTab.tsx`는 이미 `isInstalled`를 갖고 있다. 이 값이 true일 때 상단 배너를 재진입 관점으로 분기한다 (레이아웃 변경 없음, 텍스트 분기만):

- 제목: "앱 사용 설정을 마저 따라해 보세요" (기존: "…앱으로 설치해서 쓰세요").
- 설명: "이미 앱으로 실행 중이시니 설치 단계는 건너뛰시고, 작업표시줄 고정 → 컴퓨터 켤 때 자동 실행 → 알림 켜기 단계만 아래 따라하기 화면에서 이어서 하시면 됩니다."
- 미설치 상태의 기존 문구·설치 버튼은 그대로 유지.

### ③ 하지 않는 것 (명시)

- **사이드바 메뉴 항목 추가 금지** — 헤더 진입점이 상시라 중복이고, 교사 화면 최소 구성 원칙과 충돌.
- **교사 홈·학생 포털에 카드 추가 금지** — 교사 홈은 "주간시간표+급식만" 지시(2026-08-07) 유지. 학생 포털은 이 기능 범위 밖(교사 PC 대상 기능; 학생 포털의 iorad 링크들은 졸업 데이터 이전용으로 무관).
- 화면 문구에 PWA·standalone 등 개발 용어 노출 금지 (기존 규칙).

### ④ 선택 사항 (이번 구현에서 제외, 사용자 확인 후)

iorad 임베드 URL의 `#trysteps-N`으로 "설치 이후 단계"부터 바로 시작시킬 수 있다. 몇 번째 스텝이 작업표시줄 고정 시작점인지는 튜토리얼 제작자(사용자)만 알므로, 사용자가 스텝 번호를 주면 ②의 분기에서 iframe 시작 스텝만 바꾸는 후속 1줄 수정으로 처리한다. 이번 구현에는 포함하지 않는다.

## 3. 완료 정의 (DoD)

- `npx tsc --noEmit` · `npm run build` 통과 (작성자 자가 통과 후 인계).
- 브라우저(미설치) 상태: 헤더 버튼 기존 동작 회귀 없음 — 클릭 → 안내 화면.
- standalone 상태 검증: Chrome DevTools → Rendering 탭 → "Emulate CSS media feature display-mode: standalone"으로 배지→버튼 전환·클릭 이동·배너 문구 분기를 확인.
- 변경 파일은 `PWAInstallPrompt.tsx`·`PWAInstallGuideTab.tsx` 2개를 벗어나지 않을 것 (벗어나야 하면 중단하고 확인 요청).
