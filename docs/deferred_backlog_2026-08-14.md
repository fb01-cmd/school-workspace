## 0-1. 🔴 추론 밀도로 다시 세운 순위 (2026-08-14 사용자 요청)

사용자: *"우선순위를 고려할 때 **하드하게 돌려야 하는 순위**로도 고려해줘. **Fable급으로 돌려야 하는 건 미리 명시**를 해주고."*

**A 목록에는 Fable급이 없다.** A1~A6은 전부 문서·소규모 코드·기구현 확인이라 Opus나 Antigravity로 충분하다. Fable을 여기 쓰면 낭비다.

### F1. 🟣 **Fable급 — 신학기 백지 편성 경로** (오늘 유일한 Fable 대상)

> **✅ [2026-08-14 당일 종결]** 실험 통과 — 하드 0·미배정 0·결정론·소프트 38(컴시간 39보다 낮음).
> `compileSectionsFromHours` 신설 + `scripts/solve_blank.ts`. **"그리드는 알려주는데 시수표는
> 모르는 정보" 5종 목록 확보** → [`phase9c_blank_run_2026-08-14.md`](./phase9c_blank_run_2026-08-14.md) §3
> = 시수표 입력 화면·C2 코호트 등록부의 사양. 아래 원문은 착수 전 분석으로 보존.

`solver.ts:97-98`이 스스로 적어 뒀다:
> *"현행 그리드 + 등록부 → 섹션 목록. **신학기(그리드 없는) 경로는 시수표+등록부 컴파일러를 Phase C-2에서 추가한다**"*

**즉 9c의 마지막 큰 조각이 통째로 비어 있다.** 오늘 재현 실험이 성공한 것은 **현행 그리드에서 역산**했기 때문이고(§3-2), 그건 *"답이 있는 문제를 다시 푼 것"* 이다. **컴시간 없이 짜는 능력은 아직 증명되지 않았다.**

- 시수표 입력 화면도 없다(`HoursRequirement`를 쓰는 컴포넌트 0건).
- 11월 말 검증 시한의 **본체가 이것**이다.

**왜 Fable급인가** — 그리드가 없으면 다음을 전부 다른 출처에서 구성해야 하고, 그 매핑 설계가 이 작업의 전부다:

| 그리드가 주던 것 | 백지에서는 어디서 오나 |
|---|---|
| 학급별 과목·교사·시수 | 시수표 (입력 필요) |
| 동시수업 묶음 | 등록부 (있음) |
| 특별실 점유 | 등록부 (있음) |
| 연속 블록 | 등록부 (있음) |
| **창체·SLAT 고정 슬롯** | **없음** ← C2(교육과정 코호트 등록부)가 여기서 필수가 된다 |
| 학년별 요일 운영 교시수 | 설정에서 역산 or 입력 |

### F1을 오늘 검증 가능한 형태로 쪼개는 법 (핵심 아이디어)

**시수표를 새로 입력받을 필요가 없다.** `deriveHoursFromGrids`가 이미 있다(`validate.ts:118`).

```
현행 그리드 → deriveHoursFromGrids → 시수표
                                        ↓
                        compileSectionsFromHours (신설)   ← 그리드를 보지 않는다
                                        ↓
                                   솔버 → 검사기
```

**그리드에서 시수표만 뽑은 뒤 그리드를 버리고** 시수표만으로 섹션을 만들어 돌린다. 결과를 오늘의 기준선(하드 0·소프트 38)과 비교하면:

- **성공하면** → 백지 편성 능력이 증명된다. 11월 시한의 핵심 위험이 사라진다.
- **실패하면** → **무엇이 부족한지가 정확히 드러난다.** "그리드는 알려주는데 시수표는 모르는 정보"의 목록이 나온다 — 그게 곧 시수표 입력 화면의 사양이고, C2 등록부의 요구사항이다.

**어느 쪽이든 값지다.** 그리고 이건 **비교 기준이 있는 실험**이라 오늘 안에 판정이 난다.

| 등급 | 항목 | 왜 |
|---|---|---|
| **🟣 Fable** | **F1 신학기 백지 편성 (설계 + 시수표 컴파일러 + 대조 실험)** | 9c 마지막 큰 조각. 추론 밀도 최고. **8/24 전에 해야 한다** |

## 1. 그래서 지금 뭘 하나

**A1 → A6 확인 → A2·A3 → A4** 순을 권한다.

- **A1**은 오늘 만든 백업이 실제로 쓰이게 만드는 마지막 한 걸음이다. 지금 안 하면 "만들었지만 아무도 모르는 기능"이 된다.
- **A6**은 확인만 하면 로드맵 한 줄이 닫힌다(비용 거의 0).
- **A2·A3**은 각각 작고 독립적이라 Antigravity가 병렬로 할 수 있다.
- **A4**(나이스 내보내기)는 오늘 형식을 다 파악했으므로 **정보가 가장 신선한 지금** 만드는 것이 싸다. 미루면 다시 파악해야 한다.

**B1은 시한이 있다** — 8/24. 나머지 B·C·D는 지금 건드리지 않는다.
