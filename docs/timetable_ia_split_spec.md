# 시간표 메뉴 IA 분리 스펙 v1 — 작성 vs 운영 (2026-08-11)

> **배경 (사용자 지시 2026-08-11)**: "시간표를 짜는 메뉴와 학기 중 운영하는 메뉴는 아예 완전 분리 필요." 현행 "시간표 관리 (일과계)" 단일 메뉴에 탭 17종이 동거 — 학기 중 매일 쓰는 도구(주 운영·교환·직권)와 학기 전에만 쓰는 도구(가져오기·등록부·자동 작성)가 섞여 실무 동선이 흐려짐. 9c 완성으로 작성 계열 탭이 계속 늘어나는 중이라 지금 갈라야 재작업이 최소.
> IA 배치는 Claude 소관 (AGENTS.md 협업 규칙 §1 추가 조항).

## 1. 분리 원칙

**"언제 쓰는 도구인가"로 가른다** — 학기 전·개정 시 = 작성, 학기 중 상시 = 운영. 등록부(이동수업·특별실 등)는 운영 엔진(교체 후보)도 소비하지만 **관리 행위 자체는 셋업 성격**이므로 작성 쪽.

## 2. 사이드바 — 기존 1메뉴 → 2메뉴

| 새 메뉴 | 이름(눈높이) | 기본 탭 |
|---|---|---|
| A | **시간표 운영** | 주 운영 (휴업·단축) |
| B | **시간표 작성** | 자동 작성 |

기존 "시간표 관리 (일과계)" 메뉴는 제거. 위치는 현행 자리에 A·B 연속 배치.

## 3. 탭 배치표

**A. 시간표 운영 (학기 중 상시)**
1. 주 운영 (휴업·단축)
2. 학사일정
3. 수업교환 신청 요청대장
4. 직권 배정
5. 공강 교사
6. 교사별 시간표 · 학급별 시간표 (열람 2종)
7. 나이스 입력 목록 — **현 NEIS 탭의 섹션 1(수업교환 목록)만**
8. 시수 집계

**B. 시간표 작성 (학기 전·개정 시)**
1. 가져오기 & 학기 관리
2. 제약 등록부 5종: 이동수업 · 특별실 · 특별교사 금지 · 연속수업 · 복수교사
3. 자동 작성 (초안·AI 진단)
4. 기초시간표 개정
5. 나이스 일괄 내보내기 — **현 NEIS 탭의 섹션 2(사전 검증·매핑표)만** (F-1b에서 한 화면에 합쳤던 것을 분리 이동 — 두 섹션은 용처가 다름이 이번 지시로 확정)

## 4. 구현 지침 (Antigravity)

- TimetableSection을 운영/작성 두 컴포넌트로 분리하되 **탭 컴포넌트들은 무수정 이동** — 설정 로드·권한 가드·activeTermId 전달 로직은 공용 훅/래퍼로 추출해 중복 금지.
- NeisExportTab만 실제 분할: 섹션 1 → 운영 "나이스 입력 목록" 탭, 섹션 2 → 작성 "나이스 일괄 내보내기" 탭 (상태·API 호출은 이미 섹션별 독립이라 기계적 분리).
- 권한: 두 메뉴 모두 현행과 동일(일과계+super_admin, 참관자는 운영의 요청대장·주 목록만). authz.ts 무변경.
- 사이드바 라벨·순서 외 신규 기능 0 — 순수 재배치. 완료 기준: 17종 탭 전부 어느 한쪽에 존재(유실 0), tsc·build 통과.

## 5. 이 스펙과 함께 처리 (동일 사이클 권장)

**메타문구 일소** — 사용자 화면에서 내부 문서 참조 제거 (AGENTS.md ui-copy-rules 신설 근거):
- 실측: "매뉴얼 §6-가"(특별교사 금지)·"§6-라"(연속수업)·"§6-사"(복수교사)·"컴시간 매뉴얼 §8-다"(자동 작성 2곳) 등.
- 원칙: §번호·매뉴얼 조항·Phase명·스펙 파일명은 **코드 주석으로 이동**, 화면에는 기능 설명만.
- **"컴시간" 언급의 정밀 기준 (2026-08-11 계획 리뷰에서 정밀화)**: 제거 대상은 "계승·재현·매뉴얼 §인용" 같은 **설계 근거 언급**뿐. 가져오기 화면처럼 **사용자가 실제로 컴시간을 조작해야 하는 지시문**("컴시간에서 내려받은 전체시간표 엑셀을 업로드")에서는 유지 — 출처 프로그램명을 지우면 어떤 파일을 올려야 하는지 알 수 없게 된다. 기능 설명 vs 설계 근거를 구분할 것.
