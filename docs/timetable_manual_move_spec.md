## §0 설계 제1원칙 — 표가 계속 보이고 있어야 한다 (사용자 지시)

> *"시간표는 [월요일 3교시 이현준 → 화요일 2교시 지상인] 처럼 쓰여 있으면 생각하는 데 한참 걸린다고. 그냥 표로 뭐가 계속 보이고 있어야 건드리기 좋아."*

1. **모든 정보는 그리드 위에 얹는다.** 이동 후보·감점 변화·연쇄 영향을 **텍스트 문장으로 쓰지 않고** 시간표 표의 칸 색·뱃지로 보여준다. 텍스트 표기(「월3→화2」류)는 화면 어디에도 쓰지 않는다 — 로그·확인 대화상자도 미니 그리드로 그린다.
2. **모달 최소화.** 컴시간은 이동할 때마다 「이동시 문제점」 팝업이 흐름을 끊는다 — 우리는 문제를 **집는 순간 칸 위에 미리** 보여줘서 팝업 자체가 필요 없게 한다.
3. **화면 문구 규칙 준수** (AGENTS ui-copy-rules): 개발 용어(Kempe·LNS·소프트/하드) 금지. 화면 용어는 「직접 조정」·「잠깐 빼두기」·「이 칸으로 이동하면 −1점」 같은 눈높이 표현.
4. **PC 전용이다 (사용자 지시 2026-08-22: "모바일 생각하지 마. 어느 누구도 이런 걸 모바일로 안 해").** 두 그리드 병치가 성립하는 넓은 화면만 지원한다 — 좁은 화면(예: 1024px 미만)에서는 `[직접 조정]` 토글을 **비활성화하고 안내 문구를 제공한다**(미표시가 아니라 비활성 + 안내, 기존 열람·자동 작성 기능은 그대로). **글씨 크기 스펙의 360px 합격 조건은 이 모드에 적용하지 않는다** — 진입 자체가 안 되는 화면이므로 (font_size_spec 대상에서 명시 제외, 검사 예외 사유 주석 필수).

**고친다 (컴시간의 약점)**

1. **가능/불가만 보여주고 「얼마나 나빠지는지」는 안 보여준다** → 우리는 후보 칸마다 **감점 변화 숫자**를 얹는다(§2-3). 이게 최대 개선점 — 컴시간 사용자는 이동해 보고 배정검색을 다시 돌려야 결과를 안다.
2. **문제점이 이동 시점의 팝업** → 집는 순간 칸 위에 사전 표시.
3. **90년대 밀도의 6패널** → 패널 수는 3+1로 줄이되 정보량은 유지(§2-2). 교사↔학급 축 전환이 클릭 왕복 없이 즉시.
4. **점수 조망 부재** → 상단에 현재 총점·시작 대비 변화 상시 표시(이미 있는 감점 상세와 연동).

## §2 우리 화면 설계

### 2-1. 위치(IA)

- **새 메뉴가 아니다.** 「시간표 작성」 초안 편집기(`DraftAutoTab`)의 기존 3면 편집기를 **직접 조정 모드**로 확장한다. 진입 = 편집기 상단 도구줄의 `[직접 조정]` 토글 하나.
- 기존 요소 재사용: 학급 그리드(뷰어), 교사 주간 시간표 카드(파생), 감점 상세 패널, 실행취소/다시실행(`draft_op`·`opCursor`), What-if 검증, 해결안 찾기.

### 2-2. 화면 구성 (3+1패널 — 전부 상시 표시, 모달 없음)

```
┌─ 상단 바: 총점 27.5점 (시작 25.5 · +2)   [실행취소] [다시실행] [작업기록] [직접 조정 ⏻]
├────────────────────┬────────────────────────┐
│ Ⓐ 학급 그리드       │ Ⓑ 교사 그리드           │   ← 나란히, 같은 크기
│   (지금도 있는 것)   │   (지금 카드를 승격)      │
│   2-5반 주간표      │   장예빈 선생님 주간표     │
├────────────────────┴────────────────────────┤
│ Ⓒ 잠깐 빼둔 수업 트레이  [비어 있으면 얇게 접힘]      │
├─────────────────────────────────────────────┤
│ Ⓓ 감점 상세 (기존 패널 그대로 — 조작마다 실시간 갱신)  │
└─────────────────────────────────────────────┘
```

- **Ⓐ·Ⓑ 연동이 핵심이다** (컴시간 ①④⑤의 계승): Ⓐ에서 칸에 마우스를 올리면 그 수업 교사의 주간표가 Ⓑ에 즉시 뜬다(지금 클릭인 것을 hover로). Ⓑ에서 칸을 올리면 그 학급이 Ⓐ에 뜬다. **어느 쪽에서든 집을 수 있다.**
- **[2026-08-22 개정 — 고정(📌)과 따라오기의 분리]** 따라오기만 있으면 특정 교사·학급을 붙잡고 작업할 수 없다(사용자 실기기). ⓐ Ⓐ·Ⓑ 각 그리드 머리에 **📌 고정 토글** — 고정하면 hover 연동을 무시하고 명시적 선택(학년·반 칩, 교사 검색)으로만 바뀐다 ⓑ **「시간표 추가」**로 고정 전용 그리드 패널을 최대 2개 추가(교사 또는 학급 선택, 항상 고정) — "따라오기 1 + 고정 1"을 교사·학급 어느 조합으로든 만들 수 있다. 추가 패널에서도 집기·후보 표시는 동일하게 동작한다.
- 학급/교사 선택은 기존 학년·반 칩과 교사 검색(이름 자동완성 — `AutocompleteInput`)으로.

### 2-3. 집기 → 신호등 (컴시간 색 6종의 단순화 + 감점 숫자)

칸을 클릭하면 「집은 상태」가 되고(칸 테두리 강조), **두 그리드의 모든 칸이 즉시 3색**으로 칠해진다:

| 색 | 뜻 | 상호작용 |
|---|---|---|
| 초록 | 옮길 수 있고 **점수가 좋아지거나 같다** — 칸 귀퉁이에 `-1` 같은 변화 뱃지 | 클릭 = 즉시 이동 |
| 노랑 | 옮길 수 있지만 **감점이 생긴다** — `+2` 뱃지, hover 시 어떤 감점인지 그리드 위 말풍선(예: 「연속 3교시가 생겨요」) | 클릭 = **그대로 이동**(감수 강행 — 컴시간 [이동 실행] 계승). 확인 팝업 없음, 상단 총점이 변할 뿐 |
| 회색(빗금) | **하드 위반** — 옮길 수 없다(교사 겹침·고정 수업·특별실 겹침·동시수업 등). hover 시 이유 한 줄 | 클릭 무반응 |
| (점유 칸) | 다른 수업이 있는 칸도 초록/노랑이 될 수 있다 = **맞교환 또는 밀어내기**(§2-4) | 클릭 = 교환이면 즉시, 밀어내기면 연쇄 시작 |

- 뱃지 숫자 = **공식 감점 변화**(검사기 등가). 클릭 1회당 후보 ≤35칸×2그리드, 워커에서 수십 ms.
- 집기 해제 = 같은 칸 재클릭 또는 Esc (컴시간과 동일).
- **[2026-08-22 승격] 셀 불변 조항은 편집기 그리드의 상시 규칙이다** — 직접 조정 후보 표시만이 아니라 **평상시 렌더에도** 적용한다. 잠금·이동불가 설명 문장이 든 셀이 다른 셀보다 커서 hover 연동 때 판 전체가 출렁이고 마우스가 튕기는 것이 실측됐다(사용자: *"마우스 오버할 때마다 위치가 달라져… 원하는 작업을 하는 게 매우 힘들어"*). 모든 셀은 같은 높이, 문장류는 전부 hover 툴팁.
- **셀 불변 조항 (2026-08-22 실기기 1차에서 위반 실측 — 감점 문장이 셀 안에 들어가 월요일만 보였다)**: 집기·후보 표시는 **셀의 크기·격자 레이아웃을 절대 바꾸지 않는다.** 셀 안에 들어갈 수 있는 것 = 기존 내용(과목·교사) + 우상단 소형 뱃지(±숫자) + 배경 틴트 + 소형 아이콘(⇄)까지다. 감점 내역 문장·차단 사유 문장·잠금 안내는 **hover 말풍선으로만** 나온다. 주간 5일이 집기 전과 후에 똑같이 한눈에 보여야 한다 — §0-1의 격자판 적용이다.

**집기 단위 규약 (2026-08-22 Codex 사전 검토 R4 반영)**

- **동시수업(밴드) 셀·자리표시(창체·SLAT) 셀은 집을 수 없다** — 현행 편집기의 차단(`DraftAutoTab` 🔒 안내)을 그대로 계승한다. 밴드 통째 이동은 이 스펙의 범위 밖(후속 검토 항목으로만 남긴다 — 여러 학급·특별실이 한 몸이라 연쇄 규약이 별도로 필요하다).
- **연속 블록(2교시+ 수업)은 블록 통째로 집는다** — 쪼개서 한 교시만 옮길 수 없다(H9 보호). 후보 칸 계산도 블록 길이 기준(연속 빈 칸만 초록/노랑).

### 2-4. 연쇄(루미큐브) — 밀어내면 밀려난 카드가 손에 들린다

점유 칸에 떨어뜨렸는데 교환이 성립하지 않으면(상대 수업이 내 자리로 못 옴), 컴시간처럼 모달로 묻지 않고:

1. 내 수업이 그 칸에 들어가고, **밀려난 수업이 「들고 있는 카드」가 되어 커서에 붙는다** — 트레이 위에 「지금 들고 있음: 2-5반 연극(장예빈)」 미니 카드 표시.
2. 다시 두 그리드가 그 카드 기준으로 3색 재계산 — 계속 굴린다.
3. 끝내는 법 셋: ⓐ 빈 칸/교환 성립 칸에 내려놓기 ⓑ 트레이에 「잠깐 빼두기」 ⓒ 실행취소(연쇄 전체가 한 단위로 되돌아감 — 저널 원복).
4. 들고 있는 동안 상단 총점은 「미완료(들고 있는 수업 1)」 상태 표시 — 게시·저장은 가능하되 미배정으로 정직 집계(기존 미배정 목록 재사용).

### 2-5. 잠깐 빼두기(주차장) — 컴시간 「걸림돌 삭제」의 양성화

- 아무 수업이나 트레이로 드래그(또는 집은 상태에서 트레이 클릭) = 판에서 빠진다. 컴시간은 「삭제」라 부르지만 실제로는 재배정 전제의 임시 조치 — 우리는 이름부터 「잠깐 빼두기」.
- 트레이의 카드를 집으면 다시 3색 모드 — 어디로든 되돌린다.
- **게시 관문**: 트레이가 비어야(그리고 하드 0이어야) 「기초시간표로 채택」 활성화. 기존 미배정 검사에 자연 합류 — 새 검사 불필요.

### 2-6. 작업기록 (컴시간 작업기록 열람 대응)

- 이미 있는 것: `draft_op` 단위 실행취소/다시실행. 얹는 것: `[작업기록]` 버튼 → 조작 목록(시각 + **미니 그리드 썸네일**, 텍스트 표기 금지)에서 클릭 한 번으로 그 시점 복원(= opCursor 이동, 신규 서버 작업 없음).
- **(2026-08-22 실기기 피드백 — M1 임시판의 「#1 맞교환/이동 (2학년 5반)」 라벨로는 뭘 했는지 알 수 없다: *"작업 기록은 구체적으로 줘야 할 것 같아"*)** M3에서 항목 라벨에 최소 **과목·교사**가 보여야 하고(예: 연극(장예빈) ⇄ 인윤(류상오) — 위치 텍스트는 여전히 금지, 위치는 썸네일이 말한다), 본형은 미니 그리드 썸네일이다.
- 연쇄 한 판(집기~내려놓기)은 **op 1건**으로 묶는다 — 실행취소 한 번에 한 판이 통째로 돌아온다.
- **(Codex 사전 검토 R5 반영)** 현행 `BaseRevisionOp`에는 `swap`·`edit_cell`·`swap_pair`뿐이라 연쇄·빼두기를 표현할 타입이 없다 — **신규 op 2종이 Claude 몫 선행 작업이다**: `chain`(이동 목록을 한 단위로)·`park`/`unpark`(빼두기/복귀). 재생기(`applyRevisionOps`)의 관용 규약(이미 저장된 초안이 재생 불가가 되면 안 된다)을 지켜 설계한다.

### 2-7. 칸 잠금 (컴시간 이동금지/임시금지 대응 — 후순위)

사람이 확정한 칸에 우클릭 「이 칸 고정」 = 이후 자동 도구(해결안 찾기·재작성)가 못 건드림. **M3로 미룬다** — 없어도 굴리기는 성립.

## §4 분담·단계 (AGENTS §1 — IA는 이 문서가 명시했다)

- **Claude**: 증분 채점기 분리·후보 일괄 채점 API·연쇄 op 설계 (순서 의존·원복 로직 — §1-2 직접 구현 영역).
- **Antigravity**: 패널 배치·3색 칠·드래그/집기 상호작용·트레이·작업기록 UI (이 스펙의 §2가 배치 원본).
- **단계**: **M1** = 집기→3색(+뱃지)→빈 칸 이동·맞교환 (연쇄 없이) / **M2** = 연쇄 + 빼두기 트레이 + 연쇄 묶음 op / **M3** = 작업기록 썸네일 목록 + 칸 잠금.
- 각 단계 관문: tsc·build·`check:ui`·`check_ui_removals` + **실기기에서 사용자가 실제 남은 위반 1건(장예빈 수 1-2-3)을 이 도구로 굴려보는 것** — 이게 통과 기준이자 존재 이유다.

## §5 성능·안전 주의

- 후보 채점은 **읽기 전용 시뮬레이션**(그리드 복사본) — 실패해도 판이 안 더러워진다. 적용은 기존 `draft_op` 경로만 통과.
- **(Codex 사전 검토 R2 반영)** 현행 409는 하드 위반·연산 불성립 관문이지 **동시 편집 관문이 아니다** — 저장이 버전 비교 없이 update라 두 창이 서로를 덮을 수 있다(`server.ts` 실측). 직접 조정은 조작 빈도가 높아 이 구멍이 실제로 밟힌다 → **draft_op에 opCursor 기반 선행조건(불일치 시 충돌 응답 + 화면 새로고침 유도)을 추가한다 (Claude 몫, M1 선행).**
- **(Codex 사전 검토 R3 반영)** 빼두기 트레이는 `customUnplaced` 직접 저장에 얹지 않는다 — 그 경로는 그리드·op와 정합 검증이 없다. 트레이 상태는 **`park`/`unpark` op의 재생 파생값**으로만 만들어 저장·재접속·동시 편집에서 일관되게 한다.
- 후보 채점 ≤70칸 × 증분 delta — 프리페치·Firestore 추가 읽기 0건 (모든 계산은 이미 로드된 초안 데이터로 브라우저에서).
- 게시(기초시간표 채택) 관문 불변: 하드 0 + 미배정 0(트레이 포함).
