# 화면 확인 체크리스트 (사용자용)

> 화면이 제대로 도는지 **직접 눌러 보고 확인하는** 목록이다. 코드 지식은 필요 없다.
> 작성 배경: 2026-08-15, 통 이동 UI 재배선에서 지시에 없던 기능 4건이 조용히 사라진 사고.
> 타입 검사·빌드는 "버튼이 없어진 것"을 잡지 못하므로, 이 목록이 마지막 관문이다.

**어디서**: https://portal.hmh.or.kr → 왼쪽 메뉴 **시간표 운영** → **직권 배정** 탭
**준비**: 위쪽에서 교사를 한 명 고른다. (아무나 상관없다. 아래 A~D는 어느 교사든 확인된다.
실데이터로 확인하기 좋은 자리 = **김진만 선생님 / 2026-08-10 주 / 2학년 4반 월요일 5교시**)

> ⚠️ **끝까지 누르지 말 것**: 직권 배정은 신청이 아니라 **즉시 실제 반영**이다.
> **[단건 즉시 반영]** 과 양해 확인창의 마지막 반영 버튼은 누르지 않는다. 그 앞까지는 아무것도 저장되지 않는다.
> 실수로 반영했다면 요청대장에서 **되돌리기**로 원상복구된다(묶음도 전 반이 한 번에 되돌아간다).

## A. 보강 배정 — 2026-08-15 복원분 (가장 중요)

한때 목록 자체가 사라져 **보강 배정이 아예 불가능**했던 자리다.

- [ ] **A-1** 수업 칸을 하나 누른다 → 오른쪽에 후보 영역이 나타난다
- [ ] **A-2** 후보 영역 위쪽의 **[👤 보강]** 을 누른다 → **"보강 가능 교사 목록 (N명)"** 이 실제로 나온다
      *(인원수만 있고 목록이 없으면 실패)*
- [ ] **A-3** 목록의 각 줄 오른쪽에 **"누계 N회"** 가 보인다 *(누가 이미 많이 했는지 = 공평 배정 근거)*
- [ ] **A-4** 같은 과목 교사에게는 초록색 **"동일 과목"** 딱지가 붙는다 *(해당자가 없으면 넘어간다)*
- [ ] **A-5** 교사 한 명을 누르면 오른쪽에 **선택된 보강 후보**로 이름·누계·동일 과목이 표시된다

## B. 징검다리 체인 — 2026-08-15 복원분

- [ ] **B-1** 옮기고 싶은 **수업 칸**을 누른다 → 그 다음 **빈 교시**를 누른다
- [ ] **B-2** 창이 열리면서 **"이동시킬 원본 수업"이 방금 고른 그 수업으로 이미 지정**돼 있다
      *(수업을 다시 고르라는 목록이 뜨면 실패 — 이번에 신고하신 증상)*
- [ ] **B-3** **[징검다리 경로 탐색]** 을 누른다 → 경로가 나오거나 "없다"는 안내가 나온다
- [ ] **B-4** 경로를 **못 찾은 경우**, 그 안내 아래에 **[🔄 3단계까지 넓혀 다시 탐색]** 버튼이 보인다
      *(경로를 찾은 경우엔 이 버튼이 안 나오는 게 정상 — 넘어간다)*

## C. 담기 이탈 경고 — 2026-08-15 복원분

- [ ] **C-1** 아무 후보나 골라 **[🛒 담기]** 로 하나 담는다
- [ ] **C-2** 그 상태에서 **브라우저 새로고침(F5)** 을 눌러 본다 → **"이 페이지를 나가시겠습니까?"** 확인창이 뜬다
- [ ] **C-3** **[취소]** 를 눌러 페이지에 남는다 → 담긴 항목이 그대로 있다
- [ ] **C-4** 확인이 끝나면 담기 목록을 비운다

## D. 이동수업(묶음) 이동 — 2026-08-15 신규 + 화면 수정분

- [ ] **D-1** 보라색 **🔀 이동수업** 딱지가 붙은 수업 칸을 누른다 *(막히지 않고 후보가 나와야 정상)*
- [ ] **D-2** 후보가 **빨간색 "⚠️ 양해 필수"** 로 시간표 안에 섞여 나온다
- [ ] **D-3** **표가 깨지지 않는다** — 특정 요일 칸만 옆으로 늘어나지 않고, 후보 칸 글씨가
      **"묶음 이동 · N개 반"** 처럼 짧게 나온다 *(긴 과목 나열이 그대로 박혀 있으면 실패)*
- [ ] **D-4** 그 빨간 후보를 누르면 경고창에 **"선생님 수업도 함께 옮겨집니다"** 문구가 있다
- [ ] **D-5** 경고창에 **어느 반의 무슨 수업이 누구와 바뀌는지 반별로** 나열된다
- [ ] **D-6** 맨 아래 **"양해 필요 당사자"** 명단에 **같은 이름이 두 번 나오지 않는다**
      *(한 선생님이 두 역할이면 `홍길동 선생님(7반 기하·미적Ⅰ)`처럼 한 줄로 합쳐진다)*
- [ ] **D-7** 후보를 고른 뒤 오른쪽 버튼이 **[담기] 없이 [⚡ 단건 즉시 반영] 하나만** 넓게 있다

## E. 기존 기능이 그대로인지 (회귀 확인)

- [ ] **E-1** 일반(묶음 아닌) 수업으로 **맞교환 후보**가 초록색으로 나오고 점수가 보인다
- [ ] **E-2** 일반 후보는 **[담기]와 [단건 즉시 반영] 두 버튼이 모두** 있다
- [ ] **E-3** 여러 건을 담으면 **담기 목록**에 쌓이고, 각 항목을 개별 삭제할 수 있다
- [ ] **E-4** 특별실이 겹치는 후보는 빨간 **"장소 조율"** 경고로 나온다 *(해당 후보가 없으면 넘어간다)*

## F. 이동수업(묶음)을 **다른 주로** 옮기기 — 2026-08-15 신규

지금까지 묶음 수업은 **같은 주 안에서만** 옮길 수 있었다. 이제 다음 주·다다음 주로도 옮겨진다.
(같은 학기 안에서만 된다. 다른 학기 주는 여전히 안 나온다.)

> 🚩 **F절만은 배포된 뒤에 확인한다.** A~E와 달리 F는 **새 기능**이라, 코드가 포털에 올라가기 전에는
> 다른 주 칸이 전부 비어 있는 것이 **정상**이다(고장이 아니다). 2026-08-15에 이 안내가 없어
> 배포 전 화면을 보고 "시작부터 실패"로 읽힌 일이 있었다.
> **확인 순서: ① push·배포 완료 → ② 포털 새로고침 → ③ F-1부터.**
> 새 기능 확인 항목을 이 파일에 추가할 때는 **"언제부터 보이는지"를 반드시 함께 적는다.**

**어디서 ①: 직권 배정 탭** — 주가 위아래로 여러 개 이어져 나오는 화면이다.

- [ ] **F-1** 보라색 **🔀 이동수업** 딱지가 붙은 수업 칸을 누른다
- [ ] **F-2** **아래쪽 다른 주 표에도** 빨간 **"⚠️ 양해 필수"** 후보가 나온다
      *(같은 주에만 나오고 다른 주는 전부 비어 있으면 실패)*
> 📍 **F-3·F-4는 어디를 보나**: 후보를 클릭하면 **오른쪽 「후보 상세 및 미리보기」 패널**에 바로 뜬다.
> (마지막 반영 버튼을 눌렀을 때 나오는 확인창이 아니다 — 그 전에 이미 보인다.)

- [ ] **F-3** 오른쪽 패널의 **「교환 위치」** 줄에 **이번 주가 아닌 날짜**가 찍힌다
      *예: `교환 위치: 8/21(금) 1교시` — 소스가 8/11(화)인데 8/21이면 다른 주로 가는 것이 맞다*
- [ ] **F-4** 그 아래 **⚠️ 당사자 양해 필요 (동시수업 묶음 이동)** 상자 안에 **반별로 한 줄씩** 나온다
      *예: `2반: 일화(김진만) ↔ 권성민(영Ⅱ)` / `3반: 중화(이경호) ↔ 김보현(도탐)`*
      *상대 자리가 빈 교시인 반은 `↔` 대신 **"빈 교시로 이동"** 으로 나온다*
- [ ] **F-4b** 그 상자 맨 아래 **「양해 필요 당사자」** 에 **위 줄에 등장한 선생님이 빠짐없이** 들어 있다
      *(같은 이름이 두 번 나오면 실패 — D-6과 같은 확인)*
- [ ] **F-5** 표가 깨지지 않는다 — 다른 주 표도 요일 칸이 옆으로 늘어나지 않는다

**어디서 ②: 교사 화면 — 지금은 확인할 수 없다 (2026-08-15 확정)**

담당자가 **휴직 중이라 본인 시간표가 없고**, 이 화면은 로그인한 본인 것만 보여준다(다른 교사로 바꿔
보는 기능은 없다). **직권 탭에서 대신 해 보는 것도 안 된다** — 직권 반영·되돌리기는 관련 선생님
전원에게 **실제로 알림이 발송**되기 때문이다(실사용자에게 가는 알림이 유일한 금지선).

그래서 아래는 **개학 후 실제 선생님이 처음 쓸 때** 확인한다. 지금 억지로 하지 않는다.

- [ ] **F-6** *(개학 후)* 묶음 수업 칸을 누르면 **여러 주의 후보가 함께** 나온다
- [ ] **F-7** *(개학 후)* 다른 주 후보를 골라 **양해 확인란을 체크**하고 신청된다
- [ ] **F-8** *(개학 후)* 신청 후 요청대장에 **🧩 통 이동** 카드가 뜨고, 옮겨 갈 **주(날짜)** 가 보인다

**아래 3개는 사람이 다시 볼 필요가 없다 — 기계 검증으로 이미 통과했다.**
(`scripts/verify_simul_move_phase3.ts` [9] — 실데이터로 신청→승인→두 주 반영→되돌리기까지 돌리고
알림은 억제, 흔적은 하드 삭제. 맞교환 반·빈 교시 반 두 경우 + 직권까지 각각 통과.)

- [x] **F-9** 승인하면 **두 주가 동시에** 바뀐다 — 기계 검증 `[9-6]`
- [x] **F-10** 옮겨 간 주에서도 **🔀 이동수업 딱지가 유지**된다 — 기계 검증 `[9-6]`
      *(이 검사는 실제로 2026-08-15에 결함 1건을 잡아냈다. 옮기면 딱지가 사라지던 것을 고쳤다.)*
- [x] **F-11** 되돌리기하면 **두 주가 모두** 원래대로 — 기계 검증 `[9-7]`

> 💡 **안 나올 수도 있는 경우 (정상)**: 한 반이 같은 교시에 묶음 수업을 **두 개** 듣고 있으면
> 그 수업은 다른 주로는 안 옮겨지고 같은 주 후보만 나온다. 이건 막아 둔 것이지 고장이 아니다.

## 이 목록을 앞으로 쓰는 법

화면을 건드리는 작업(Antigravity·Claude 누구든)이 끝나면 **푸시 전에 이 목록을 한 번 훑는다.**
새 기능이 추가되면 그 확인 항목을 이 파일에 **한 줄 추가**한다 — 목록이 길어지는 것이 곧 그물이 촘촘해지는 것이다.

기계로 먼저 걸러내는 도구도 있다(개발자용):

```
bash scripts/check_ui_removals.sh <작업 시작 전 커밋>
```

사라진 버튼·기능·화면 문구를 목록으로 뽑아 준다. 뜬 항목마다 **"이 삭제가 지시서에 있었나?"** 를 묻고,
없던 것이면 되살린다. 자세한 규칙은 `AGENTS.md` ①-1.
