# 쪽지 2단계 스펙 — 이미지 첨부 (전부 Drive) + 양해 쪽지 전송

> 2026-08-15 작성 (Claude Fable 5). 1단계 스펙 [`memo_spec.md`](./memo_spec.md)의 "2단계: 첨부 파일 실체" 항목의 확정판.
> **사용자 확정 (2026-08-15)**: 용량 정책 = **전부 Drive** — 모든 첨부를 Drive에 올리고 쪽지에는 참조만 싣는다. 경로 하나·용량 제한 사실상 없음·0원.
> 로드맵 연계 2건을 이 스펙이 흡수한다: ① **양해 쪽지 전송 버튼**(§5) ② **첨부 Drive 폴더 체계화**(§2).

## §0 원칙

1. **쪽지 문서에는 파일 실체를 넣지 않는다.** Firestore에는 Drive 파일 참조(`attachments[]`)만. Vercel 4.5MB 제한·Firestore 1MB 문서 제한을 구조적으로 우회한다.
2. **v1 범위는 이미지만** (`image/png`·`image/jpeg`·`image/webp`). 첫 실수요가 양해 이미지(PNG)다. 일반 파일은 실수요 후 — MIME 화이트리스트 한 줄 확장으로 열린다.
3. **첨부 열람 권한 = 쪽지 열람 권한과 동일 집합.** 도메인 전체 링크 공유는 쓰지 않는 것이 기본(첨부에 개인정보가 실릴 수 있다 — 시간표·명단). 예외는 §3-3.
4. 무료 원칙: Drive 15GB(계정 기본) + 파기 회전(§6)으로 0원 유지.

## §1 저장 소유 계정 — `hmnotice@` Drive

| 후보 | 판정 |
|---|---|
| 발신 교사 본인 Drive | ❌ 퇴직·전출 시 계정 삭제와 함께 첨부 소실 — 수신자가 열람 기간 내 못 보게 됨 |
| `fb01@` | ❌ 인프라 소유 계정 — 코드·배포·키의 자리이지 콘텐츠 저장소가 아님 (역할 구분 원칙) |
| **`hmnotice@`** | ✅ **채택.** 알림 발신 전용 계정 — 첨부는 통신의 부속물이라 역할이 정합. DWD 사칭 경로(`getDriveClient("hmnotice@…")`) 기존재 |

- 보호 계정 3종에 이미 포함 — 삭제 자동화에 휩쓸리지 않는다.
- 용량 감시: 운영 액션 `attachment_quota`(§7)가 사용량을 보고. 15GB 접근 시 파기 주기 단축이 1차 대응.

## §2 폴더 체계 (로드맵 「첨부 Drive 폴더 체계화」 확정판)

```
내 드라이브(hmnotice@)/
└─ 플랫폼 첨부/                ← 앱이 생성·관리, 사람 손대지 않음
   └─ 쪽지/{YYYY}/{MM}/        ← 월별 폴더 = 파기 크론의 삭제 단위(§6)
      └─ {memoId}_{n}_{원본파일명}
```

- 폴더는 최초 업로드 시 lazy 생성, id는 `platform_config/attachment_folders` 문서에 캐시(월당 Drive 조회 1회).
- 파일명에 `memoId`를 접두해 역추적 가능(감사·파기 검증용).
- 다른 기능이 첨부를 갖게 되면 `플랫폼 첨부/` 아래 형제 폴더(`업무/`·`생활지도/` 등)로 확장 — 루트 규약만 이 스펙이 정한다.

## §3 데이터 모델·권한

### 3-1. `memos` 문서 확장

```
attachments?: Array<{
  driveFileId: string;
  name: string;          // 원본 파일명 (표시용, ≤100자)
  mimeType: string;      // 화이트리스트 검증 후 저장
  size: number;          // bytes (표시용)
  webViewLink: string;   // Drive 열람 URL (클라이언트는 이 링크만 연다)
  thumbnailLink?: string; // Drive 제공 썸네일 — 만료될 수 있으므로 실패 시 아이콘 폴백
}>   // ≤5개
```

- 기존 `links`(≤5)와 별개 한도. firestore.rules 무변경(첨부 참조는 쪽지 본문과 같은 읽기 규칙 아래 있다).

### 3-2. 업로드 경로 — 서버 경유 단일 경로

```
클라이언트: 이미지 선택 → 캔버스 리사이즈(최대 변 2000px·JPEG 품질 0.85, PNG는 원본 유지) → ≤3.5MB 검증
  → POST /api/memo action:"attach_upload" (multipart, 장당 1요청)
서버: MIME·크기 재검증 → hmnotice@ DWD로 Drive 업로드(§2 폴더) → {driveFileId, webViewLink, …} 반환
발송: memo_send payload의 attachments에 참조 배열 — 서버는 driveFileId가 방금 그 세션 업로드분인지 검증
  (업로드 시 `attachment_staging/{fileId}` 문서: uploaderEmail·시각. 발송 시 대조 후 삭제 — 남의 파일 id 끼워넣기 차단)
```

- 클라이언트 직접 Drive 업로드는 불가(DWD 키는 서버 전용) — 4.5MB 제한 안에서 서버 경유가 유일 경로이고, 리사이즈로 이미지에는 충분하다.
- **고아 파일 정리**: 업로드 후 발송하지 않은 파일은 staging 문서 기준 24h 후 파기 크론(§6)이 함께 삭제.

### 3-3. 열람 권한 부여

- **원칙: 수신자 개별 `reader` 권한** (`permissions.create`, `sendNotificationEmail:false` — Drive 메일 발송 금지, 알림은 쪽지가 한다).
- 발송 API가 문서 커밋 후 **비동기(after)로 부여**, 실패분은 문서에 `permissionPending: true` 표시 후 다음 발송·크론에서 재시도. 수신자가 권한 전에 클릭하면 Drive의 "권한 요청" 화면이 뜨는 것이 최악 — 수용(재시도로 수렴).
- **예외**: 수신 집합이 전 교직원(300명 상한 근접)인 공지는 개별 300콜 대신 **도메인 내부 링크 공유** 허용 — 의미론이 정확히 일치하는 경우에만. 판단 기준은 서버가 수신자 수 ≥ 전 교직원 수 × 0.9일 때 자동 전환 + 발신 화면에 "학교 전체가 열 수 있는 링크로 공유됩니다" 고지.

## §4 화면 (Antigravity 인계)

- 쪽지 쓰기: 📎 이미지 첨부 버튼 → 선택·미리보기·삭제, 진행률 표시. 실패 시 항목별 사유.
- 읽기: 첨부 썸네일 그리드 → 클릭 시 `webViewLink` 새 탭. 개발 용어 금지(Drive·DWD 노출 금지 — "첨부 이미지"로만).
- v1.1 개편(§11)의 레이아웃 규약 준수. 상세 배치는 구현 시 IA 협의.

## §5 양해 쪽지 전송 버튼 (로드맵 연계 ①, §5c-9-3 위에 얹힘)

- 교사 포털 양해 카드(§5c-9-3 받는 사람별 개별 카드)에 **[📨 양해 쪽지 보내기]** 추가: 클립보드 복사 대신 카드 이미지를 생성 → `attach_upload` → 해당 당사자 1인에게 쪽지 발송(제목·본문 자동 완성, 발신은 **클릭한 교사 본인**).
- 「시스템은 정보 전달까지만」 정합: 시스템이 조율을 대행하는 것이 아니라 본인 발신 경로를 한 클릭으로 묶는 것 (로드맵 기존 판정 승계).
- 묶음 이동은 당사자 수만큼 카드 — 버튼도 카드별. 일괄 발송 버튼은 만들지 않는다(양해는 개인에게 구하는 행위 — §5c-9-1).
- 알림 센터 [수락] 버튼(§13-3 `consentStatus` 전이)은 **이 스펙 범위 밖** — 별도 스펙.

## §6 보존·파기

- 첨부 수명 = 쪽지 수명. 쪽지 파기 크론(1단계 §6의 후행 크론)이 확장을 갖는다: `expireAt` 지난 쪽지 삭제 시 `attachments[].driveFileId`를 `files.delete` — **월 폴더가 비면 폴더도 삭제.**
- 크론 전이라도(1단계 크론 미구현 상태) 첨부만 먼저 쌓이는 문제는 없다 — 쪽지가 살아 있는 동안 첨부도 살아 있는 것이 맞다.
- 개인정보: 첨부 이미지에 시간표·명단이 실릴 수 있음 → `personal_data_inventory.md`에 「쪽지 첨부(Drive, hmnotice@)」 항목 등재 + 파기 주체는 위 크론임을 명기 (phase11 규약).

## §7 검증·운영

- 검증 스크립트(`memo_attachment_selftest.ts`): 업로드→발송→수신자 권한 확인→파기 사이클, 실계정 대상·알림 억제·흔적 삭제 (기존 selftest 규약).
- 운영 액션 `attachment_quota`: hmnotice@ Drive `about.get(storageQuota)` 보고.
- DWD 스코프: `https://www.googleapis.com/auth/drive`는 기존 등록분으로 동작해야 정상(getDriveClient 기사용). 미등록으로 실패 시 스코프 등록 URL만 안내.

## §9 명시적 범위 제외

- 일반 파일 첨부(문서·한글 등) — MIME 확장만으로 열리는 구조를 준비하되 v1 미포함.
- 알림 센터 [수락] 버튼·`consentStatus` 전이 — 별도 스펙.
- 첨부 검색·용량 통계 화면 — 실수요 후.
