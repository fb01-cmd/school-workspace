# 글씨 크기 판정 기준 스펙 (font_size_spec)

- 작성: Claude, 2026-08-20 (STATUS.md 「결정 끝 — 작업 대기」 항목의 「기준」 몫)
- 발단·실측 규모: `development_roadmap.md` §2 「글씨 크기 — 중요한 정보가 너무 작다」 (12px 이하 2976곳 vs 14px 이상 799곳 — 플랫폼 전체가 작은 쪽으로 설계돼 있다)
- 사용자 요구의 핵심: *"중요하지 않은 참고사항 같은 게 작은 건 괜찮은데, 중요하게 알아야 할 정보들이 작은 건 문제"* + *"글씨를 키울 땐 모바일 반응성도 꼭 고려"*

## §0 결정 요약

- **[판단] 접근은 ⓒ(역할별 기준)를 채택한다.** ⓑ(9·10px 기계 상향)는 ⓒ의 1단계로 흡수한다(로드맵 권고 그대로).
- **[판단] ⓐ(전역 확대 스위치)는 채택하지 않는다.** 근거 셋:
  1. 중요/비중요 구분 없이 전부 커진다 — 사용자 요구("중요한 것이 작다")와 어긋난다.
  2. **모바일 최소 폭에서 가장 먼저 깨진다** — rem 전역 확대는 글자만이 아니라 rem 기반 여백까지 키워, 좁은 폭에서 가로 스크롤·겹침이 데스크톱보다 먼저 터진다. 검증 범위가 「전 화면 × 실기기」로 최대가 된다.
  3. 근본 원인(작게 잡힌 기준)을 안 고친다 — 스위치를 끄면 되돌아간다.
  - 재검토 지점: 2단계(§4)까지 적용한 뒤에도 사용자가 여전히 작다고 하면, 그 검수 보고에서 Claude가 「사용자별 접근성 옵션」으로 재판정을 묻는다.

## §1 용어 — 이 저장소의 크기 클래스

Tailwind 표준 클래스는 rem 기반이라 브라우저 확대 설정과 호환된다. **상향할 때는 임의값(`text-[13px]` 류)이 아니라 표준 클래스를 쓴다.** 11px만 표준 클래스가 없어 임의값 `text-[11px]`을 허용한다.

| 클래스 | 실크기 | 이 스펙의 지위 |
|---|---|---|
| `text-sm` | 14px | 1급 최소 |
| `text-xs` | 12px | 2급 최소 |
| `text-[11px]` | 11px | 3급 최소 (화면 전체의 절대 하한) |
| `text-[10px]` | 10px | **격자 셀 예외(§3)에서만** |
| `text-[9px]` | 9px | **전면 금지** (격자 셀에서도) |

## §2 판정 기준 — 정보 3등급

판정 물음은 하나다: **"이 글자를 못 읽으면(또는 잘못 읽으면) 사용자가 잘못된 행동을 하는가?"**

| 등급 | 정의 | 예 (이 플랫폼 기준) | 최소 크기 |
|---|---|---|---|
| **1급 — 행동 결정 정보** | 읽고 나서 사용자의 행동이 갈리는 값 | 사람 이름(수신자·보강 교사·결재자), 날짜·시각·교시·마감, 장소(교실·특별실), 상태(승인/반려/대기/실패), 결정에 쓰는 인원·건수, 버튼·링크 라벨, 에러·경고 문장, 입력 필드의 값과 라벨 | **14px** (`text-sm`) |
| **2급 — 식별 보조 정보** | 1급을 구별·보조하지만 그것만으로 행동이 갈리지 않는 것 | 이메일 주소, 소속·직책, 보조 카운트 뱃지, 목록의 부가 열, 툴팁, placeholder, 도움말 문장 | **12px** (`text-xs`) |
| **3급 — 메타·장식** | 없어도 기능을 쓰는 데 지장 없는 것 | 단위 표기, 축약 뱃지 글자, 캡션·꼬리표, 버전 표기 | **11px** (권장 12px) |

- **애매하면 한 급 위로 둔다.** 판정 비용을 줄이는 쪽이 아니라 읽히는 쪽이 기본값이다.
- 같은 값이라도 화면에 따라 등급이 다를 수 있다 — 예: 시각이 목록의 보조 열이면 2급, "마감"으로 읽히는 자리면 1급.

## §3 예외 2종 (이 목록이 예외의 전부다)

1. **고밀도 격자 셀** — 주간 시간표 격자·미니 프리뷰처럼 한 화면에 수십 셀이 놓여 물리적으로 14px이 불가능한 곳. 조건 셋을 **모두** 충족할 때만:
   - 하한 **10px** (9px은 격자에서도 금지).
   - 같은 정보를 셀 탭/클릭 상세 또는 다른 화면에서 1·2급 크기로 다시 볼 수 있어야 한다.
   - 예외를 적용한 파일을 §7 허용 목록에 등재한다 (기계 검사의 대조군).
2. **이미지·인쇄 생성 전용 렌더** — 화면에 보이지 않는 것: `OffscreenShareCard`(html-to-image 캡처 전용, `left:-9999px`), `@media print` 블록. 화면 규정 밖이며 이 스펙의 대상이 아니다.

## §4 모바일 합격 조건 — 크기 기준과 한 몸이다

**"최소 크기 충족"만으로는 합격이 아니다. 그 크기에서 가장 좁은 폭이 깨지지 않아야 합격이다.**

- **검증 폭 = 360px** (국내 보급 안드로이드의 CSS 폭. 기존 `mobile_m_spec.md`의 375px 확인을 포괄하는 더 좁은 기준이다.)
- 360px에서 다음 넷을 모두 충족해야 그 화면의 크기 적용이 「완료」다:
  1. **페이지 몸통의 가로 스크롤 0.** 넓은 표·격자는 자체 `overflow-x-auto` 컨테이너 안에서만 스크롤한다.
  2. **컨트롤 겹침·가림 0** (버튼·뱃지·입력 필드).
  3. **1급 정보의 값 잘림 금지** — 말줄임(truncate)으로 마감·이름·상태가 안 보이면 실패다. 말줄임은 2·3급에만 허용.
  4. **깨지면 글자를 되돌리지 않고 배치를 바꾼다** — 가로 나열을 세로 스택으로 푸는 것이 정답이고, 크기 하한을 낮추는 것은 오답이다. 크기 기준이 레이아웃보다 우선한다.
- **검증 주체**: Antigravity는 화면 확인이 불가하다(`AGENTS.md` §1) — 구현자의 몫은 tsc·build·grep까지. 360px 브라우저 확인은 Claude, **실기기는 사용자**. 실기기 미통과 상태의 적용은 완료로 치지 않는다(로드맵 §2의 사용자 제약 그대로).

## §5 적용 단계 (적용은 Antigravity, 과제는 `docs/handoff/NEXT.md`)

- **1단계 — 기계적 상향**: §3 예외 2종 밖의 `text-[9px]`·`text-[10px]` 전량을 §2 등급에 맞춰 상향 (기본 `text-xs`, 명백한 3급만 `text-[11px]`, 1급이었으면 `text-sm`). 격자 셀의 9px은 10px로. 크기만 바꾸고 레이아웃은 손대지 않는다 — 상향으로 배치가 흐트러지는 곳은 보고만 하고 다음 단계로 넘긴다.
- **2단계 — 1급 정보 14px 승격**: 화면 단위로 순회하며 1급 정보가 12px 이하인 곳을 `text-sm` 이상으로. 우선순위는 교사가 매일 보는 화면부터(허브의 쪽지·업무·조직도, 주간 시간표·보강, 모바일 `/m`). 화면 묶음마다 과제를 따로 끊고, 각 묶음은 §4 모바일 합격 조건을 통과해야 닫힌다. 과제 등재는 1단계 검증 통과 직후 Claude가 한다.
- 12px 이하 2976곳 전체를 순회하는 것이 목표가 아니다 — **1급인데 작은 것**을 없애는 것이 목표다. 2·3급은 1단계 하한만 지키면 그대로 둬도 된다.

## §6 기계 검사 (완료 확인 방법)

```bash
# 1단계 후 0건이어야 한다
grep -rn "text-\[9px\]" src/
# 남는 것 전부가 §7 허용 목록 파일이어야 한다
grep -rln "text-\[10px\]" src/
```

- `npx tsc --noEmit` · `npm run build` 통과, `scripts/check_ui_removals.sh` 결과 보고 — 크기 상향 작업에서 핸들러·라벨이 사라지면 그 자체가 반려 사유다.
- 화면 검증(360px + 실기기)은 §4의 주체 분담을 따른다.

## §7 10px 허용 목록 (격자 셀·§3-1 예외 적용 파일)

**1단계 완료 시점에 구현자가 채우고 Claude가 검수한다.** 이 목록에 없는 파일에서 `text-[10px]`이 grep에 잡히면 실패다.

- (아직 비어 있음 — 1단계에서 채운다. `OffscreenShareCard.tsx`는 §3-2 대상이라 이 목록이 아니라 스펙 범위 밖이다.)

## §8 범위 밖 (이 스펙이 다루지 않는 것)

- 터치 타깃 크기(버튼 히트영역) — 별건 (허브 소품 ⓑ 계열).
- 이메일·챗 발송 본문의 글자 크기 — 수신 클라이언트가 렌더링을 지배하므로 별도 판단.
- 색 대비(저대비) — 별건. 단 크기를 키우며 색을 함께 바꾸지 않는다(크기 과제에 색 변경을 끼워 넣지 않는다).
