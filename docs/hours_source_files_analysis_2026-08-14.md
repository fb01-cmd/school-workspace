## 1. 파일 3종의 실물 구조

### ① 과목별 배정표 (HWP → PDF, 8쪽) — **주 원천**

부서(교과)별 1쪽: 국어 · 외국어 · 수학 · 과학 · 사회 · 생활교양 · 예술 · 체육.
각 쪽에 표 2개:

| 표 | 축 | 내용 |
|---|---|---|
| 과목별 배정표 | 과목 × 학급(1~3학년 각 10반) | 과목이 어느 반에 주 몇 시간 들어가나 + 비고(과목 총시간) |
| 과목별 **개인** 배정표 | 교사 × 과목 × 학급 | **교사별 시수표의 원자료 그 자체** + 비고(교사 총시간) |

- 학급 축에 **계열 밴드가 명시된다**: 2·3학년은 인문(1~5반)·자연(6~10반). 1학년은 통합과정.
- 개인 배정표 비고는 `15` / `10+5` 형태 — **+N이 창체(진로) 시간**으로 분리 표기된다.
- 부서 제목에 부서 총시간이 적힌다: 국어 "113시간+창체5" · 수학 "127시간" · 과학 "140시간" 등.

### ② 창체 수업 담당교사 (HWP → PDF, 1쪽)

학년(3) × 반(10) → **진로 담당교사** 격자. 반당 1시간.

⚠️ **실측 함정: 문서 내부 제목이 "2025학년도 1학기"다** (파일명은 2026-2). 양식 재활용으로 제목이 안 갱신된 것 — 사람은 무시하고 넘어가지만, 자동화가 학기를 제목에서 읽으면 틀린다. **학기 식별은 사용자 입력으로 받고, 문서 제목과 다르면 경고**해야 한다.

### ③ 이동수업 현황 (엑셀, 2학년 2학기 1장)

반(10) × 열: 계열 소속(인문교육·사회과학·경제경영 / 기계항공·화학나노·보건생명) + **선택과목별 수강 인원수** + 총원 행.

- 수강 인원이 있는 반 집합 = **동시수업 밴드 구성의 원천** (예: 중국어회화 수강 반 {1,2,3,5,10} — 시수표·배정표의 중국어회화 배정 반과 일치).
- 하단에 **과목별 사용 교실**이 적혀 있다: 기하=온학습터 · 인공지능기초1=6반교실 · 인공지능기초2=8반교실 · 일본어회화=일본어실 · 중국어회화=중국어실 → **특별실 등록부(venueGroups)의 원천까지 이 파일이 준다.**
- ⚠️ 이번 수령분은 **2학년만**이다. 1학년은 통합과정이라 이동수업이 없지만, **3학년 것은 별도 존재할 것** — 추가 수령 필요.

## 2. 일과계 수작업의 정체 (자동화 대상)

```
① 배정표(부서별 8쪽, 교사×과목×반 시수)  ─┐
② 창체 담당교사(학년×반)                  ─┼→ 일과계가 손으로 병합 → 교사별 시수표(.xls) → 컴시간
③ 이동수업 현황(반×선택과목 인원)          ─┘        ↑ 지금 수동인 구간 = 자동화 대상
```

수작업 내용 = ①의 개인 배정표 8쪽을 한 표로 합치고, ②를 "진로" 행으로 바꿔 넣고, ③으로 이동수업 구성을 확인하는 것. **전부 기계적 병합·대조다.**

## 3. 명칭 이원화 — 매핑 규칙 2건

| 배정표 | 창체 파일 | 시수표 | 규칙 |
|---|---|---|---|
| "창체" 행 (개인표 +N) | "진로" 열 | **"진로" 행** | 배정표의 창체 = 시수표의 진로. 병합 시 과목명을 "진로"로 통일 |
| (없음) | (없음) | 창체·SLAT **고정 슬롯** | 시수표에 행이 없다 — 코호트 등록부(9c-H ②) 소관, 이 파이프라인과 무관 |

## 4. 교차 검증 실측 — 데이터가 서로를 증명한다

2026-08-14 실측 (스크립트 대조, 전건 일치):

| 대조 | 결과 |
|---|---|
| ② 창체 담당 반 수 ↔ 시수표 "진로" 행 계 | ✅ 6명 전원 일치 (10·5·5·2·3·5) |
| ① 수학 개인표 8명 비고 합 ↔ 부서 제목 "127시간" ↔ 시수표 수학 8명 계 합 | ✅ 셋 다 127 |
| ③ 중국어회화 수강 반 집합 ↔ 시수표·배정표 배정 반 | ✅ 일치 |
| ① 개인표 계열 밴드(인문 1~5·자연 6~10) ↔ ③ 반 계열 소속 | ✅ 일치 |

→ **자동 오류 검출의 재료가 이미 파일 안에 있다.** 배정표 오류(일과계 증언 "있는 경우가 있다")는 이 대조들이 어긋나는 지점으로 드러난다.

### 자동 검출 가능한 오류 목록 (스펙 초안)

1. 부서 쪽 내부: 과목별 배정표 격자 ≠ 개인 배정표 합 (같은 쪽의 두 표가 서로 어긋남)
2. 교사 비고 총계 ≠ 셀 합 / 부서 제목 총시간 ≠ 표 합
3. 배정표 창체(+N) ↔ 창체 파일 담당 반 불일치
4. 이동수업 현황에 없는 반에 선택과목 배정 (또는 그 반대)
5. 같은 반·같은 과목에 두 교사 (복수교사 지정 없이)
6. 문서 제목 학기 ≠ 대상 학기 (②에서 실측된 함정)
7. 최종 시수표 무결성 3종 (기존 `excelHoursParser` 검사 재사용)
8. 1학기 담임 교체 → 담당반 변경 (일과계 증언 함정 2): 창체 파일 재수령 시 직전판과의 차분 표시

## 5. 병목 — 입력 형식 (착수 시 결정 사항)

배정표 원본이 **HWP 표**다. 경로 3안:

| 안 | 방식 | 판정 |
|---|---|---|
| ⓐ PDF 표 추출 | HWP→PDF→표 파싱 | ❌ 셀 병합·좌표 추출이 불안정, 쪽마다 깨질 수 있음 |
| ⓑ **한글에서 표 복사 → 붙여넣기(TSV)** | 부서 쪽마다 개인 배정표를 복사해 화면에 붙여넣기 | ✅ **권장.** 한글 표 복사는 TSV로 나온다 — 기존 컴시간 가져오기 1단계의 붙여넣기 파서 패턴 재사용 (숨겨둔 코드가 자산이 된다) |
| ⓒ 부장님께 엑셀 양식 제공 | 원천을 엑셀로 전환 | 장기적 최선이지만 타인 업무 방식 변경 요구 — 시스템은 정보 전달까지만 원칙과 충돌 소지, 사용자 판단 사안 |

②창체(격자 1장)·③이동수업(엑셀)은 형식 문제 없음 — 각각 붙여넣기·업로드로 충분.

> **[2026-08-16 사용자 확정 — 경로 ⓓ 신설·채택]** ⓑ(표 복사→붙여넣기)는 일과계 업무 방식 변화가 커
> 거부반응 우려(사용자 판단). 대신 **HWP→PDF 저장→업로드 + 플랫폼의 Gemini API로 구조화 추출**을
> 채택한다. 근거: ① 일과계 동선이 "PDF 저장→업로드"로 사실상 무변화 ② §4의 교차 대조가 그대로
> **AI 오인식의 결정론 검증 그물**이 된다(9c-D 철칙 "AI 출력은 검사기를 통과해야만 반영"과 정합)
> ③ 무료 한도(하루 20회 실측)에 학기 1~2회 작업은 충분. 유의: 무료 등급 입력은 구글 학습에 쓰일 수
> 있음. **[같은 날 정정]** "기존 AI 기능과 같은 경로"는 오판이었다 — 기존 기능은 전부
> `buildPseudonymizer`(ai.ts)로 실명·이메일을 T01식 가명으로 바꿔 보낸다. 따라서 이 경로도
> **로컬 텍스트 추출(실물 PDF 텍스트 층 깨끗함 실측) → 가명화 → AI에는 가명 텍스트만** 구조로
> 규율을 보존한다. 실명 PDF 원본을 AI에 직접 보내지 않는다.
> ⓐ(좌표 기반 PDF 파싱)의 ❌ 판정은 유지 — ⓓ는 좌표가 아니라 AI 추출이라 병합에 강하고, 틀리면 그물이 받는다.

## 6. 산출물 연결 (9c-H와의 접점)

이 파이프라인의 출력 = **9c-H `HoursPlan`** (신설된 저장 모델 그대로):

- 개인 배정표 병합 행 + 진로 행 → `rows` (교사 이메일 매칭은 9c-H 업로드의 성명→이메일 매칭 UI 재사용)
- 이동수업 현황 → `simulGroupId` 후보 + 특별실(venueGroups) 제안
- 즉 **별도 신기능이 아니라 9c-H 시수 조정 화면의 네 번째 진입 경로**("배정표에서 생성")로 얹는 것이 맞다.
