# 1부 — 운영자용: 세 일꾼과 나

## 등장인물

| 일꾼 | 성격 | 비용 |
|---|---|---|
| **Claude** | 설계자 겸 반장. 무엇을 만들지 정하고, 남이 만든 것을 검사하고, 위험한 일(보안·삭제·배포)을 직접 한다 | **비싸다** — 쓸수록 한도가 닳고 며칠 뒤에 회복된다 |
| **Antigravity** | 손 빠른 목수. 화면·버튼·대량 수정처럼 "만드는 일"을 한다 | 무료 |
| **Codex** | 깐깐한 검사관. 만들어진 것을 읽고 "여기 이상하다"를 목록으로 보고한다. **절대 결정하지 않는다** | 유료(별도 결제) |

핵심 원칙 하나: **비싼 일꾼(Claude)은 그가 아니면 안 되는 일에만 쓴다.** 그래서 만드는 일은 목수에게, 검사는 검사관에게 나눠 주고, Claude는 방향을 정하고 최종 판정만 한다.

## 내가 하는 일은 딱 세 가지다

1. **방향 정하기** — Claude에게 말로 시킨다. ("루미큐브처럼 굴려보는 화면 만들자", "이 옵션 필요 없는 것 같은데?")
2. **한 줄 배달** — Claude가 "Antigravity에 넘길 준비 됐다"고 하면, Antigravity 창에 늘 똑같은 한 줄을 붙여넣는다:
   ```
   docs/handoff/NEXT.md 읽고 수행해
   ```
   긴 지시문을 복사할 필요가 없다 — 지시 내용은 Claude가 파일에 미리 써 둔다.
3. **실기기 확인** — 다 만들어지고 검사까지 끝나면, Claude가 "화면에서 이것만 눌러봐 주세요"라는 짧은 시나리오를 준다. 눌러보고 "된다/안 된다" 한마디면 된다.

그 외 전부 — 지시서 작성, 완료 감시, 검사관 파견, 불합격 판정, 재작업 지시, 기록 — 는 Claude가 알아서 한다.

## 한 사이클이 도는 모습 (실화: "직접 조정" 기능이 만들어진 과정)

1. 내가 Claude에게: "시간표를 루미큐브처럼 사람이 굴려볼 수 있어야 해."
2. Claude가 **설계도(스펙)** 를 쓰고 → **Codex에게 먼저 검토**시킨다 → Codex가 "설계에 구멍 5개"를 찾아온다 → Claude가 설계도를 고친다. (만들기 전에 결함을 잡아서 왕복을 아낀다)
3. Claude가 자기 몫(엔진 부품)을 직접 만들고, 화면 만드는 일을 **NEXT.md 파일에 지시서로** 써 둔다.
4. 나는 Antigravity에 그 한 줄을 붙여넣는다. Antigravity가 화면을 만들고 저장(커밋)한다.
5. Claude는 저장을 **자동으로 감지**하고(감시를 걸어 둔다), 묻지 않고 검사에 들어간다: ① 기계 검사(컴파일·빌드·규칙 검사) ② Codex 파견(항목별 통과/실패 보고) ③ Codex가 "실패"라고 한 것은 **Claude가 전부 직접 다시 확인**한다 — 검사관도 틀릴 수 있어서다(실제로 오판을 기각한 사례가 있다).
6. 합격이면 배포하고 나에게 실기기 시나리오를 준다. 불합격이면 Claude가 원인을 갈라("이건 목수 실수 / 이건 내 부품이 부족했던 것") 재작업 지시서를 다시 써 둔다 → 나는 또 그 한 줄만 붙여넣는다.
7. 모든 결과는 파일(일지·현황판)에 남는다 — 그래서 대화창이 닫혀도, 다음 날 다른 세션이 열려도 이어진다.

## 왜 이렇게 하나

- **셋이 서로를 잡는다.** 목수가 만든 걸 검사관이 보고, 검사관의 보고를 반장이 재확인하고, 반장의 설계를 검사관이 미리 본다. 오늘 하루에만: 설계 구멍 5개(만들기 전), 기능 결함 3건(만든 후), 검사관 오판 2건(재확인)이 각각 다른 눈에 잡혔다.
- **내 말은 파일이 돼야 실행된다.** 말은 휘발되고 세션은 닫히지만, 파일(STATUS·NEXT·일지)은 남는다. "지금 뭐가 남았지?"의 답은 사람 기억이 아니라 STATUS.md 파일 하나에서 나온다.
- **나는 배달부가 아니다.** 내가 하는 유일한 전달은 그 한 줄뿐이고, 그마저도 매번 같은 문장이다.

# 2부 — 개발자용: 구조·세팅·프로토콜

## 2-0. 개요

역할 분리는 **출력물의 성격**으로 정한다 (AGENTS §1·§1-1):

| 출력물 | 담당 | 근거 |
|---|---|---|
| 판단·스펙·보안·비가역 작업·아키텍처 | Claude | 틀리면 대가가 큼. 결정하는 입은 하나여야 함 |
| 코드·화면·대량 편집 (생산) | Antigravity | 틀려도 다시 만들면 됨. 무료 |
| 검증·전수 대조·사실 수집 (**주장**이 산출물인 일) | Codex | 코드에는 관문(컴파일러·빌드)이 있지만 주장에는 없다 — 그래서 전담 검증자를 둔다 |
| 안전 규칙이 코드 구조 자체인 좁은 구현 (순서 의존·가드·원복 로직) | Claude 직접 | 스펙 문장으로는 전달이 안 되는 종류 (AGENTS §1-2) |

## 2-1. 초기 세팅 (파일이 전부다)

저장소 루트에 다음을 둔다. **모든 조율 상태는 git 추적 파일** — 채팅·에이전트 전용 폴더에 두지 않는다(세션 휘발 대비).

```
AGENTS.md                 # 규칙의 단일 원본 (모든 에이전트가 따름)
CLAUDE.md                 # Claude 자동 주입용 — 규칙 본문 없이 AGENTS.md를 가리키기만 한다
                          #   (자동 주입 파일에 본문을 복사하면 낡은 사본이 이긴다 — 실사고로 확립)
STATUS.md                 # 지금 열린 항목 대장. 덮어쓰기 전용, 행마다 「확인 방법」 필수
project_notes.md          # append-only 일지 (핸드오버·실측·부정 결과까지 전부)
docs/handoff/NEXT.md      # Antigravity 오더 파일. 덮어쓰기 전용 — 끝난 과제는 지운다
.githooks/pre-commit      # 커밋 스코프 가드 (남의 작업 중 파일 오염 차단, core.hooksPath로 연결)
scripts/check_*.{sh,ts}   # 기계 관문들 (문서 정합·UI 규칙·삭제 검사 등)
```

에이전트별 세팅:
- **Claude**: CLI(터미널). 세션 시작 시 STATUS.md + AGENTS.md만 전체 읽기(나머지는 검색). 커밋·푸시 권한 보유.
- **Antigravity**: GUI 대화형 창 (헤드리스 CLI는 작업 폴더 버그로 봉인 — AGENTS §1-3). 오더는 NEXT.md 경유. `git push`·`gh`·`.env.local` 금지.
- **Codex**: `codex exec -s read-only` 로 Claude가 직접 호출. 비밀키 접근 금지 — 실행이 필요한 검증은 캐시 파일을 만들어 넘긴다.

## 2-2. 오더 프로토콜

**사용자 → Claude**: 자연어. Claude가 스펙/과제로 구체화한다.

**Claude → Antigravity** (NEXT.md 과제 양식):
- 기준 커밋 명시 · 범위 · **완료 확인 방법(필수)** · 핸드오버 기재 의무
- 머리에 상설 규약: 재작성 금지(부분 수정만), 삭제>추가면 정지 보고, 과제별 커밋, add -A 금지, push 금지, "지시와 코드가 다르면 맞추지 말고 보고", 판정불가 허용, 근거는 file:line
- 사용자는 `NEXT.md 읽고 수행해` 한 줄만 릴레이

**Claude → Codex** (검증 과제 5줄 규약, AGENTS §1-3):
1. 판정 불가 허용 ("실행해야 아는 건 몰지 말고 무엇을 실행해야 아는지 적어라")
2. 스펙을 정답으로 전제 금지 ("다르면 다르다고 보고")
3. 근거는 file:line — 근거 없는 단정은 그 자체가 실패
4. 보고 형식 고정: `[통과/실패/판정불가] file:line — 한 줄` (장문 금지 — 읽는 비용이 이득을 상쇄)
5. 대상을 커밋 해시로 고정 (더러운 트리를 읽히면 오탐)

호출 패턴 (실측으로 확립 — stdin 함정 회피):
```bash
# codex exec는 출력 리다이렉트 시 stdin EOF를 기다리며 무한 정지한다 (17분 실측)
nohup bash -c "codex exec -s read-only \"\$(cat task.md)\" > report.txt 2>&1 < /dev/null" &
# 멍때림 감시: 파일 크기 3분+ 정지 && 프로세스 생존 → 경보
# 프로세스 감시는 pgrep -x codex (패턴 -f는 감시 루프 자신에 걸린다 — 실측)
```

## 2-3. 완주 사이클 (상태 기계)

```
사용자 방향 제시
  → Claude 스펙 작성 ──→ Codex 스펙 사전 검토 ──→ Claude 반영     [만들기 전 결함 제거]
  → Claude 선행 구현(§1-2 영역: 채점기·op·가드) + selftest
  → NEXT.md 과제 등록 → 사용자 한 줄 릴레이 → Antigravity 구현+커밋+핸드오버(④)
  → Claude 완료 감시 (git 폴링: 신규 커밋 ∧ 깨끗한 트리, 20s 간격)
     ※ 핸드오버 누락 대비: 일지 커밋이 아니라 **코드 커밋**을 감시 조건으로
  → 감지 시 무질문 진행:
     ① 기계 관문 (tsc·build·check:ui·check_ui_removals + 관련 selftest)
        - 삭제 검사: 사라진 항목마다 "지시서에 있었나?" 대조
     ② Codex 커밋 검증 (위 5줄 규약 + 과제별 체크리스트)
     ③ 「실패」는 Claude가 전건 재확인 — 「통과」는 표본만 (AGENTS §1-1 3단계)
        - 오판이면 근거와 함께 기각 (실사례: 기존 관행을 신규 결함으로 오판 2건 기각)
        - 사실이면 원인 귀속: 작성자 실수 → 재작업 과제 / 선행 부품 부족 → Claude가 부품 보강 후 재배선 과제
  → 합격 → 배포(push는 Claude/사용자만) → STATUS에 실기기 확인 행 → 사용자 실기기 → 종결
  → 모든 단계를 일지(append-only)에 기록, STATUS 갱신은 같은 커밋에서
```

세션을 닫을 때: **켜 둔 감시를 명시적으로 끄고**, STATUS에 재개 지침(감시 조건 포함)을 남긴다 — 다음 세션이 그 행만 보고 이어받는다.

## 2-4. 안전장치 (전부 실사고 후 도입)

| 장치 | 막는 사고 |
|---|---|
| pre-commit 스코프 가드 | 남의 작업 중 파일이 커밋에 쓸려 들어가 미검수 배포 (3회 실사고) |
| 삭제 검사 스크립트 | "재작성"이 기능을 조용히 지우는 것 (컴파일은 버튼 소실을 못 잡는다) |
| append-only 일지 + numstat 확인 | "요약 정리"로 위장한 기록 유실 (4회 실사고) |
| STATUS 행별 확인 방법 필수 | 확인 불가능한 항목 = 소망. 유령 항목 방지 |
| 검증자 ≠ 작성자 | 자기 작업 자기 승인 (교차 검증 ③) |
| 「실패」 전건 재확인 | 검증자의 오판이 멀쩡한 코드를 뜯게 하는 것 |
| 출처 꼬리표 `[사용자 결정/판단/사실]` + 원문 인용 | 제안이 결정으로 굳는 것, 요약 왜곡 전달 (세션 간 규약) |

## 2-5. 이 구조의 요지 한 줄

**대화는 휘발되고 파일은 남는다** — 오더·상태·규칙·기록을 전부 git 파일로 만들고, 사람은 방향과 최종 확인만, 비싼 에이전트는 판단과 검증만, 나머지는 값싼 에이전트에게. 서로의 출력을 서로 다른 눈이 검사하게 배선하면, 단일 에이전트로는 못 잡는 결함이 단계마다 걸러진다.
