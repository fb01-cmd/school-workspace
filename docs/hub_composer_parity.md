# 허브 작성 폼 전수 대조 — 되살아난 것 3건 + 빠진 것 9건

> **대조**: 2026-08-19 Claude (Opus 5) · **계기**: 사용자 실기기 — *"웹 링크 추가 없앤다고 했던것 같은데 살아있네?"*
> **대상**: `MemoSection`(쪽지 작성부) ↔ `HubMemoComposer` · `TaskComposerModal` ↔ `HubTaskComposer`
> **왜 지금까지 안 걸렸나**: 앞선 전수 대조는 **수신자 선택(조직도) 쪽만** 봤다. 작성 폼 자체는 한 번도 대조한 적이 없다. 그리고 찾은 것이 **"빠진 것"뿐**이라 **"없앴는데 되살아난 것"** 은 애초에 찾지 않았다.

## ⚠️ 뿌리부터: 되살아난 2건은 구현 잘못이 아니라 **스펙 잘못**이다

`messaging_hub_ia_spec` §2-4의 입력 표가 업무에 **「지시 내용」**, 쪽지에 **「링크」** 라고 적고 있었다. **둘 다 사용자가 이미 없애기로 하고 제거까지 끝낸 것**이다. Claude가 스펙을 쓰면서 로드맵의 제거 결정과 대조하지 않았고, 구현자는 스펙대로 충실히 만들었다.

**스펙 §2-4는 이미 정정했다**(정정 경위도 본문에 남겼다). 아래 화면 수정은 그 정정의 이행이다.

## (B) 되살아난 것 — 사용자가 없앤 것이 다시 생겼다

### B-1. 쪽지 「웹 링크 / + 링크 추가」 입력

- **결정**: 로드맵 28번 — 사용자 *"본문에 링크가 먹으니 없어도 될 것 같아"* · 커밋 `306e07a`
- **원본 상태**: `MemoSection.tsx:1183-1185`(state)·`:1400-1408`(handler)만 사장돼 있고 **화면 렌더는 0건**
- **허브**: `HubMemoComposer.tsx:60-63`·`:132-146`·`:357-441` — 입력 UI 전체가 부활
- **덤으로 더 나쁘다**: 원본은 `https://` 시작 강제 + 5개 상한이었는데, 허브는 **스킴을 자동으로 붙여주고 개수 제한이 없다**
- **지시**: 입력 UI를 제거한다. **읽는 쪽의 「첨부 링크」 표시는 건드리지 마라** — 과거 쪽지 하위호환으로 일부러 남긴 것이다(28번 처방). 서버 모델·검증도 그대로 둔다

### B-2. 업무 작성기에 「지시」 재등장

- **결정**: 로드맵 8번 — 사용자 *"어감이 매우 안 좋아"* → **「지시」 전면 금지**, 라벨은 **「내용」**. 커밋 `92fadca`
- **허브**: `HubTaskComposer.tsx:459` 라벨 `지시 내용 및 안내 사항` · `:471` placeholder `지시 내용이나 전달 사항을 입력해 주세요.`
- **원본**: `TaskComposerModal.tsx:433` 라벨 `내용` · `:451` placeholder `업무 내용, 유의사항, 제출 방법 등을 적어주세요.`
- **전수 확인**: 지금 코드베이스에서 사용자 화면에 「지시」가 남은 곳은 **이 두 줄뿐**이다(나머지 검색 결과는 전부 주석의 "지시서")
- **지시**: 원본과 같은 문구로 되돌린다

### B-3. 편집기 맞춤법 빨간 줄 부활 (쪽지·업무 양쪽)

- **결정**: 로드맵 34-ⓑ — 실기기에서 *"맞춤법 빨간 줄이 링크 여부 판독을 방해"* → `spellCheck` 해제. 커밋 `c58dd4a`

- **지시**: `HubMemoComposer.tsx:291-298`·`HubTaskComposer.tsx:466-473`의 편집기에 `spellCheck={false}` 추가

## (A) 빠진 것 — 있어야 하는데 허브에 없다

### ⭐ A-1 (최우선). 서식 버튼을 눌러도 화면에 아무 변화가 없다

`HubMemoComposer.tsx:297`·`HubTaskComposer.tsx:472`가 `prose prose-sm`만 걸었는데 **`@tailwindcss/typography`가 설치돼 있지 않다**(`package.json`에 없고 `globals.css`에 `@plugin`도 없다). 즉 **그 클래스는 아무 일도 하지 않는다.**

원본은 클래스를 직접 명시한다 — `MemoSection.tsx:1927`·`TaskComposerModal.tsx:452`:
```
[&_ul]:list-disc [&_ol]:list-decimal [&_blockquote]:… [&_a]:text-indigo-600 [&_a]:underline …
```

Tailwind가 기본적으로 `ul/ol` 마커와 `a` 밑줄을 지우므로, 허브 편집기에서는 **툴바의 글머리·번호·인용·링크 버튼을 눌러도 눈에 보이는 변화가 없다.** 글자는 들어가는데 표시가 안 되니 "버튼이 고장 났다"로 보인다.

**지시**: 원본의 서식 클래스 문자열을 그대로 가져다 쓴다. **`prose`를 살리려고 플러그인을 새로 설치하지 마라** — 다른 화면과 렌더가 갈라진다.

### A-2. 이미지 붙여넣기가 안 된다 (쪽지)

원본은 컨테이너·편집기 양쪽에 붙여넣기 처리가 있다(`MemoSection.tsx:1502-1530`·`:1554-1579`). 허브 작성기에는 **`onPaste`가 한 곳도 없다.** 캡처를 붙여넣는 동선이 통째로 사라졌다.

### A-3. 외부에서 붙여넣은 서식이 조용히 사라진다 (쪽지)

원본 `MemoSection.tsx:1581-1589`가 붙여넣기를 가로채 **평문으로만** 넣는다(`memo_richtext_spec` §79 *"붙여넣기 = 평문만 … 원천 차단"*). 허브는 그 처리가 없어 웹·워드에서 붙여넣으면 저장 형식 밖의 내용이 들어가고, 저장할 때 **직렬화기가 조용히 버린다** — 사용자는 쓴 대로 안 갔다는 걸 보낸 뒤에 안다.

### A-4. 첨부한 이미지를 본문에 넣을 수단이 없다 (쪽지)

원본의 「+ 본문에 넣기」·「본문에 들어감」 표시와 편집기에서 지웠을 때 참조를 정리하는 처리 일체(`MemoSection.tsx:1245-1310`·`:1532-1552`·`:2004-2059`)가 허브에 없다.

### A-5. 본문 글자 수 카운터·1만 자 사전 검증이 없다 (쪽지)

원본 `MemoSection.tsx:1884-1886`(카운터)·`:1612-1615`(검증). 허브는 없어서 **서버가 400으로 막을 때까지 모른다.** 긴 글을 쓴 사람이 보내기를 누른 뒤에야 실패를 본다.

### A-6. 첨부가 하나 실패하면 나머지가 조용히 사라진다 (쪽지)

`HubMemoComposer.tsx:113-126`이 `for…await` 루프 안에서 **첫 실패에 빠져나가 남은 파일을 버린다.** 원본은 파일별로 올리고 실패한 것만 사유가 붙은 카드로 남긴다(`MemoSection.tsx:1442-1489`·`:2062-2066`).

로드맵 29번이 *"조용한 실패 금지 원칙의 작성기 버전"* 이라고 못 박은 자리다.

### A-7. 보내기가 왜 안 눌리는지 안 알려준다 (쪽지)

로드맵 29번 — 사용자 *"왜 안 눌러지는지 알려줘야 오해를 안 하지"*. 원본은 버튼 옆 한 줄 + 툴팁(`MemoSection.tsx:2092-2112`). 허브(`HubMemoComposer.tsx:455-459`)는 비활성만 걸고 **사유가 한 곳도 없다.**

### A-8. 양식 파일 안내가 없다 (업무)

원본 `TaskComposerModal.tsx:468-472` — 「최대 5개」 + 「한글(HWP/HWPX), 오피스, PDF 등 (파일당 30MB 이하)」. 허브에는 종류·크기 안내가 전무하다(로드맵 36번이 지정한 문구다).

### A-9. 쪽지↔업무 전환에서 첨부가 경고 없이 사라진다

전환 시 제목·본문만 넘기고(`HubMemoComposer:199-202`·`HubTaskComposer:317-320`), `MessagingHub:170-177`이 기존 작성기를 언마운트한다 → **이미 Drive에 올라간 첨부와 고른 양식 파일이 말없이 증발한다.**

스펙 §2-4가 *"경고 없이 버리지 않는다"* 로 정한 자리이고, **이번 정정에서 첨부도 그 대상임을 명시했다.**
