# 9c 백지 편성 실험 — 통과 (2026-08-14)

> 미룬 목록 §0-1 **F1**의 실행 기록. *"컴시간 없이 짜는 능력은 아직 증명되지 않았다"* → **오늘 증명됐다.**
> 코드: `compileSectionsFromHours`(`src/lib/timetable/solver.ts`) 신설 + 실험 스크립트 `scripts/solve_blank.ts`.

## 0. 알아야 할 것 (3줄)

1. **컴시간 없이 시간표를 짜는 데 성공했다.** 시수표(누가 어느 반에서 몇 시간 가르치는지)와 등록부만 주면, 현행 시간표를 안 보고도 문제 없는 시간표가 나온다 — 품질도 컴시간 것보다 오히려 낫다(감점 38 vs 39).
2. 다만 시수표만으로는 **모자라는 정보가 5가지** 있고, 그 목록이 이번에 정확히 나왔다(§3). 이것이 앞으로 만들 "시수표 입력 화면"에 반드시 들어가야 할 칸들이다.
3. 그중 하나(창체·SLAT 자리)는 이번엔 현행 시간표에서 베껴 넣었다 — 다음 학기에 진짜로 쓰려면 그 등록 화면(교육과정 코호트 등록부)을 만들어야 한다.

## 1. 실험 설계

재현 실험(`solve_rehearsal.ts`)은 현행 그리드에서 섹션을 역산했다 — 답이 있는 문제를 다시 푼 것. 이번에는:

```
현행 그리드 → deriveHoursFromGrids → 시수표 (432행)
                                       ↓
                       compileSectionsFromHours   ← 그리드를 보지 않는다
                                       ↓
                                  솔버 → 검사기
```

그리드에서 **함께 뽑되 "장래 다른 출처가 주게 될" 입력** (실험용 대역 — 각각의 정식 출처는 §3):

| 대역 입력 | 규모 | 정식 출처 |
|---|---|---|
| 자리표시(창체·SLAT) 고정 슬롯 → `FixedBlock[]` 형태 | 4슬롯 120건 | 교육과정 코호트 등록부 (질의 결과 §2-2) |
| 학년별 요일별 교시수 | 3학년분 | 설정·입력 화면 |
| 교사 이름·과목 약칭 (표시용, 판정 무관) | — | 계정 원장 · term.subjects |

## 2. 결과 (2026-2 실데이터, 30학급)

```
섹션: 그리드 역산 총 416(고정 60·동시 12) 점유 968  vs  백지 총 416(고정 60·동시 12) 점유 968 — 완전 일치
시드 포트폴리오(8시드): 전 시드 미배정 0 → 선발 시드 1
검사기: 하드 0건 / 소프트 38점 (컴시간 현행 39점보다 낮음, 재현 실험 38점과 동급)
결정론: 같은 시드 재실행 동일 출력 ✅
```

**판정 기준 3종(하드 0 · 미배정 0 · 결정론) 전부 통과.** 재실행: `npx tsx --env-file=.env.local scripts/solve_blank.ts` (반복 실험 시 `--cache=` 권장 — Firestore 읽기 절약).

### 2-1. 가장 값진 부산물 — 동시수업 그룹 몫의 역산이 실데이터를 복원했다

시수표에는 "이 수업이 어느 동시수업 그룹 소속인지"가 없다. 실측 함정: 3-8반은 물Ⅱ 3h+화Ⅱ 3h를 갖는데 그룹(6·8·10반, 슬롯 월5·수4·목5) 몫은 **화Ⅱ 쪽**이고 물Ⅱ는 일반 수업이다 — 시수표만 보면 구분 불능.

그런데 그룹은 전 학급 동시 진행이라 **열(occurrence)마다 교사가 겹칠 수 없다.** 이 제약으로 소규모 백트래킹 역산을 돌렸더니: 3-6=물Ⅱ(송현우) → 3-8은 물Ⅱ(송현우) 불가 → 화Ⅱ(정성희) → 3-10은 화Ⅱ(정성희) 불가 → 생Ⅱ. **그리드 실데이터와 정확히 일치.** 11개 그룹 전부 역산 성공(수과탐 교대 구성 포함).

### 2-2. 실데이터에서 확인된 그룹 구조 (설계 지식)

2026-2의 동시수업 11그룹 전수: **학급마다 자기 과목 하나(또는 교대 두 개)를 갖고, 그룹 전 학급이 같은 슬롯 집합에 동기화**된다. "같은 셀에 분반 여러 개"인 구성은 한 건도 없다. 스펙이 걱정하던 셀 내 다중 분반은 이 학교 데이터에는 없다 — 다만 컴파일러는 시그니처 병합 문법(그리드 역산과 동일)이라 생겨도 수용한다.

## 3. 시수표가 모르는 것 — 시수표 입력 화면·등록부의 사양 (이번 실험의 본론)

그리드가 주던 정보 중 시수표+현행 등록부에 **없는** 것과 처리 방식:

| # | 부족한 정보 | 이번 처리 | 정식 요구사항 |
|---|---|---|---|
| 1 | **창체·SLAT 등 자리표시 수업의 고정 위치** | 그리드에서 추출한 `FixedBlock` 120건으로 대역 | **교육과정 코호트 등록부(C2) 신설 필수.** 등록 축은 교육과정(입학년도 역산), 컴파일러에는 학급 단위 entries로 전개 — `compileSectionsFromHours`는 학년 축을 모르므로 하드코딩 없음. 없으면 `fixed-missing` issue + 검사기 H1로 드러난다 |
| 2 | **동시수업 그룹 소속 표시** (한 학급이 그룹 과목을 2개 가질 때 어느 쪽이 그룹 몫인지) | 교사 겹침 회피 백트래킹 역산 — 전 그룹 성공, 가정은 `simul-assumed` issue로 전부 명시 | 입력 화면에서 그룹 소속을 명시하게 하면 역산 불요(안전). 역산 실패 시 `simul-unsolved`로 강등되어 H7로 드러난다. 등록부 **슬롯 미지정 + 그룹 밖 잔여** 조합은 H7 위험 — issue에 경고 포함 |
| 3 | **주당 그룹 교시수 h** | 등록부 slots 있으면 그 수, 없으면 학급별 합의 최소값 | 등록부에 slots 또는 주당 교시수 필드가 있으면 확정적 |
| 4 | **슬롯 제한형 특별실의 시수 배분** (과탐 실험 — 시수 중 몇 시간이 특별실인지) | 전 시수 실 점유 보수 처리(`venue-slot-limited` issue 10건) — H8은 확실히 방지, 과제약이지만 이번 데이터로는 전 시수 배치에 지장 없음 | 장래: 특별실 등록부에 "주당 실 사용 시수" 필드. 급하지 않다 — 보수 처리로 통과 |
| 5 | **학년별 요일별 운영 교시수** | 그리드 역산 대역 | 신학기 입력 화면 필요 (spec §2-2). 컴파일러가 컴시간 §5-사 정합성 검사(학급 슬롯 수요=운영 교시수)를 자체 수행 — `class-slot-mismatch` issue |

부수(판정 무관, 표시용): 교사 이름(이메일→성명)과 과목 약칭은 계정 원장·`term.subjects`에서 주입. 시수표 입력이 성명 기반이면 **성명→이메일 매칭 단계**가 입력 화면에 필요하다(질의 결과 §1의 동명이인 주의 동일).

## 4. 코드 반영

- `src/lib/timetable/solver.ts` — `compileSectionsFromHours` 신설 (`BlankCompileInput/Result/Issue`). 모든 가정·부족 정보는 `issues[]`로 반환 — 숨기지 않는다. C-2 예고 주석 갱신.
- `scripts/solve_blank.ts` — 실험 스크립트 (읽기 전용, `--cache=` 지원).
- 등록부 소비는 그리드 역산 컴파일러와 동일 규약(배정금지·연속·특별실·일괄 배정) — 이번 학기 데이터는 금지 0·연속 0·복수 0이라 **이 세 등록부의 백지 경로는 아직 실데이터 검증 전**이다(등록되면 재실험).
