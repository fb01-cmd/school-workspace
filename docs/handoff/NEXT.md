## 과제 B — 모바일에서 「다시 제출(교체)」이 아무 일도 하지 않는다 (실사용 기능 유실)

**기준 커밋**: `de79f69` · **대상**: `src/components/mobile/MobileTasksSection.tsx`

### 증상

휴대폰에서 **이미 제출한 업무**의 「다시 제출 (교체)」를 눌러 파일을 고르면 **화면에 아무 변화가 없고 제출도 되지 않는다.** 파일명도, 확인 버튼도, 오류도 나오지 않는다. 사용자는 제출된 줄 안다.

### 원인 (Claude가 코드로 확인 완료 — 조사하지 말고 이대로 고쳐라)

이 화면은 상태별로 분기가 갈린다.

| 분기 | 줄 | 무엇이 있나 |
|---|---|---|
| `myStatus.state === "ACCEPTED"` | `:681` | **담긴 파일 카드 전체** — 파일명·메모·「제출 확정하기」 버튼·안내 문구 (`:699`~`:760`) |
| `myStatus.state === "DONE"` | `:792` | 「다시 제출 (교체)」 **파일 선택만** (`:806`~`:826`) |

`stagedSubmitMap`을 **읽는 곳은 `:699` 하나뿐**이고 그건 `ACCEPTED` 분기 안이다. `handleMobileSubmit`을 부르는 곳도 `:750` 하나뿐이고 역시 그 안이다.

따라서 `DONE` 상태에서 파일을 고르면 **state에는 담기는데 그걸 그리는 코드가 없고, 올리는 버튼도 없다.**

**이건 2026-08-19 `306e07a`에서 들어온 회귀다.** 그 전에는 이렇게 동작했다:

```js
if (f && confirm("이전 제출본은 교체됩니다. 다시 제출하시겠습니까?")) {
  handleMobileSubmit(task.id, f);
}
```

담기 방식으로 바꾸면서 **카드를 `ACCEPTED` 분기에만 넣고 `DONE`을 빠뜨렸다.** `tsc`·`build`는 통과한다 — 타입 검사는 「버튼이 없어진 것」을 못 잡는다.

### 할 일

**`DONE` 분기에서도 담긴 파일 카드가 보이게 한다.**

1. `:698`~`:760`의 **담긴 파일 카드 렌더를 공용 함수로 뽑는다.** 컴포넌트 안의 지역 함수면 된다 (예: `renderStagedCard(task, mySubmission)`).
   - **`ACCEPTED` 쪽 동작·모양은 한 글자도 바뀌면 안 된다.** 뽑아낸 뒤 그 자리에서 그 함수를 부르기만 한다.
   - 안내 문구의 `mySubmission &&` 조건(`:742`)은 **그대로 함수 안에 따라간다** — 그래야 첫 제출에는 안 뜨고 재제출에는 뜬다.
2. `DONE` 분기(`:792`)에서 **파일이 담겨 있으면 그 카드를 보여준다.** 「다시 제출 (교체)」 라벨은 담긴 게 없을 때만 보이면 된다.
   - 즉 `ACCEPTED`와 같은 구조가 된다: 담긴 게 없으면 고르는 링크, 담기면 카드.
3. 카드의 「제출 확정하기」가 `DONE` 상태에서도 `handleMobileSubmit`을 부르는지 확인한다. **이 함수는 이미 교체 제출을 처리한다** — 새로 만들지 마라.

### 하지 말 것

- **`confirm()`을 되살리지 마라.** 카드 방식이 더 낫다. 없어진 것은 확인창이 아니라 **카드 자체**다.
- **`ACCEPTED` 분기의 동작을 바꾸지 마라.** 이 과제는 `DONE`에 없던 것을 채우는 일이다.
- 제출 API·업로드 로직을 건드리지 마라.
- 파일 전체를 재작성하지 마라. **뽑아내기 + `DONE` 분기 수정** 두 곳이면 끝난다.
