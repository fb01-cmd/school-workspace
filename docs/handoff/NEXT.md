## 과제 BB — 기초시간표 개정 화면에 「직접 조정」 붙이기 (사용자 확정 2026-08-23)

**기준 커밋: 이 파일이 커밋된 시점의 HEAD.** 대상은 `BaseRevisionTab.tsx`(832줄). **`DraftAutoTab.tsx`는 건드리지 마라 — 이번 과제에서 그 파일은 「베끼는 원본」이지 수정 대상이 아니다.**

**왜 하나**: 오늘 만든 것(직접 조정·3색 신호등·감점 표시)이 **전부 초안 편집 화면에만** 있다. 그런데 **개학 후 실제로 고칠 일은 개정 화면에서 생긴다** — 이미 공개된 시간표에 컴플레인이 들어오는 자리다. 사용자: *"기초시간표 개정에서 수작업으로 하는 배정을 돕는 아이가 필요한 거고."*

### 먼저 알아야 할 사실 (Claude 조사, 2026-08-23)

1. **op 어휘가 이미 같다.** 개정 화면은 `BaseRevisionOp[]`를 쌓는다(`:41`) — 초안 편집과 **같은 타입**이다. 새 op를 만들 필요가 없다.
2. **필요한 데이터를 주는 서버 통로가 이미 있다.** `action: "draft_model"`(`route.ts:1321`)이 **현행 기초 그리드 전량 + 등록부 5종 + 설정**을 한 번에 준다. **새 서버 액션을 만들지 마라.**
3. **지금은 한 학급만 본다.** 개정 화면은 `action: "class"`로 학급 하나(`baseGrid`)만 가져온다(`:118`) — 그래서 **교사 중복 같은 전역 제약을 볼 수 없다.** 이것이 이번 과제의 핵심 변화다.
4. **⚠️ 저장 방식이 초안과 다르다 — 여기서 실수하기 쉽다.** 초안은 조작마다 서버에 `draft_op`를 보내지만(낙관적 반영·`expectedOpCursor` 필요), **개정은 `ops`를 화면에 쌓아 두었다가 「초안 저장」 버튼으로 한 번에** 보낸다(`revision_save_draft`). **초안 편집의 `executeOptimisticOp`를 그대로 복사하지 마라** — 서버 왕복이 없으므로 낙관적 반영도 커서 충돌도 필요 없다. 조작은 **로컬 `ops` 배열에 추가**하는 것으로 끝난다.
5. **적용 전까지는 아무 영향이 없다.** `revision_apply`(적용 시점 지정)를 눌러야 실제 시간표가 바뀐다. 되돌리기는 `handleRemoveOp`(`:201`)로 이미 있다.

### BB-1. 전체 판을 보고 편집하게 만든다

1. **화면 열 때 `draft_model`을 1회 호출**해 전 학급 그리드 + 제약 모델을 받는다. 그 위에 현재 `ops`를 `applyRevisionOps`로 적용한 것이 **지금 판(`currentGrids`)** 이다 — 초안 편집과 같은 구조다.
2. **검사기 결과를 보여준다.** `validateTimetable(currentGrids, model)`로 **중대 문제 건수 · 감점 총점**을 상단에 띄운다. 문구는 초안 화면과 **똑같이** 「중대 문제」·「감점」을 써라(다른 말을 쓰면 두 화면을 비교할 수 없다).
3. **집기 → 3색 신호등 → 이동**을 붙인다. `evaluateMoveCandidates`(`moveCandidates.ts`)를 그대로 쓴다 — **후보 판정을 새로 짜지 마라.** 초록/노랑/회색과 감점 변화 뱃지, 차단 사유 툴팁까지 초안 화면과 같은 규약(스펙 §2-3).
4. **셀 불변 조항 준수** — 셀 안에 문장 블록 금지, 사유는 툴팁으로(스펙 §0-1). 셀 높이 균일.
5. **구 맞교환 편집(`selectedSlotA`, `:47·:149·:425`)을 걷어낸다.** 과제 R에서 초안 화면에서 철거한 바로 그 두 번 클릭 방식이다. **직접 조정이 상위 호환**이므로 편집 상호작용을 하나로 합친다. 지우기 전에 **다른 데서 쓰는지 grep으로 확인하고 보고**해라.
6. **좁은 화면 규칙** — 스펙 §0-4·§0-6: 숨기지 말고 **흐린 비활성 + 안내**. 조건부 렌더에서 통째로 빠지지 않게(과제 V-2 전례).

**이번 과제에 넣지 않는 것 (다음 과제로 예고)**
- **교사 그리드 병치**: 초안 화면의 격자 렌더러는 `DraftAutoTab` 안에 있어 공유하려면 **공용 컴포넌트로 추출**해야 한다 — 그건 회귀 위험이 있어 **따로 끊는다.** 이번에는 **학급 격자 하나**로 하되, 교사 충돌은 **3색(회색=차단)과 사유 툴팁이 이미 알려준다.**
- **해결안 찾기(수읽기)**: BB-1이 통과한 뒤 붙인다.
- **트레이(잠깐 빼두기)·연쇄**: 개정에 필요한지 자체가 미정 — 판단 후.

### 읽기량 (규칙 ⑪ — 보고에 반드시 적어라)
