## 과제 G — 동명이인이 같은 업무에 제출하면 파일 이름이 똑같아진다

**기준 커밋**: `ad8feec` · **사용자 지적 2026-08-20**

### 무엇이 문제인가

제출 파일 이름은 `normalizeSubmissionFileName`(`src/lib/tasks/logic.ts:283`)이 만든다:

```
{소속}_{이름}_{업무명}.{확장자}     예) 휴직 교사_이현준_파일제출.jpg
```

**같은 부서에 이름이 같은 선생님이 두 분이면 완전히 같은 이름이 된다.** 두 파일은 같은 업무의 같은 제출함 폴더에 들어가고, **구글 드라이브는 같은 이름을 막지 않는다.** 오류 없이 나란히 쌓이고, **담당 선생님이 열었을 때 누가 낸 것인지 구분할 수 없다.**

담임은 소속이 `3학년2반`처럼 들어가 상대적으로 안전하지만, **부서로 들어가는 경우 실제로 겹칠 수 있다.**

### 겹치지 않는 경우 (건드리지 마라)

- **다른 업무** — 폴더가 다르다(`ensureTaskFolders`: `연도/업무ID/제출함`)
- **같은 사람의 재제출** — 기존 Drive 파일을 덮어쓴다(`overwriteTaskFile`)

### 할 일

**(1) 파일명 생성기에 구분자를 받는 자리를 만든다**

`src/lib/tasks/logic.ts`의 `normalizeSubmissionFileName` 파라미터에 선택 항목을 추가한다:

```ts
/** 동명이인 구분자 — 있으면 이름 뒤에 괄호로 붙는다 (2026-08-20). 없으면 종전과 완전히 동일. */
disambiguator?: string;
```

- 있을 때 결과: `휴직 교사_이현준(hjl)_파일제출.jpg`
- **없을 때는 지금과 글자 하나도 달라지면 안 된다.** 기존 호출부의 결과가 바뀌면 실패다.
- 구분자도 `cleanSegment`를 통과시키고 길이를 제한해라(20자면 충분).

**(2) 서버가 겹침을 감지해 구분자를 넣는다**

`src/app/api/tasks/route.ts`의 multipart `submit` 분기(`normalizeSubmissionFileName` 호출 지점, `:150` 부근):

1. 먼저 **구분자 없이** 이름을 만든다.
2. **`task.submissions`에서 나 아닌 다른 제출자 중, 저장된 `name`이 그 이름과 같은 사람이 있는지** 본다.
   - **Drive를 조회하지 마라.** 이 정보는 이미 `task.submissions` 맵에 있다. 추가 비용 0이다.
3. 있으면 **구분자를 넣어 다시 만든다.** 구분자는 **내 계정 아이디**(`email.split("@")[0]`).

**(3) [중요] 남의 파일은 건드리지 마라 — 비대칭을 받아들인다**

겹침이 나면 **나중에 낸 사람만** 아이디가 붙는다. 먼저 낸 사람 파일은 그대로다.

```
휴직 교사_이현준_파일제출.jpg          ← 먼저 낸 분
휴직 교사_이현준(hjl2)_파일제출.jpg    ← 나중에 낸 분
```

**둘 다 이름을 맞추려고 먼저 낸 사람의 Drive 파일을 고치지 마라.** 남이 이미 제출한 결과물을 시스템이 말없이 바꾸는 것이 훨씬 나쁘다. **이름이 달라지기만 하면 목적은 달성된다** — 두 파일이 서로 다른 사람 것임을 알 수 있다.

### 하지 말 것

- **화면에 이메일을 노출하지 마라.** 이건 **제출함 폴더 안 파일 이름**이고 담당자만 본다. 오늘 지운 「화면의 이메일 표기」와 다른 사안이다. **화면 쪽은 손대지 마라.**
- 재제출(덮어쓰기) 동작을 바꾸지 마라.
- `firestore.rules`·자격 검사·업로드 API 흐름을 건드리지 마라.
- 기존 제출물을 일괄 이름 변경하는 마이그레이션을 만들지 마라.
