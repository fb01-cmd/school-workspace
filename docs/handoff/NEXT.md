## 과제 F — 휴대폰에서 소속 없는 계정은 업무 화면이 통째로 빈 화면이다

**기준 커밋**: `69d5403` · Codex 검증 실패분의 후속

### 무엇이 문제인가

`69d5403`이 모바일에도 잠금 버튼과 안내를 넣었는데 **도달할 수 없다.**

`src/components/mobile/MobileTasksSection.tsx:528` 에 컴포넌트 최상단 조기 반환이 있다:

```ts
if (notEligible) return null;
```

`renderTaskItem`(`:530`)보다 **위**이고 컴포넌트 본체이므로, 소속이 없으면 **업무 영역이 아무것도 안 그려진다.** 새로 넣은 비활성 버튼·안내는 **죽은 코드**다.

**PC는 잠긴 버튼과 「내 조직 정보 신청」이 보이는데 휴대폰은 빈 화면이다.** 오늘 계속 문제가 된 「PC와 모바일이 갈리는」 형태이고, 무엇보다 **선생님이 왜 비어 있는지·무엇을 하면 되는지 알 수 없다.**

### 할 일

**`return null` 을 안내 화면으로 바꾼다.**

`:528` 의 `if (notEligible) return null;` 을, 자격이 없을 때 **작은 안내 한 덩어리만 그리고 끝내는** 형태로 바꾼다.

- 내용은 두 줄이면 된다:
  - `조직 정보가 등록되면 업무를 쓸 수 있습니다.`
  - 「내 조직 정보 신청 →」 버튼 — PC와 **같은** `openMyProfileModal` 커스텀 이벤트를 쏜다.
- **문구는 PC와 글자까지 같게** 맞춘다(`TasksSection.tsx`의 자격 안내 참고).
- 모바일 화면 폭에 맞춘 작은 카드 하나면 된다. **새 컴포넌트 파일을 만들지 마라.**

**그리고 죽은 코드를 정리한다.**

이 화면이 자격 없을 때 여기서 끝나므로, `69d5403`이 모바일에 넣은 **비활성 버튼과 안내는 도달하지 못한다.** 아래 중 하나를 택하고 **무엇을 택했는지 보고해라**:

- ⓐ 그 버튼들을 원래대로(자격 조건 없는 형태) 되돌린다 — 어차피 자격 있는 사람만 여기까지 온다
- ⓑ 그대로 둔다 — 나중에 조기 반환이 없어져도 안전하다

**ⓐ를 권한다.** 도달할 수 없는 분기는 다음 사람이 읽을 때 사실이 아닌 것을 사실로 믿게 만든다.

### 하지 말 것

- **훅 순서를 바꾸지 마라.** `:528` 아래에는 훅이 없음을 확인했으니, 그 자리에서 반환 내용만 바꾸면 된다. **조기 반환을 위로 옮기거나 훅을 아래로 내리지 마라.**
- 목록 구독 게이트(`:122`)는 **그대로 둔다.** 자격 없는 계정이 목록을 안 불러오는 것은 맞다.
- 서버·`firestore.rules`를 건드리지 마라.
- PC 쪽은 건드리지 마라. 지금이 맞다.

### 완료 확인

1. `npx tsc --noEmit` 0건.
2. **자격 있는 계정: 아무 변화가 없다.** 업무 목록·버튼이 종전과 똑같다. 이게 조건이다.
3. **자격 없는 계정(휴대폰)**: 빈 화면이 아니라 **안내와 「내 조직 정보 신청」이 보이고**, 눌리면 프로필 모달이 열린다.
4. **PC와 문구가 글자까지 같은지** 양쪽 `파일:줄번호`로 대조해 보고해라.
5. `bash scripts/check_ui_removals.sh 69d5403` — ⓐ를 택했다면 삭제가 잡힌다. **그 삭제가 이 지시서의 ⓐ에 해당함을 밝혀라.**
6. **실기기 확인은 Antigravity가 못 한다.** 보고에 *"실기기 미확인"* 을 명시해라.

### 보고할 것

- ⓐ·ⓑ 중 무엇을 택했는지와 이유.
- 자격 없을 때 실제로 그려지는 것이 무엇인지 `파일:줄번호`.
