## 과제 AA — 수업교환 체인: 계기판 + 대가 표시 (사용자 실기기 2026-08-23)

**기준 커밋: 이 파일이 커밋된 시점의 HEAD.** 대상은 `DirectSubstituteTab.tsx`(체인 화면)와 `server.ts`의 `computeChainSearch`. **초안 편집(`DraftAutoTab`)은 건드리지 마라 — 다른 화면이다.**

발단: 사용자 *"수업교환 체인도 같은 증상. 3단계 가도 뭐 없었던 기억이 있는데."* 조사 결과 **손잡이를 돌리기 전에 계기판이 없다**는 것이 먼저 드러났다.

### AA-1. 왜 빈손인지가 화면에서 안 읽힌다 (우선)

**서버는 이미 알고 있는데 화면이 안 쓴다.**

- `computeChainSearch`(`server.ts:5112~5416`)의 한도: `CHAIN_BRANCH_CAP = 8`(단계당 분기) · **`CHAIN_TIME_BUDGET_MS = 3000`(시간 예산)** · `maxDepth` 1~3(사용자 조절) · `CHAIN_MAX_RESULTS = 5`(결과 상한).
- 시간이 다 되면 **`truncated: true`를 반환**하고(`:5318·5354·5411`) 라우트가 `...result`로 그대로 내려보낸다. **그런데 `DirectSubstituteTab.tsx`에 `truncated`라는 단어가 0건**이다 — 사용자는 「시간이 모자라 다 못 봤다」와 「진짜 경로가 없다」를 **구분할 수 없다.**
- 게다가 실패 문구가 **깊이를 탓한다** — *"탐색 **깊이(N단계)** 내 연결 가능한 경로가 없습니다"*(`:5390` 부근). **시간 초과로 못 찾았어도 그렇게 말한다.** 사용자가 깊이를 3으로 올린 것은 **화면이 그렇게 유도했기 때문**이다. 그런데 **깊이를 올려도 시간 예산은 3초 그대로**라 결과가 같을 수 있다.

**요구**
1. 결과가 **잘렸으면 화면에 말한다** — 「시간(3초) 안에 다 보지 못했습니다. 아래는 그때까지 찾은 것입니다」류. 결과가 **0건일 때도** 시간 초과였으면 그렇게 말해야 한다(지금은 「경로 없음」으로만 보인다).
2. **실패 문구를 갈라라.** 서버 `reason`이 「깊이 안에 경로 없음」을 말하는 경우와 시간 초과를 **문구에서 구분**한다. 시간 초과인데 깊이를 탓하는 문장이 나오면 안 된다 — 사용자가 엉뚱한 손잡이를 돌린다.
3. **결과 5건 상한도 알린다** — `CHAIN_MAX_RESULTS = 5`라 더 있어도 잘린다. 「더 있을 수 있습니다」 한 줄.
4. **한도 값을 화면에 숫자로 쓰지 마라**(「3000ms」·「CHAIN_BRANCH_CAP」 금지). 「3초 안에」 정도의 눈높이 표현.
5. ⚠️ **한도 자체는 이번에 바꾸지 마라.** 계기판이 먼저다 — 무엇이 병목인지 보이고 나서 조절한다. (수읽기에서 계기판이 화면에 있었는데 안 읽어 엉뚱한 손잡이를 돌린 전례가 바로 앞에 있다.)

### AA-2. 체인이 「무엇을 대가로 치르는지」 안 보여준다

**이것도 데이터는 이미 다 있다 — 화면이 안 쓸 뿐이다.**

- 서버가 체인마다 **`totalScore`를 계산해서 담는다**(`server.ts:5257` `steps.reduce((sum, s) => sum + s.score, 0)`). 각 단계도 `score`를 갖는다.
- 단건 교환 후보는 이미 **`score`와 `penalties[]`(감점 사유 문구)를 화면에 보여준다**(`DirectSubstituteTab.tsx:1541·1642`의 「감점 N」).
- 그런데 **체인 결과 카드**(`:2054~2075`)는 **단계별 `stepSummary` 한 줄만** 보여준다. **`totalScore`도, 단계별 감점·사유도 안 보여준다.**

**요구**
1. 체인 카드에 **총 감점**을 표시한다. 단건 후보와 **같은 말**을 써라(「감점 N」) — 두 곳의 용어가 다르면 비교가 안 된다.
2. 단계마다 **그 수의 감점과 사유**를 붙인다. 사유 문구는 **서버가 만든 것을 그대로** 쓴다(`penalties[]`) — 화면에서 새로 짓지 마라.
3. **정렬·강조는 스펙 §0-5를 따른다**: 감점이 늘어나는 체인은 **좋아 보이는 딱지를 먼저 붙이지 않는다.** 총 감점이 큰 것과 작은 것이 한눈에 갈리게.
4. 감점이 0이면 **「추가 감점 없습니다」를 명시**한다(비워 두면 안 나온 건지 없는 건지 모른다 — 기보 카드와 같은 규칙).

**참고(이번 범위 아님)**: 체인 단계가 `stepSummary` **텍스트 한 줄**로 표시된다. 직접 조정 스펙 §0-1은 텍스트 이동 표기를 금지하고 미니 그리드를 요구하는데, 그건 초안 편집 도메인 규칙이라 여기 적용 여부는 **Claude가 따로 판단한다.** 지금은 건드리지 마라.

**완료 확인**: tsc · build · check:ui · `check_ui_removals`(기준 커밋) · selftest 4종(`lookahead` 31 · `movecand` · `m2ops` · `unplaced`) 유지 + ⓐ`truncated`를 화면이 쓰는 지점 ⓑ시간 초과와 「경로 없음」이 **다른 문구**로 갈리는 코드 근거 ⓒ체인 카드가 `totalScore`·단계별 `penalties`를 쓰는 지점 — 각각 file:line. **한도 상수(`CHAIN_*`)를 바꾸지 않았음도 함께 보고.** **핸드오버 ④ 기재**(덧붙이기만, **표·목록은 본문에 실어라**).
