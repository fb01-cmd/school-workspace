## 과제 W — 작업기록이 「무엇이 어떻게 됐는지」 말하게 + 개발 용어 정리 (사용자 실기기 2026-08-22)

**기준 커밋: 이 파일이 커밋된 시점의 HEAD.** 배치 원본 = `docs/timetable_manual_move_spec.md` §2-6(M3).

### W-1. 작업기록이 셀을 안 가리킨다 (우선)

사용자 원문: *"작업 기록도 아예 하나의 셀을 정확히 가리켜야 의미가 있어. 1학년 9반 어느 수업(교사는 누구)이 어느 수업과 맞교환 되었다는 건지."*

지금은 `#8 맞교환/이동 (1학년 9반)` — **무엇이 무엇과 바뀌었는지가 없다.** 원인은 라벨을 `op` 데이터만 보고 만들기 때문이다(`DraftAutoTab.tsx:4930` 부근). op에는 학급·칸 좌표만 있고 **수업·교사가 없다.**

**어디서 가져오나 (이게 이 과제의 핵심 설계다)**

수업 내용은 **그 시점의 판**에서 읽어야 한다. `currentGrids`(지금 판)를 읽으면 **과거 기록이 틀린 내용을 말하게 된다** — 그 뒤로 판이 바뀌었기 때문이다.

- 항목 `idx`에 대해 `baseGrids`에 `meta.ops.slice(0, idx)`를 `applyRevisionOps`로 재생하면 **그 op 직전의 판**이 나온다. 거기서 op가 가리키는 칸의 수업을 읽는다.
- 둘 다 이미 이 파일에 있다(`openDraft.baseGrids`, `applyRevisionOps` import).
- 목록이 길면 재생이 반복되니 **한 번 훑으면서 순차로 누적**해라(항목마다 처음부터 다시 재생하지 말 것).

**op 종류별로 무엇을 보여줄지**

| op | 보여줄 것 |
|---|---|
| `swap` | 두 칸의 **과목 + 교사** 양쪽. 예: 「**수학(김○○)** ↔ **영어(박○○)**」 |
| `edit_cell` | 바뀌기 전 수업 → 바뀐 뒤 수업 (빈 칸이면 「비어 있던 칸」) |
| `park` | 빼둔 수업의 과목 + 교사 |
| `unpark` | 되돌린 수업의 과목 + 교사 + 어느 칸으로 |
| `chain` | 각 수를 같은 방식으로 나열(접어 두고 펼치기 가능) |
| `swap_pair` | 학급별로 어떤 수업이 오갔는지 |

**위치는 텍스트로 쓰지 마라 (스펙 제1원칙).** *"월요일 1교시 → 화요일 3교시"* 같은 문장 금지. 위치는 **작은 격자 그림**으로 보여주고, 글자로는 **과목·교사만** 쓴다.
- ⚠️ `MiniPreviewGrid.tsx`는 **보강(주간 시간표)용**이라 인자 모양이 안 맞는다. 그걸 억지로 쓰지 말고, 이 화면의 격자 렌더러를 축소해 쓰거나 작은 전용 표를 새로 만들어라. **어느 쪽을 골랐는지 보고에 적어라.**

### W-2. 「하드 위반」·「소프트」를 눈높이 말로

사용자: *"하드 위반이라는 단어는 있으면 안 돼?"* → **화면에는 안 쓴다**(프로젝트 규칙). 처음부터 있었던 것은 면제가 아니라 부채다.

- 「하드 위반」 → **「중대 문제」** · 「소프트 감점」/「소프트」 → **「감점」**
