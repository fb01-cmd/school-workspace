## 과제 V — 기보 카드 상세 + 교사 그리드 드래그 + 좁은 화면 안내 (사용자 실기기 2026-08-22)

**기준 커밋: 이 파일이 커밋된 시점의 HEAD** (커밋 메시지에 `과제 V 인계`가 있는 커밋). 세 건 다 같은 파일(`DraftAutoTab.tsx`)이다.

### V-1. 기보 카드가 「무엇을 대가로 치르는지」 안 보인다 (우선)

사용자 원문: *"감점이 해결되지 않고 개선되는 애들은 결국 어딘가 감점이 증가한다는 건데, 그게 어딘지 뭔지 상황을 정확히 알려줘야 그 감점을 늘리더라도 진행할지 결정하지."*

지금 카드에는 「총점 0.5점 개선」·「✅ 이 감점 해소」와 관련 교시 목록뿐이다. **어디서 벌고 어디서 잃은 0.5점인지가 없다.** 2수 기보만 총점 추이(`23 → 23 → 22.5`)가 나오고 1수 기보는 그것조차 없다.

**엔진이 이미 데이터를 준다 (Claude 선행분, 이 커밋 포함).** `LookaheadLine.sideEffects: LookaheadSideEffect[]` —
- `kind`: `"new"`(없던 게 생김) · `"worse"`(커짐) · `"gone"`(없어짐) · `"better"`(줄어듦)
- `text`: **검사기가 쓴 사람 문장 그대로** (예: `"김○○ 화요일 시수 쏠림 (5시간)"`). **화면에서 이름을 새로 짓지 마라** — 감점 상세 목록과 같은 문장이어야 사용자가 대조할 수 있다.
- `before` · `after` · `delta` (양수 = 나빠짐)
- **이미 나빠지는 것이 위로 정렬돼 있다.** 그대로 순서대로 그리면 된다.
- 목표 감점 자체는 **빠져 있다**(그건 `targetDelta`가 말한다). 그래서 「이 감점 해소」와 겹치지 않는다.

**요구**
1. 기보마다 **대가 줄**을 만든다. 나빠지는 항목(`new`·`worse`)은 눈에 띄게, 좋아지는 항목(`gone`·`better`)은 차분하게. 예: `⚠ 새로 생김 — 이나 화요일 시수 쏠림 (5시간) +0.5점`.
2. **숫자가 맞아떨어지게 보여라.** 검증된 항등식이 있다: **목표 변화 + 부작용 합 = 총점 변화**. 「이 감점 −1점」 + 「화요일 쏠림 +0.5점」 = 「총점 −0.5점」처럼 읽히게 배치하라.
3. **1수 기보에도 총점 변화를 표시한다**(지금은 2수 이상만 나온다). `stepScores`와 `finalDelta`를 쓴다.
4. 나빠지는 항목이 하나도 없으면 **「다른 감점이 늘어나지 않습니다」** 한 줄을 명시적으로 띄운다 — 비워 두면 "안 나온 건지 없는 건지" 모른다.
5. 개발 용어 금지. 「부작용」·「sideEffects」·「delta」 같은 말을 화면에 쓰지 마라. 「이 수를 두면 대신 이렇게 됩니다」류로.

### V-2. 교사 시간표에서 드래그가 안 된다 (결함)

사용자: *"드래그앤드롭이 학급 시간표에선 되는데 교사 시간표에선 안 돼."* **사실이다** — 교사 격자에는 **놓는 자리(`teacherDndProps`의 onDragOver/onDrop)만 있고 집는 쪽(`draggable`·`onDragStart`)이 0건**이다. 학급 격자에는 둘 다 있다.

- 교사 격자 셀에도 학급 격자와 **같은 방식으로** `draggable` + `onDragStart`를 단다. 집었을 때 하는 일(집기 상태·3색 채점)은 **교사 셀 클릭(`handleTeacherCellClick`)이 이미 하는 것과 동일**해야 한다 — 새 경로를 만들지 말고 그 함수를 재사용하라.
- 이전 검증에서 이게 안 잡힌 이유는 내가 「드롭 판정」만 물었기 때문이다. 이번엔 **집기·놓기 양방향**을 보고에 각각 적어라.

### V-3. 좁은 화면에서 아무 설명 없이 기능이 사라진다

사용자: *"가로를 줄이면 뭐가 흐려지는 건 없고 직접조정이 꺼져. 아이콘도 사라져."* 둘 다 맞다 —
- 「직접 조정」 토글이 `hidden lg:flex`(`:2260` 부근)라 **소리 없이 사라진다.** 과제 R-2에서 「흐린 비활성 + 안내」를 **미배정 버튼에만** 걸고 토글은 안 고쳤다(내 지시가 반쪽이었다).
- 게다가 폭이 좁아지면 `setManualMode(false)`가 돌아 **켜져 있던 직접 조정이 조용히 꺼진다**(`:304` 부근 effect).

**요구**
1. 토글을 숨기지 말고 **흐린 비활성 + 「넓은 화면에서 쓸 수 있어요」**로 바꾼다. **본보기가 이미 있다** — 미배정 「배정하기」 버튼(`:3798` disabled + `:3853` 안내)과 똑같이 하면 된다.
2. 좁아져서 직접 조정이 꺼질 때 **왜 꺼졌는지 한 줄**을 띄운다(말풍선·안내 줄 등). 지금은 아무 말이 없다.
3. 스펙 `docs/timetable_manual_move_spec.md` §0-4의 「1024px 미만 미표시」 문구도 **「비활성 + 안내」로 정정**하라. 규칙과 코드가 어긋난 채로 두지 마라.

**완료 확인**: tsc·build·check:ui·`check_ui_removals`(기준 커밋) + selftest 4종(`lookahead` **27건**·`movecand`·`m2ops`·`unplaced`) 유지 + ⓐ대가 줄이 `sideEffects`를 그대로 쓰는지(직접 계산 금지) ⓑ교사 격자 집기가 `handleTeacherCellClick`과 같은 경로인지 ⓒ토글 비활성 안내 — 각각 코드 근거(file:line) 보고. **핸드오버 ④ 기재** + **`project_notes.md`는 덧붙이기만**(과제 U에서 남의 줄을 지웠다).
