* **활성 학기에서는 편성 등록부를 열람 전용으로 (2026-08-15 사용자 발상 — "일단 메모로")**: 사용자 관찰 — *"이동수업 관리나 특별실 관리는 이미 학기가 활성화된 상태에선 의미 없는 기능 아냐? 시간표가 이미 짜여 확정되고 돌고 있는데 특별실이 추가되거나 묶이는 수업이 새로 생기고 줄어들 수 없잖아. 안전을 위해서라도 활성 학기면 열람 정도로 축소되어야 할 것 같은데."*
  - **Claude 1차 확인 결과, 결론이 두 갈래로 갈린다 (실코드 대조 2026-08-15)**:
    - **㉮ 이동수업(SimulGroup)·특별실(VenueGroup) = "의미 없는" 게 아니라 오히려 살아 있는 판정 원본이다.** 그리드를 로드할 때마다 서버가 이 등록부로 `lesson.simul`·`lesson.room`을 **스탬프**하고(`server.ts:569-570`·`593-594`), 그 스탬프가 ① 교체 후보의 하드 제외 ② 특별실 겹침 = 조율 필요 후보 도출 ③ **통 이동 전 과정**의 판정 근거다. 즉 **읽기는 학기 내내 필수**. 위험한 것은 읽기가 아니라 **편집**이다 — 등록부를 학기 중에 고치면 합성기가 매번 다시 스탬프하므로 **이미 승인된 교체·통 이동의 판정 근거가 소급으로 바뀐다.** 사용자 직감(위험)은 맞고, 근거는 "의미 없음"이 아니라 "소급 효력"이다.

    - `시트건수 > 플랫폼건수`이면 차액만큼 기록 추가, 아니면 아무것도 안 함(플랫폼이 더 많아도 삭제 없음 — 추가 전용). 무상태·멱등: 실행 후 건수가 같아지므로 재실행 시 0건.
  - **추가되는 기록의 형태**: 정규 생성 경로(POST create)와 동일 필드로 직접 기입 — `occurredAt` = ~~비고의 `M/D` 파싱 성공 시 그 날짜, 실패 시~~ **항상 크론 실행일 (2026-08-09 검수에서 정정 — 비고 날짜 파싱 금지)**: 행의 비고는 1학기 기존 기록의 날짜일 수 있어(전환기의 흔한 형태 = 1학기 비고 있는 행에 2학기 새 체크 추가), 파싱하면 새 기록이 과거 일자로 박히고 리셋 마커 이후만 집계하는 엔진(`computeStudentStatus`의 `occurredAt > markerMs` 필터)에서 단계 판정이 조용히 누락될 수 있음. 매일 실행이라 실행일 오차 ≤1일, 비고에 `[날짜 근사]` 표기(비고 원문은 note에 보존되므로 정보 손실 없음), `recordedBy` = `admin@hmh.or.kr`, note에 `[시트 자동 가져옴]` 태그. 학생 대조는 이관과 동일: Workspace Directory familyName(학번 5자리) ↔ `{학년}{반2}{번2}`, 이름까지 일치해야 수입(불일치는 제외 목록으로 보고, 실이메일은 Directory에서 — 합성 금지). **단계 자동 판정도 정규 경로와 동일하게 수행**: 기록 추가 후 `computeStudentStatus` 재계산 → 새 단계 도달 시 auto 단계 이벤트 생성(처리함 큐 공급). 정규 생성 경로에 DM 발송은 원래 없으므로 알림 문제 자체가 없음(스크립트는 관례상 `_force_notify_mock` 첫 import 유지).
  - **운영**: 매일 1회 크론(Vercel cron 또는 GitHub Actions) · 킬 스위치 = `discipline_config`의 플래그 1개(끄면 즉시 no-op) · 일몰 = 가동일 +1개월(예: 9/10)에 크론 제거 + 시트에 "플랫폼으로 이전됨" 안내 배너·읽기 전용 전환(학생부장 공지와 동시). 실행 로그는 감사 로그(`writeAuditLog`)에 요약 1줄(대조 N건·추가 M건·제외 목록).

  - **스펙 보강 (2026-08-09 Claude 계획 리뷰에서 확정 — 구현 필수)**: ① 단계 자동 판정은 재구현 금지 — `records/route.ts` create의 auto 이벤트 블록(리셋 마커 이후 동일 단계 기존 이벤트 중복 방지 + causeRecordIds 계산 포함)을 `server.ts` 공유 헬퍼로 추출해 정규 경로·브리지가 같은 코드 사용. ② 킬 스위치 기본값 = 꺼짐: `sheetBridgeEnabled` 필드 부재 시 no-op(전환 공지일에 플래그 켜는 순간부터 가동). ③ 크론 엔드포인트는 GET+CRON_SECRET(기존 lifecycle 크론의 fail-closed 패턴)만 — 수동 실행용 POST는 두지 않음(CLI 스크립트가 담당). ④ 폭주 가드 2종: 학급 탭 머리글(1~2행)이 기대 라벨과 불일치하면 해당 탭 스킵+경고 / 1회 실행 추가 예정 건수 상한 30건 초과 시 전체 중단+감사 로그(정상 상황에서 비정상 신호). 경미: 비접두열 체크 경고 로그, Directory suspended 학생 제외+보고, 테스트 스크립트 첫 import `_force_notify_mock`, Vercel 크론은 기존 1개+신규 1개=Hobby 한도 2개 정확히 소진(추후 크론 필요 시 통합 검토).
