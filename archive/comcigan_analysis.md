# 컴시간 설명서 분석 — 다음 페이즈(시간표) 기초 조사

> 2026-07-26 Claude 작성. 입력: 사용자 제공 PDF 2부(`주간시간표설명서.pdf` 39p, `일과진행설명서.pdf` 36p — 컴시간 http://comcigan.co.kr 공식 설명서).
> 용도: 로드맵 Phase 9(시간표·교체수업) 스펙 설계의 도메인 지식 원본. 스펙 확정 전까지는 조사 문서일 뿐임.

## 1. 컴시간 제품 구성 (두 프로그램 + 부속)

| 구성 | 역할 | 사용 시점 |
|---|---|---|
| **주간시간표** | 학기 초 기초시간표 자동 작성 (CSP 엔진) | 연 2회 (학기 초) |
| **일과진행** | 매일의 결·보강 처리, 수업 교환, 시수 관리 | **매일** (일과계 교사) |
| 컴시간알리미 | 교사용 열람 앱 — 변경시간표 확인, 수업교환 요청 | 전 교사 매일 |
| 일과서버 | **학교 내 PC에 상주하는 로컬 서버** — 알리미·일과진행의 데이터 허브 | 항시 (죽으면 전체 마비) |

## 2. 도메인 모델 (스펙 설계 시 그대로 필요한 개념들)

### 기초 데이터 (주간시간표의 입력)
- **교사별 시수표**: 정식과목명(NEIS 일치 필수)·단축과목명(한글2자)·교사명·학년/반별 주당 시수. 엑셀 양식으로 일괄 입력
- 등록부: 성명(교사), 학급(+담임), 과목(복수교사 과목 표시), 요일별 시수(학년별, 최대 8교시), 일과시간(점심 위치)
- **가상학급**: 수준별 이동수업으로 실제보다 늘어나는 학급 수

### 배정 제약 (자동배정 엔진의 제약 조건 = 우리가 만든다면 CSP 제약)
- **이동/배정금지**(특별교사 — 특정 요일·교시 비우기), **일괄배정**(재량활동·고교 선택교육과정·합반 — 특정 교시에 여러 학급 동시), **연속수업**(실습 2시간 연속, "2,2" 분할 지원), **동시수업**(수준별 이동수업·격주 — 여러 교사 같은 교시), **특별실**(공용 교실 충돌 방지, 특별실+연속 조합), **복수교사**(한 학급 2교사 동시, 시수 동일 강제)
- 배정 품질 검색조건: 중복(같은 요일 같은 학급 2회), 학년(교사 하루 3과목+), 요일별 시수 균형, 순배(1~4반 순환), 연속3시간+, 점심 전후 연속, 오전/오후 균형
- 수동 이동 UX 핵심: **연쇄이동** — A를 B로 옮기면 밀려나는 교사들의 시간표 변화를 미리 보여주고 선택

### 일일 운영 (일과진행의 기능 = 실사용 빈도 최고)
- 주 단위 날짜등록(휴업일 지정), 기초시간표 위에 변경을 쌓는 구조(변경분 빨간색)
- **일반보강**(교환 가능 교시 자동 탐색 → 맞교환), **특별보강**(교환 없이 남이 대신 수업 — 야영·수학여행 일괄배정 지원), 교시간/요일간 교환, 동일교시 학급교환, 합반, 정기고사 수업처리
- **수업없는 교사 열람**(교시별 공강 교사 = 보강자 찾기), 시수누계/남은 시수
- **수업교환 요청대장**: 교사가 알리미에서 교환 신청 → 일과계 승인 처리 → 결재용 일람표 인쇄
- 작업기록 자동 저장 → 시점 복원

### 외부 연계 (대체 시 반드시 커버해야 하는 경계)
- **NEIS**: 기초시간표 일괄파일 업로드(과목명·교사명이 NEIS 등록과 정확히 일치해야 함), 수업교환 목록 출력 → 나이스 수기 입력
- 엑셀 인쇄(전체/주간/교사별/학급별)

## 3. 우리 플랫폼 관점의 판단 재료

- **강점 대비**: 컴시간의 약점은 ① 학교 PC 상주 로컬 서버(일과서버 죽으면 마비, PC 이사 수동), ② 명단·교사 데이터 수동 관리(전출 교사 수동 삭제 — 우리 플랫폼은 이미 자동), ③ 유료 사용기간 연장 서류, ④ 폐쇄적 데이터(내보내기 = 엑셀·NEIS 파일뿐)
- **최대 리스크**: 주간시간표의 자동배정 엔진은 수십 년 다듬어진 제약 충족 솔버 — 전면 재구현은 Phase 중 최고 난도. 반면 **일과진행(결보강)은 알고리즘보다 데이터 구조·UX 문제**라 현실적 첫 표적이 될 수 있음
- **연동 진입점**: 컴시간을 유지한 채 데이터를 받아오는 공식 API는 없음. 진입점은 교사별 시수표 엑셀, NEIS 일괄파일, 엑셀 인쇄물 정도 (역파싱 필요)

## 4. 스펙 설계 전 사용자 결정 필요 사항

1. **대체 범위**: ⓐ 일과진행(결보강)만 웹으로 재구축(기초시간표는 컴시간/엑셀에서 가져옴) / ⓑ 주간시간표까지 전면 대체(자동배정 엔진 포함) / ⓒ 컴시간 유지 + 열람·알림만 플랫폼으로(알리미 대체)
2. 현재 학교의 컴시간 **사용 계약 상태**(사용기간, 갱신 예정)와 일과계 담당자의 불만 지점 — 무엇이 가장 아픈가?
3. NEIS 입력 의무 범위 — 수업교환 목록을 NEIS에 넣는 주기와 담당자
4. 알리미를 교사들이 실제로 얼마나 쓰는지 (대체 시 전 교사 이행 비용)
